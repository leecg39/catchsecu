# 이메일 반송·신고·수신거부 실행 계획

2026-10-03. P09-T02의 남은 로컬 계약을 구현한다. 181경로/72 Task와 선행 게이트를 유지하며 외부 공급자 검증은 별도로 남긴다. 기존 이메일 작성·발송·파일 검증은 [이전 보고서](../email-content/README.md)에 있다.

## 확정할 계약

- 인증된 릴레이의 독립 webhook 계약을 사용한다. 현재 SMTP 설정만으로 공급자의 webhook 형식을 추측하지 않는다. 실제 공급자 변환 어댑터·DKIM·HTTPS 검증은 별도다.
- 릴레이는 서버 전용 HMAC 키로 `timestamp.rawBody`에 서명한다. 시간차 5분, 제한된 본문·스키마, 상수 시간 비교, eventId/본문 해시로 중복·충돌을 검사한다. 이메일/회사 ID를 신뢰하지 않고 실제 Job→CampaignDelivery에서 범위를 도출한다.
- 이벤트 종류는 전달·일시 반송·영구 반송·신고·수신거부다. 공급자 이벤트와 수신거부의 출처를 구분한다. 기록은 불변이며 원문 이메일·토큰·공급자 자유 텍스트를 저장하지 않는다.
- 수신거부/영구 반송/신고는 서비스 내 해당 이메일 해시를 차단한다. 일시 반송은 최근 7일의 아직 전달되지 않은 서로 다른 3개 작업을 기준으로 차단한다. 같은 작업의 중복 이벤트로 임계값이 상승하지 않는다. 뒤늦은 전달 이벤트도 이미 확정된 차단을 해제하지 않는다. 이 수치는 독립 구현 정책이며 운영자가 승인한 공급자 정책은 아니다.
- 차단 이력은 불변으로 보존한다. 원문 동의/응답 삭제 후에도 재발송 방지를 위한 HMAC 해시만 남긴다. 재동의만으로 영구 차단을 자동 해제하지 않는다. 해제/이의 처리의 운영 정책은 별도다.
- 수신거부 토큰은 작업 ID와 서버 HMAC으로 바인딩하고 90일간 유효하다. GET은 안내만 표시한다. 확인 POST는 쿠키·로그인 없이 토큰으로 인증하며 반복 POST는 같은 결과다. [RFC 8058](https://www.rfc-editor.org/rfc/rfc8058)의 form POST를 지원한다. One-click 헤더는 HTTPS와 DKIM 헤더 서명 설정이 갖춰진 경우에만 활성화한다.

## 순서·수용 조건

1. `suppression.ts`, `marketing.ts`, `campaign-common.ts`, `campaign-worker.ts`, `jobs.ts`의 현재 차단·잠금·전달 상태를 대조한다. source→contact→campaign→delivery→job 잠금 순서를 유지한다.
2. EmailFeedback·EmailSuppression과 복합 FK·유효성/불변 DB 가드를 추가한다. 기존 SMTP 접수 상태와 사후 수신 결과를 별도 필드/조회로 구분한다.
3. 서명된 webhook의 스키마·인증·시간·본문 제한·멱등/충돌·미발송 작업 거부를 구현한다. Job 기반 범위 검사와 안전한 오류/감사만 허용한다.
4. 현재 마케팅/일반 서비스 메일·미리보기·예약·전송 직전에 새 차단을 검사한다. 통계의 발송 가능 인원도 같은 기준을 쓴다.
5. 발송 직전에 서비스별 수신거부 링크를 본문에 추가하고 헤더 정책을 적용한다. 기존 worker가 새 정책을 생략하지 않도록 프로토콜과 배포 절차를 확인한다.
6. 공개 확인 화면과 GET/POST API를 추가한다. 위조/만료·GET 비변경·POST 반복·헤더 없는 form POST·다른 서비스 격리·원문 삭제 후 동작을 시험한다.
7. 발송 내역에 인증된 수신 결과와 시각을 표시한다. 서비스의 차단 목록은 조회 권한·현재 데이터 보유 기한·검색/페이지를 적용한다. 공급자 미설정 상태를 표시한다.
8. PostgreSQL 시험: 동일 이벤트 경합·본문 충돌·순서 역전·3개/7일 경계·중복 작업·예약 직전 수신거부·타회사/서비스/역할·직접 SQL 위반·개인정보 파기 후 최소 기록.
9. 로컬 앱에서 실제 HTTP HMAC 이벤트를 보내고 DB/화면을 대조한다. 실제 로컬 메일 링크를 Ego에서 열고 확인하며 GET 비변경과 POST 차단을 확인한다. 운영 사이트에는 이벤트/메일을 보내지 않는다.
10. 전체 회귀·타입·린트·빌드·OpenAPI·37개 이후 migration·390px·재시작을 확인한다. TASKS/tasks.json/goal 문서는 부분 증거만 갱신하고 외부 실제 공급자 결과로 집계하지 않는다.

## 외부 검증 조건

SMTP 공급자가 알려지면 서명 검증과 provider message ID 매핑 어댑터를 공급자 공식 문서에 맞춰 연결해야 한다. 현재 독립 릴레이 이벤트 시험은 실제 공급자 delivery/complaint 증거가 아니다. [Nodemailer 헤더 문서](https://nodemailer.com/message/list-headers)와 RFC의 HTTPS·DKIM 요구를 운영 수신함에서 확인하기 전에는 one-click 운영 완료로 표시하지 않는다.
