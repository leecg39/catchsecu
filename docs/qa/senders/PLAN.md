# P08-T01 발신번호·이메일 주소 구현 계획

## 근거와 계약

원본 mail/number·sms/number의 목록 열, 대표 설정, 등록 안내와 빈 상태를 docs/research/services/에서 확인했다. 실제 등록 심사/유료 상태는 미확인이다. 아래 상태 전이는 독립 구현 계약이다.

서비스 권한을 명확히 적용하기 위해 발신자는 회사·서비스에 속하고 채널·정규화 주소 HMAC을 유일 키로 사용한다. 초기 설계의 회사 단위 주소는 서비스별로 별도 등록·확인한다. 다른 서비스의 인증을 자동으로 공유하지 않는다.

## 데이터·DB

- [x] Sender: 암호화 주소, 이름·설명, pending/verified/expired/disabled/deleted, 인증 세대, 확인/만료 시각, 대표 여부, version, 등록자. 주소 변경·재인증은 기존 인증을 폐기한다.
- [x] SenderVerification: 이메일 코드/DNS TXT/공급자 결과, 만료·시도 제한·소비·세대. 코드 해시, DNS 값 암호화. 현재 세대의 검증 근거 없이 verified 불가.
- [x] 불변 SenderEvent와 버전별 변경 감사. 회사/서비스 복합 FK·유일 대표·인증 전 대표 금지·이력 없는 변경·삭제 복원 방지.
- [x] SMS 증빙은 기존 FileObject·암호화 비공개 저장·ClamAV에 연결. 파일 10MB, PDF/PNG/JPEG, 최대5개, 현재 서비스·발신자 바인딩. 삭제 시 실제 객체 정리.
- [x] Job 발신자 FK로 사용 중 삭제를 제한한다. 이전 인증 세대/버전으로 예약된 메일은 실제 전달 전에 다시 검사한다.

## API·검증

- [x] sender.read/manage와 현재 서비스 권한. 목록·상세·등록·이름/설명/주소 수정·대표 설정·비활성/재개·삭제, 검색·상태 필터·서버 페이지·이력.
- [x] 등록 멱등키, 변경 version, Origin·요청 제한·비밀 비노출. 주소 normalization과 헤더 개행 금지.
- [x] 이메일은 해당 주소로 보낸 10분/5회/일회 코드와 서비스별 DNS TXT 값 모두 확인. TXT 확인은 Node DNS 실제 요청, 새 인증은 최대90일. 개인 이메일 공급자 도메인은 등록 제한.
- [x] 이메일 소유 확인과 전송 설정은 별도로 표시. 외부 발송에는 SMTP 연결과 운영자가 지정한 도메인 허용 목록 필요. 로컬 검증은 외부 발송 자격으로 사용하지 않는다.
- [x] 문자 번호는 SOLAPI의 인증된 계정 조회에서 번호·ACTIVE·만료를 확인한다. 키를 회사에 고정해 다른 회사가 같은 서버 키로 번호를 가져오지 못하게 한다. 외부 미설정·오류는 인증 성공으로 바꾸지 않는다.
- [x] 증빙 업로드·검사·연결·다운로드·삭제. 일반 파일 주소로 바인딩을 생략해 접근하지 못하게 한다.
- [x] 이메일 작업 등록/실제 전달에 발신자 상태·만료·버전을 검사하고 실제 From 이름/주소를 사용한다. 인증 메일은 시스템 주소 사용.

## 화면·실동작

- [x] /mail/number·/sms/number의 DB 목록과 관리창, 등록/수정·인증·대표·비활성·삭제·증빙 UI.
- [x] 로딩·빈 상태·오류·권한·충돌, 새로고침/재시작 영속성, 390px 입력과 표 스크롤.
- [x] PostgreSQL에서 교차 범위·권한 회수·중복·버전·인증 실패/소비·DNS·만료·삭제·실제 파일/메일과 경합을 검사.
- [x] Ego에서 생성→수정→실제 로컬 코드와 DNS 프로토콜 확인→대표→중지/재인증→삭제, SMS 증빙 업로드/다운로드/삭제를 확인한다. 외부 공급자 자격증명 부재는 명시하고 실제 외부 성공으로 기록하지 않는다.

## 공식 참조

- [Node DNS Resolver](https://nodejs.org/api/dns.html#class-dnspromisesresolver): 독립 DNS 해석기와 TXT 응답 조각을 합쳐 비교한다.
- [SOLAPI 발신번호 조회](https://solapi.com/developers/api/managementSenderid-getSenderids): 계정의 번호 상태·만료를 조회한다.
- [SOLAPI API 키 인증](https://solapi.com/developers/api/authentication-api-key): 요청 시각·랜덤 salt를 HMAC-SHA256으로 서명한다.

캠페인과 SMS 실제 전달/공급자 서류 심사 접수는 P08-T02/T03에서 연결한다. 이 문서의 체크는 단계 증거이며 전체 Task 완료와 구분한다.

## 최종 점검

위 체크는 로컬 구현·통합 검증을 뜻한다. 실제 외부 SMTP·도메인·SOLAPI 계정 검증은 미완료다. Ego에서 발견한 이전 worker의 잘못된 발송을 작업 유형 분리·DB 보호·전체 재시작으로 수정했고, 최종 282개 회귀 테스트와 실제 큐 차단을 통과했다. [전체 증거](README.md).
