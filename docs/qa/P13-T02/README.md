## 구현·검증된 부분

| 요구 | 현재 증거 |
|---|---|
| 빈 서비스 권한에서 정당한 요청 | `/service/none`이 `/context`와 `/access-requests`를 읽고 실제 회사 서비스 목록에서 요청한다. 없는 회사는 `/company-info`로 이동한다. |
| 요청 중복 방지 | PostgreSQL의 회사·구성원·서비스별 `pending` 부분 유일 인덱스와 회사 행 잠금. 동시 동일 POST 2회가 201/200과 같은 ID를 반환하는 테스트가 통과했다. |
| 관리자 검토 | `/set/member`, `/set/authority`에서 대기 요청 승인·거절 및 상태 조회. `member.manage`를 다시 검사하고 본인 승인·타 회사 접근·오래된 버전을 차단한다. |
| 승인 후 접근 | 승인 트랜잭션에서 `ServiceGrant`와 요청 상태·감사 이력을 함께 저장한다. 실제 `/context`의 서비스 목록에 승인된 서비스가 생기는 PostgreSQL 테스트가 통과했다. |
| 취소·거절 | 요청자만 대기 요청을 취소할 수 있다. 거절과 취소는 권한을 만들지 않으며 재요청이 가능하다. |
| 로딩 상태 | `/loading`이 실제 `/context`를 읽어 회사 등록, 서비스 요청, 대시보드 중 하나로 이동하고 오류 시 재시도 버튼을 제공한다. `/`, `/dashboard`, `/IE`는 일반 구성원의 빈 활성 서비스 상태를 `/service/none`으로 보낸다. |
| GET 로그아웃 | `/logout`의 GET은 로그아웃 실행 버튼만 표시하고 세션 파기는 POST에서만 수행한다. 기존 `LogoutForm` 코드 확인. |
| 전문가 회사 선택 | Migration 49의 배정·서비스 범위·만료·회수를 `/expert/select-company`, `/context`, 운영자 배정 화면에 연결했다. [P03-T02 검증](../P03-T02/README.md). |
| 접근 오류 | `/access-not-allow`는 서버에서 전달한 운영자·역할·서비스·전문가 제한 사유를 구분한다. 서비스 요청 링크는 현재 회사의 요청 가능한 서비스가 API에 있을 때만 표시하도록 연결했다. 전문가 권한은 서비스 요청 대신 배정 확인으로 안내한다. 새로고침은 실제 `/context`와 요청 목록을 다시 조회한다. |

전문가 배정의 최신 전체 회귀는 23개 파일·395개 통과했고, 로컬 production HTTP에서 배정·회사 선택·회수 후 재선택 차단을 확인했다. 자세한 명령과 결과는 [P03-T02 HTTP 기록](../P03-T02/http.txt)에 있다.

[접근 오류 HTTP 실행 기록](access-denial-http.txt): 비로그인 307→로그인, 일반 구성원의 운영자 경로 307→운영자 사유, 사유별 HTML 200, 현재 요청 가능한 서비스 API 조회를 확인했다. 원본 `/access-not-allow`는 일반 안내 한 상태만 관찰되었으며 새 사유별 문구는 독립 구현이다. 실제 브라우저에서 링크 노출·클릭·재조회는 아직 검증되지 않았다.

테스트: `tests/server/access-requests.test.ts` 3건 통과. 인증 401, 출처 403, 입력 422, 타 회사 서비스 404, 조회 권한 403, 동시 중복, 승인·버전 409, 취소·거절, DB 상태 제약을 실제 `catchsecu_test` PostgreSQL에서 확인했다. Migration 48은 개발·테스트 DB에 적용했고 Prisma Client 및 TypeScript 검사에 통과했다.

전체 회귀: `npm test` 22개 파일·391개 통과, `npm run typecheck` 통과, 변경 파일 ESLint 오류 0, `npm run verify:plan` 181개 경로·72개 작업 통과. 로컬 production 빌드의 새 API를 포트 3100에서 실행했다.

실제 로컬 production 서버와 `catchsecu_dev`에서도 [HTTP 실행 기록](http.txt)을 남겼다. 임시 서비스로 로그인 200→화면 200→요청 201→중복 200→관리자 목록 200→승인 200→요청자 `/context` 권한 반영 200을 확인했다. `/logout` GET 후에도 세션이 유지됐다. 임시 요청·grant·서비스를 제거하고 변경 불가 감사 이벤트는 보존했다. 재현 스크립트: `scripts/qa-access-requests.ts`.

## 완료 전 남은 범위

- `/expert/select-company`의 배정된 회사 원본 화면은 관찰되지 않았다. 로컬 브라우저에서 선택·뒤로가기·모바일·회수 즉시 이동을 검증해야 한다.
- `/access-not-allow`의 사유별 안내와 서비스 요청 가능성 조회는 연결했다. 실제 브라우저에서 요청 링크의 조건부 노출·클릭, 역할·전문가 제한 시 미노출, 회수 직후 새로고침을 확인해야 한다. 서비스가 아닌 기능 권한을 서비스 승인으로 올리지 않는 API 경계도 계속 검증해야 한다.
- 원본 Ego 화면 비교, 세션/회사/서비스별 브라우저 직접 URL·새로고침·뒤로가기·모바일 검증, 리디렉션 루프 측정이 남아 있다. 원본 브라우저 제어권이 돌아오기 전까지 원본 동일성을 주장하지 않는다.
- 실제 HTTP 응답은 확인했지만 사용자 조작을 포함한 브라우저 검증은 아직 기록되지 않았다.
