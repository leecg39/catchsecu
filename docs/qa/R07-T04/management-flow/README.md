# R07 공급자·가상 디렉터리 로컬 CRUD 체크포인트

2026-10-10. **원본 로그인 허용 정책과 공식 기관 인증은 아직 미완료**다. 이번 기록은 독립 SSO 공급자 관리와 가상 디렉터리의 실제 DB/API/Ego 검증이다.

## 변경과 결과

- 디렉터리에 이름·이메일·PIN 수정 API/화면을 추가했다. 조직 식별자·사번은 계정 subject이므로 고정한다. 버전 충돌은409이며 이름/이메일은 암호화, PIN은 해시만 저장한다.
- 공급자·디렉터리의 Idempotency-Key를 실제 처리한다. 동시 재전송은 자원/감사 한 번, 다른 내용은409, 삭제된 요청은410이다. 재조회는 현재 권한과 최신 DTO를 사용한다. 기존 키 없는 호출은 유지했다.
- 디렉터리 쓰기 권한을 공급자 관리와 동일한 직접 소속 owner로 맞췄다. admin/security는 읽기 전용이다. Company→actor→provider 순서로 잠그고 저장 마지막에도 접근 기한을 검사한다.
- 수정/삭제 시 대기 이메일 등록 티켓을 폐기하고, 삭제 시 생성 응답 캐시의 암호문/요청 해시도 폐기한다. 기존 연결 User 프로필·계정·이미 발급된 세션은 디렉터리 편집으로 바뀌지 않는다. 공급자 삭제는 기존 별도 세션 종료 계약을 유지한다.
- 조회 실패와 빈 목록을 구별하고, 동기 중복 실행 방지·동일 내용 재시도 키 유지·미저장 모달 닫기 보호·409 최신 내용 복구·검색/정렬/10행 페이지 이동·모바일 표 스크롤을 연결했다. 검색/페이지 이동은 현재 전체 목록에 대한 화면 처리다.

## 티켓 발급 경합 후속 수정

읽기 전용 검토에서 구성원 스냅샷을 읽은 뒤 관리자가 수정/삭제하면, 이미 폐기한 이메일 등록 티켓이 뒤늦게 다시 발급되는 경합을 발견했다. 최종 이메일 등록은 이전에도 거부됐으므로 인증 우회는 아니었다. 발급에 회사→공급자→구성원 잠금, 현재 버전·암호화 프로필·PIN 스냅샷 재검사와 감사 원자성을 적용했다.

- [실패 재현](../../R07-T02/core/ticket-race-before.json): 수정·삭제 경합2개 실패. [검토 기록](../../R07-T02/core/read-only-review.json).
- [최종 회귀](../../R07-T02/core/regression-final.json): **7파일241개 모두 통과**, 실패/보류0. 수정·삭제·공급자 비활성화·회사 폐쇄 경합과 감사 실패 롤백을 포함한다. 위236개는 이전 시점 기록이다.
- [새 빌드의 실제 HTTP](ticket-http.json): 별도 합성 회사에서12검사 통과. 티켓 발급→수정/삭제→이전 티켓401, 대기 티켓0. HTTP 검사는 순차 수명주기이며 실제 경합은 PostgreSQL 시험에서 확인했다.
- [최신 재시작 DB](verified-after-race-fix.json), [Ego 재조회](browser-after-race-fix.json): 기존 공급자3/구성원12/감사32와 상태 해시가 보존됐다.
- 최신 빌드·전체 타입 검사·변경 파일 린트 통과. [품질 기록](../../R00-T02/quality-gates/current.json). 과거 전체1834개 시험을 현재 소스의 전체 회귀로 간주하지 않는다.

## 남은 범위

[원본 근거](../../../planning/09-rea-fullstack/sso-source-evidence.md)상 `/security/sso`는 NONE/AZURE/GOOGLE 로그인 허용 정책이다. 이번 공급자 관리와 동일 기능이 아니다. 해당 정책의 모델·구독 권한·재인증·로그인/연결/초대/회사 전환 집행과 화면이 후속 필수다.20개 인증 경로의 현재 버전 전체 브라우저 수용, 실제 HTTPS 로컬 IdP 브라우저 인증, 공식 GPKI/새올/외부 IdP는 별도다. 기존 OIDC/SAML 서버 시험 통과는 외부 제공사나 원본 성공 증거가 아니다.
