# R07 SSO 정책 집행·복구 체크포인트

2026-10-10. 원본 전 페이지 구현 목표의 부분 진행이다. 정책 저장 API와 원본 SSO 설정 화면은 아직 미구현이다.

## 구현과 확인

- 현재 회사의 NONE/AZURE/GOOGLE를 실제 세션 인증 근거와 대조한다. 연결 Account 존재, 다른 회사의 인증, 임의 공급자 이름만으로 제한을 통과하지 못한다. 저장된 제한은 구독 만료에도 유지한다.
- 요청 문맥과 실제 서비스/파일/다운로드 트랜잭션, 비밀번호 유예, OIDC/SAML/기관 시작·완료 및 SSO MFA에 검사한다. 세션 없는 작업 발급자에는 로그인 근거를 요구하지 않는다.
- 차단된 사용자의 회사 선택·본인 계정 관리·SSO 연결 복구를 유지한다. 회사 선택과 본인확인된 초대 수락은 업무 접근을 허용하지 않으며, 제한 상태에서는 선택 서비스와 업무 권한을 비운다. 초대 재전송도 현재 정책을 반환한다. 상세 회사 목록에서 차단된 회사의 연락처·청구 정보를 제외한다.
- 제한 중 개인 연결 해제를 막는다. 공급자 중지 및 NONE 회사의 마지막 수단 검사도 후보 회사의 현재 정책에 허용되는 계정만 인정한다.

## 증거

- 최신 회귀 **14파일 373개 통과**: [집행·SSO·회사·파일 302개](../../R07-T02/session-evidence/enforcement-regression.json), [구성원·초대·비밀번호 71개](../../R07-T02/session-evidence/enforcement-boundaries.json). 두 실행의 파일 중복은 없다. 과거 339개를 더한 수치가 아니다.
- [실제 HTTP 13개](http.json): 제한 전 업무 문맥, 제한 후 회사/보안 API 403, 서비스·권한 없는 복구 문맥, 내 계정 접근, 허용 SSO 연결 시작, 회사 전환, 업무 페이지 복구 이동. [재시작 후 HTTP](http-after-restart.json)도 동일하게 200/SSO 필요/업무 scope 0이다.
- [재시작 후 DB](verified.json): 세션 1, 인증 근거 0, GOOGLE 정책 v1, 감사 7건. 해시 `bbbb99eb0c32c88318614abb158f5b0c9b298cca415f69e4fc92e41344b4aa3b` 일치.
- [읽기 전용 독립 검토](read-only-review.json): 마지막 로그인 수단 판정과 제한 회사 초대 복구 문제 두 건을 수정하고 재확인했다. 검토자는 DB/테스트를 실행하지 않았다.
- build `.next-rea-enforcement`, 전체 typecheck 통과. 변경 파일 lint 오류 0, 기존 AppShell 이미지 경고 1. OpenAPI 308경로/441작업의 handler·정책 누락 0.

## 시험의 한계와 복구 기록

정책과 공식 endpoint 형태의 제공자는 **QA 전용 DB fixture로 준비**했다. 정책 저장 API, 외부 사전검사, 실제 Google/Microsoft 로그인 성공을 시험한 것이 아니다. 서명 시험은 통제된 전송과 합성 RSA 키로 수행했다. 실제 기관 연결은 별도 미완료다.

초기 새 시험은 불변 구독을 수정하려다 DB 제약에 거절됐다. 만료된 합성 구독을 처음부터 생성하도록 수정했다. 확장 회귀의 파일 시험 6개는 종료된 ClamAV 데몬 때문에 실패했고, 설치된 1.5.4 데몬 재기동과 최신 서명 확인 후 전체 관련 회귀가 통과했다. HTTP 시험기의 잘못된 `/me/profile` 경로는 실제 `/me`로 수정했으며 [중단 기록](runner-path-correction.json)과 중단된 비공개 fixture를 보존했다.

[브라우저 검증은 대기](browser-pending.json)다. Ego 기존 공간 3이 없고 현재 목록도 비어 있어 새 작업공간 생성 확인을 요청했다. 아직 새 복구 UI의 시각적 수용을 완료로 표시하지 않는다.
