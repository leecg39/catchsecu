# 격리 PostgreSQL 설치·시드·업그레이드·복구

2026-10-10. 별도 PostgreSQL 17.11 클러스터의 임시 포트에서 수행했다. 기존 dev/test 서버에는 쓰기 요청을 보내지 않았다. 종료 후 임시 클러스터를 정상 중지했다.

- 빈 DB에 103개 migration 적용. 실행 기록의 모든 checksum이 현재 SQL과 일치하며 미완료 migration이 없다.
- 시드 후 회사2·계정10, 모델129개와 migration 기록을 포함한 테이블130개를 확인했다.
- 시드 반복 실행 전후 모든 테이블의 행 수·내용 해시와 암호화 파일 바이트가 동일하다. 보관된 폼도 다시 게시하지 않는다.
- 102개 migration을 먼저 설치하고 데이터를 저장한 뒤 103번째를 적용했다. 기존 행 유지·전체 checksum·재실행을 확인했다.
- 이메일 중복23505·회사 간 폼 참조23503으로 DB 제약을 확인했다.
- 실제 `pg_dump` 백업을 별도 DB에 `pg_restore`했다. 130개 테이블의 행 수·내용 해시가 모두 같았다. 별도로 복사한 암호화 파일1개는 로컬 QA 키로 복호화했을 때 저장된 SHA-256과 일치했다.

102개 migration 시점의 이전 결과는 `../db-rehearsal-102/`에 보존했다.

첫 실행에서 시드를 반복하면 기존 폼·응답의 수정 시각이 바뀌는 실패를 발견했다. 또한 기존 폼 상태·응답 연결을 무조건 다시 설정하고 파일을 덮어쓰는 코드를 확인했다. 폼 게시 상태와 정보주체 연결은 처음 생성할 때만 설정하고 기존 파일은 다시 쓰지 않도록 고쳤다. 자격증명 출력 위치도 `.local` 하위의 독립 경로로 지정할 수 있게 했다. 최초 실패는 `first-run-failure/`에 보존했다.

최종 결과는 `result.json`, 테이블 대조는 `restored-table-digests.json`, 각 단계는 번호별 로그를 참고한다. 비밀번호와 원본 DB URL은 출력하지 않았다.

실행: Node24에서 `node --env-file=.env.local --import tsx scripts/qa-rea-db-rehearsal.ts`. PostgreSQL 실행 경로는 `REA_POSTGRES_BIN`으로 지정할 수 있다. 시드 계정·파일·덤프는 실행별 `.local/rea-fullstack/pg-<runId>`의 비공개 폴더에 있다.

이 결과는 로컬 고정 fixture의 설치·복구 검증이다. 운영 자료 이관, 대용량 복원 시간, 외부 공급사 자격증명·키 복구, 중단 작업 재개까지 완료했다는 의미는 아니다. 파일은 검사 대기 fixture이며 ClamAV 검사 성공으로 집계하지 않는다.
