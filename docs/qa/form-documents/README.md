# 폼 문서 연결·동의 영수증 검증

2026-10-03. P05-T04·P06-T01·P06-T02의 부분 구현 증거이다. 전체 181개 경로의 완료 판정과 원본 미확정 경로의 의미는 별도로 관리한다.

## 구현 결과

- FormVersion에 같은 회사·서비스의 공개 중인 동의서 버전을 최대 10개 연결한다. 한 문서의 여러 버전을 중복 연결할 수 없고, 문서별 수집/제공 유형과 필수/선택을 저장한다.
- 문서에 일수로 정한 보유 기간보다 긴 폼 보유 기간을 거부한다. 저장 시 문서 열람 권한, 게시 시 현재 공개 상태와 권한을 다시 검사한다.
- 폼 초안 저장 시 서비스 표시 문구, 회사·서비스 공개명, 내부 처리방침 본문·버전·해시를 고정한다. 외부 HTTPS 처리방침은 주소를 기록한다. 승인 검토본과 해시에 이 내용을 포함한다.
- 폼 편집에는 문서 검색·페이지 이동·선택·해제, 필수/선택 변경, 저장된 내용 보기, 현재 표시 설정을 다시 적용하는 저장 기능이 있다.
- 공개 폼에는 고정한 안내·문서별 전체 본문·해시·동의 체크박스를 제공한다. 문서/서비스 내부 ID는 공개 DTO에서 제외한다. 해당 폼 동의 키만 제출할 수 있다.
- 응답과 같은 트랜잭션으로 ConsentReceipt를 만든다. 수락한 문서만 증거에 넣으며 JSON과 PDF를 각각 AES-GCM으로 암호화한다. 증거 SHA-256과 실제 PDF SHA-256을 보관한다. 재시도해도 중복 생성하지 않는다.
- 게시 전에 모든 선택 문서를 포함한 PDF 생성을 검사한다. 지원하지 않는 글자·본문 분량·페이지 수는 게시 이전에 오류로 반환한다.
- 다운로드는 현재 submission.read·서비스 권한·보유 상태를 검사한다. 제출 당시 파일을 그대로 반환하고 감사 기록을 남긴다. 철회 이벤트는 불변 영수증과 구분한다.
- 파기 처리기는 영수증 암호문·PDF·동의 이벤트를 실제 삭제한다. 기존 폼과 CSV 영수증은 evidenceVersion=0을 유지하며 새 PDF를 소급 생성하지 않는다.

migration 21을 로컬 개발·시험 DB에 적용했다. 운영 원본 사이트에는 데이터를 쓰지 않았다.

## Ego 실제 조작

기존 TaskSpace 30 / p1에서 localhost:3100을 사용했다. 모든 응답은 합성 자료다.

1. 새 폼을 만들고 게시 문서 2개를 연결했다. 첫 문서는 필수 수집 동의, 두 번째 문서는 선택 제공 동의로 설정했다.
2. 문서가 허용하는 30일보다 긴 365일 보유 기간의 저장을 거부하는 화면을 확인했다. 30일로 고쳐 저장·게시했다.
3. 기본 동의만 체크하고 제출하면 필수 문서 동의가 누락되어 제출되지 않았다. 이후 필수 문서만 동의하고 선택 문서는 거부해 제출했다.
4. 390px 화면에서 가로 넘침이 없었다(`scrollWidth=390`). 응답 상세에는 수락한 문서 1개만 나타났다.
5. 브라우저가 내려받은 3페이지 PDF를 DB의 복호화 바이트와 대조했다. Poppler로 전체 한글 본문·문서 해시·영수증 ID·응답 ID·내장 글꼴을 확인했다.
6. 폼 본문을 수정해 v2로 게시했다. 이전 공개 링크는 410이고, v1 영수증 파일은 그대로였다. v2에서는 두 문서 모두 동의한 합성 응답을 남겼다.
7. v1 응답을 철회하고 다시 다운로드했다. 서버를 재시작한 뒤에도 다운로드 바이트가 동일했다.
8. v1 응답의 파기를 요청·승인했다. worker가 응답·영수증·이벤트를 삭제하고 증명서를 만들었다. 응답 상세에서 원문과 영수증이 사라졌고, 예전 영수증 URL은 410을 반환했다.
9. v2 응답과 영수증은 유지된다. v2 PDF에서 두 문서의 전체 본문·제공 안내·외부 처리방침 주소를 확인했다.
