# 폼의 게시 문서·표시 설정·동의 영수증 연결 계획

P05-T04와 P06-T01의 다음 구현 묶음. 전체 계획의 선행 게이트는 유지한다. 원본 P/C/OC 의미는 추론하지 않고, 이미 구현한 독립 문서 유형과 버전을 사용한다.

## 데이터와 보존 원칙

1. FormDocumentBinding을 FormVersion과 DocumentVersion에 연결한다. 회사·서비스·문서의 복합 FK, 질문과 같은 게시 후 변경 금지, 중복 문서 버전/순서 제약을 둔다. 선택 문서는 최대 10개이며 필수/선택·수집/제공 표시 유형을 명시한다.
2. 폼 초안 저장 시 서비스 표시 설정과 내부 처리방침 본문·해시를 서버에서 복사한다. 클라이언트가 임의 스냅샷/해시를 저장할 수 없게 한다. 기존 폼은 데이터가 없으면 기존 목적·기간 안내를 사용한다.
3. 문서 버전 선택은 같은 서비스의 공개 중인 동의서/국외이전 동의서만 허용한다. 처리방침은 안내용으로 연결하고 동의 항목으로 취급하지 않는다. 게시 직전에 문서 상태·권한·선택 구성을 재검사한다.
4. 게시 승인 해시에 문서 버전과 고정한 표시 내용을 포함한다. 이후 문서·문구·서비스 표시 설정을 변경해도 이미 게시한 폼/승인본/응답 증거는 바뀌지 않는다. 현재 서비스 표시를 다시 적용하는 명시적 저장 동작을 둔다.
5. ConsentReceipt에 버전이 명시된 암호화 증거와 암호화 PDF·본문 해시·PDF 해시를 저장한다. 응답과 같은 트랜잭션으로 생성하며 제출 재시도 시 중복 생성하지 않는다. 기존·CSV 동의 기록을 새 폼 동의로 꾸미지 않는다.
6. 기존 실제 파기 경로가 확장된 영수증 행 전체를 삭제하도록 검사한다. 보유 기한·권한·보존 조치 정책을 영수증 열람/다운로드에도 적용한다.

## API와 화면

- 폼 동의 설정: 공개 문서 버전 선택/해제, 필수·선택, 표시 유형, 당시 본문·서비스 표시 미리보기.
- 공개 폼: 서버가 고정한 안내·문서별 본문·해시·체크박스 표시. 내부 회사/서비스/사용자 ID는 반환하지 않는다.
- 제출: 허용된 동의 항목만 받고 필수 동의를 검사한다. 새로고침·중복 제출·종료 링크·바뀐 초안으로 제출한 값을 검사한다.
- 응답 상세: 당시 동의 항목과 문서 버전·본문/PDF 해시, 영수증 PDF 다운로드. 철회 이벤트는 기존 불변 증거와 구분해서 표시한다.
- 다운로드: 현재 회사·서비스·submission.read·보유 상태를 확인한다. 공개 링크나 응답 ID만으로 영수증에 접근할 수 없다. 파일은 이미 저장한 바이트 그대로 반환한다.

## 검증 시나리오

- 문서와 표시 설정 변경 뒤에도 이전 폼·응답·PDF 바이트가 고정되는지 확인.
- 필수 누락·미등록 동의 키·타서비스 버전·처리방침을 동의로 등록·동시 수정·권한 회수를 거부.
- 승인 후 문서 선택 변경 시 재승인 요구. 문서/정책 회수와 폼 게시의 경합 검사.
- 선택 동의 거부 시 거부한 문서의 동의 영수증을 만들지 않음. 원자 저장 실패·동일 요청 재시도 시 부분 응답/중복 증거 없음.
- 응답 파기 후 영수증 암호문·PDF 제거 및 다운로드 차단. 오래된 CSV/폼 기록은 기존 의미를 유지.
- 실제 PostgreSQL 통합 테스트와 PDF.js/Poppler의 한글·버전·본문/파일 해시 대조.
- Ego에서 폼 생성→문서 연결→게시→공개 동의/거부→응답 상세→영수증 다운로드→원본 개정→이전 영수증 재확인→철회/파기, 390px 화면 검사.
