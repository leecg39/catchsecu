# 활성 경로 fixture 계약

2026-10-10. `npm run verify:fixtures`는 active-plan.json의 원본 186개와 부가 20개 경로를 읽는다. 과거 P00-T04 증거는 보존한다.

- DB 읽기 전용. 시드 재실행, 기존 상태 덮어쓰기, 외부 발송·결제 없음.
- 정상/권한 거부/실패 시나리오 계약 618개. 실행 상태는 모두 `not_run`이며 CRUD 완료 증거가 아니다.
- 회사·서비스·폼 버전·공개 token hash를 실제 DB와 대조한다. 검사 전 파일이나 없는 행의 ID로 정상 경로를 만들지 않는다.
- 청구서와 결제 결과 경로는 실제 PaymentOrder ID를 사용한다. 콜백에는 임의 state·성공 결과를 넣지 않는다.
- 편집 화면의 formId/documentId/jobId 쿼리까지 명시한다. 와일드카드는 알려지지 않은 주소의 404 시나리오로 분리한다.
- 문서 P/C/OC 접두사의 원본 의미는 미확인이다. 독립 게시문서로 경로 해석만 확인하도록 한계를 적었다.

`route-catalog.json`은 경로별 모델·준비조건·시나리오, `result.json`은 현재 준비 누락이다. 준비가 필요한 경로는 45개다. strict 명령은 누락이 있으면 종료코드 2를 반환한다. `--catalog-only`는 계약 작성만 확인한다.

경로 fixture 단위시험 5개 통과: 없는 주문/미검증 토큰을 실재 ID로 취급하지 않음, 청구서의 실제 모델, 고정 URL, 편집 쿼리, 콜백 선행상태, fallback/알 수 없는 매개변수 거부.
