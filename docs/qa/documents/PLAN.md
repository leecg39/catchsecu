# 문서·게시·서비스 표시 구현 계획

2026-10-02. P05-T02와 P03-T04 일부를 실행한다. 전 페이지 계획의 다음 작업이며 원본 운영 계정에는 쓰지 않는다.

## 확인한 자료와 독립 계약

- 원본 도움말 public/assets/help/3-0.pdf, 3-1.pdf, 3-2.pdf, 9-1.pdf에서 생성, 목적 선택, 내용/설명 수정, 공유 URL, 공개 전환, 서비스 표시 설정을 확인했다. 추출한 텍스트는 이 폴더에 보관한다.
- 원본 /basic 경로는 유료 제한 화면이다. 기존 디자인 토큰과 확인된 메뉴·서비스 설정 필드를 사용해 독립 UI를 구현한다.
- P/C/OC 코드와 services/agree 경로의 원본 계약은 미확정이다. 이번 공개 링크는 의미가 명확한 /document/view/:token으로 발급한다. 기존 세 코드의 호환 구현 및 안내 경로는 P05-T03에 남긴다.
- 본문은 일반 텍스트이며 HTML을 실행하지 않는다. 자동 생성된 목적·항목·보유 기준·제공/수탁자와 사용자가 입력한 안내를 함께 미리보기한다. 법률 적합성 자동 판정은 하지 않는다.

## 구현 순서와 수용 조건

1. Document / DocumentPurpose / DocumentRecipient / DocumentVersion / DocumentPublication / ClauseTemplate / ServiceConsentDisplay 모델과 복합 FK, 불변 개정본, version·상태 제약을 migration 19로 추가한다.
2. 문서 초안 생성·목록·상세·수정·삭제(보관)·복원, 목적/제공자 연결, 문구 템플릿 CRUD와 적용을 구현한다. 현재 역할·서비스 권한을 각 트랜잭션에서 재검사한다.
3. 게시 시 회사·서비스 외부명, 목적·수신자·문구·안내를 스냅샷으로 고정하고 SHA-256 해시와 텍스트 렌더링을 저장한다. 새 게시도 과거 버전을 바꾸지 않는다. 링크는 무작위 token, DB에는 HMAC/암호문만 보관한다.
4. 공개 조회는 활성 회사/서비스/문서/게시 링크와 만료를 매번 확인하고 공개 필드만 반환한다. 개정본 비교, 개별 회수, 전체 비공개, 보관/복원을 구현한다. 기존 서비스 표시 설정에서 참조 중인 게시 링크의 회수는 연결 해제 후 가능하다.
5. 두 종류의 서비스 표시 설정을 DB에 저장하고 미리보기·목록 복원·동시 수정 검사를 연결한다. 외부 처리방침은 HTTPS 주소만 허용하고 서버에서는 주소를 요청하지 않는다. 내부 처리방침은 같은 서비스의 게시 버전만 연결한다.
6. 실제 PostgreSQL API 테스트: CRUD/재시작, 불변 이전 버전, 개정/회수/만료, 서비스/회사 분리, 역할 회수, 동시 수정, idempotency, HTML 문자 무해화, 잘못된 URL·타서비스 링크, 템플릿 편집 독립성.
7. Ego TaskSpace30 p1에서 생성→편집→게시→공개 문서→개정 비교→서비스 설정→회수→보관/복원 시나리오를 실행한다. 별도 DB 조회와 모바일 화면을 대조한다.
