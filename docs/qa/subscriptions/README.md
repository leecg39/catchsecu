# 상품·구독 기반: 부분 구현 검증

2026-10-03. P10-T01의 데이터·요청·체험 한도 기반을 구현했다. 정식 완료 수는 **2/72**를 유지한다. 연간 최종 가격, PG 승인, 실제 유료 시작·변경·해지 예약, 과거 청구 금액 대조와 전체 결제 화면은 남아 있다. [상세 실행 계획](PLAN.md).

## 구현 범위

- Migration 40~43: 상품과 가격 버전, 회사별 구독, 불변 이벤트를 만들고 기존 회사에 7일 체험 기록을 붙였다. 가격 버전 UPDATE/DELETE와 서버 가격과 다른 요청, PG 없는 `active` 상태를 DB가 거부한다. 초기 가격표의 시간대 오류는 migration 41~42로 보정했다. Migration 43은 체험 종료 예약·예약 취소·실제 만료 전이를 DB 상태 기계로 보호한다.
- 월 50,000원인 두 상품은 원본 화면에서 확인한 가격으로 등록했다. 연간 가격은 확인되지 않아 `NULL`, 구매 불가다. 브라우저는 상품 버전 ID만 보내고 서버가 금액을 고정한다.
- `/api/v1/plans`, `/api/v1/subscriptions`는 `billing.read/write`와 회사 범위를 검사한다. 유료 요청은 `pending`으로만 기록하며 멱등키·버전·감사 이력을 사용한다. 취소는 대기 요청에만 가능하다.
- 회사 등록 트랜잭션에서 체험을 발급한다. 서비스·구성원 초대/수락/재활성화·폼·새 정보주체 생성 시 회사별 잠금과 현재 체험 기간·한도를 검사한다. 기존 시험 fixture처럼 구독이 전혀 없는 직접 DB 회사는 호환을 위해 검사에서 제외된다. 정상 회사 등록 경로와 migration은 항상 구독을 만든다.
- 체험 종료 시각 예약·취소는 회사 권한, 버전·멱등키, 7일 기간 경계를 검사한다. 예약 시각이 지나면 조회·생성 권한이 즉시 종료된다. worker가 `trialing → expired`와 불변 이벤트를 배치로 기록하며 두 worker는 행 잠금으로 중복 전이를 막는다.
- 상품·구독 화면은 서버의 가격·기간·사용량을 표시한다. 원본 화면의 고정 체험일·가짜 결제 내역·크레딧 충전 대화상자를 제거했다.
- `/api/v1/entitlements`는 현재 체험·한도를 독립 조회한다. `/api/v1/assets`는 회사별 서비스와 개인정보 주체·캐치폼 건수를 실시간 집계하고 `billing.read`를 검사한다. `/pay/service-asset`은 전용 자산 화면을 표시하며 거부 역할에는 원본에서 관찰한 권한 안내를 보여준다. 원본의 허용 역할 화면은 확인되지 않았으므로 자산 표의 구성은 독립 구현이다.

## 2026-10-13 추가 — 무제한 한도·가격 개정 불변 검증

- **무제한(null) 한도**: `serviceLimit/memberLimit/subjectLimit/formLimit`이 모두 NULL인 활성 구독 회사에서 네 자원 모두 `assertQuota`가 통과하고, 유한 시드 한도(10)를 넘는 12개 서비스 생성 후에도 거부되지 않는다.
