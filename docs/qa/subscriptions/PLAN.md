# 상품·구독·한도 구현 계획

2026-10-03. P10-T01과 R100~R103의 계획이다. 원본 `/pay/membership/detail`은 월 50,000원 상품 두 개와 연 구독 16% 할인 문구를 보여주지만, 연간 최종 결제금액·과세·PG 흐름은 확인되지 않았다. [원본 상품 화면](../../research/services/pay__membership__detail.json), [현재 공개 상품 안내](https://www.catchsecu.com/price). 공개 안내의 가격은 이미지라 텍스트로 검증할 수 없었다. 이 구현은 화면 관찰과 별도 계약으로 구분한다.

## 안전한 결제 경계

- 서버가 버전별 상품 가격·기간·한도를 보관하고 견적을 계산한다. 브라우저 금액·할인율을 승인 입력으로 신뢰하지 않는다. 월/연 선택만 가격표를 바꾼다.
- PG 승인/서명 웹훅이 P10-T02에서 연결되기 전에는 유료 구독을 `active`로 바꿀 수 없다. 청구·크레딧·환불 성공 표시도 만들지 않는다. 실제 계정의 결제수단 원문을 저장하지 않는다.
- 무료 체험은 회사 생성 시 서버가 발급한다. 기존 회사의 초기 전환은 migration에서 명시적인 체험 기한과 출처를 기록한다. 체험·유료·커스텀 모두 기간 경계와 상태를 같은 판정기로 계산한다.

## 데이터와 서버 Task

1. **S01 불변 가격표**: Plan + PlanVersion(상품 키, 버전, 월/연, KRW 정수 단가, 기능·서비스/계정/보관 한도, 적용 기간, 게시 상태)을 만든다. 활성 버전의 본문/가격 UPDATE·DELETE를 DB에서 막고 새 버전을 추가한다. 원본의 연간 금액 미확정은 구매 불가 또는 별도 검증 상태로 노출한다.
2. **S02 구독·이력**: Subscription은 회사·상품·가격 버전·당시 금액·기간·상태·취소 예정일·승인 거래 참조·version을 가진다. SubscriptionEvent는 전환/예약/취소를 불변으로 보관한다. 같은 회사/상품/기간의 활성 구독 중복을 DB에서 막는다.
3. **S03 가격·권한 API**: 목록/상세/견적/현재 구독/자산 조회를 만든다. `billing.read/write`와 회사 범위를 검사하고 다른 회사 ID를 받지 않는다. 생성/변경/해지 예약은 버전·멱등키를 요구한다. PG 이전 요청은 pending으로만 저장한다.
4. **S04 실제 한도**: 서버의 회사/서비스/구성원/폼/보관 데이터 생성 경로에서 현재 entitlement를 판정한다. 동일 회사 advisory/row lock으로 동시 한도 우회를 막는다. 무제한과 제한, 월/연 기간 경계, 유예/만료를 구분한다. 기존 자료는 만료로 삭제하지 않으며 새 쓰기만 계약에 맞게 제한한다.
5. **S05 화면**: `/pay/membership/detail`, `/pay/license-service`, `/pay/billing-policy`, `/pay/service-asset`가 실제 가격/구독/사용량을 보여준다. 연간 확정가/결제 연동 전 구매 CTA는 실제 결제가 불가한 상태를 분명히 표시한다. 금액·기한·잔여량은 하드코딩하지 않는다.
6. **S06 검증**: PostgreSQL에서 가격 불변, 다른 회사/역할, 변조 금액, 동시 한도, 기간 경계, PG 없이 active 불가, 새 가격 버전의 과거 구독 불변을 시험한다. Ego에서 두 계정·월/연/서비스 선택·재시작을 확인하고 DB와 대조한다. 타입·린트·빌드·전체 회귀·migration/OpenAPI를 다시 검증한다.

결제 공급자 실제 승인, 영수증·환불·원장/사용량, 모든 17개 결제 경로의 최종 게이트는 P10-T02~T05로 남긴다. 전체 Task를 부분 구현 증거만으로 완료 처리하지 않는다.
