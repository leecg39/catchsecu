# P10-T02 — 결제수단·주문 현재 권한과 동시 변경

2026-10-06. 이번 내부 보완 및 검증까지 마무리한 뒤, 사용자 요청에 따라 누적 변경사항을 커밋·푸시하고 다음 작업은 시작하지 않는다. P10-T02 전체 완료 판정은 보류한다.

## 변경한 동작

- 결제수단 목록/등록/수정/해지와 주문 목록/상세/복귀/생성은 트랜잭션 안에서 현재 회사·소속·사용자·세션·선택 회사·IP·MFA·비밀번호 정책을 다시 확인한다. 세션 등 기한을 반환 직전에도 검사해, 처리 중 만료 시 업무 데이터와 감사 이력을 함께 롤백한다.
- 회사 변경 잠금을 먼저 확보해 두 요청이 공유 잠금에서 배타 잠금으로 동시에 바꾸며 교착되는 상황을 피한다. 수단 해지와 주문 생성은 같은 회사 잠금으로 직렬화한다. 대기 주문이 있으면 수단 해지를 거부하고, 해지된 수단으로 새 주문을 만들 수 없다.
- 대표수단을 교체하면 이전 수단의 version도 증가한다. 오래된 화면의 수정은 `409 VERSION_CONFLICT`로 거절한다.
- 주문 생성 재전송도 현재 권한을 확인하고 현재 DB의 주문 상태를 반환한다. 로컬 서명 승인 후 재전송은 paid/version2를 반환한다. 다른 결제수단을 요청했는데 기존 대기 주문이 있으면 `409 ORDER_METHOD_CONFLICT`로 명시한다.
- 같은 구독의 서로 다른 요청 키도 대기 주문 하나와 생성 감사 하나만 만든다. 캐시 저장 중 세션 만료 시 주문·감사·요청 키 전체를 롤백한다.
- 결제수단 이름 수정 화면을 추가했다. 실패한 등록 입력을 보존하고, 409 발생 시 최신 목록을 조회한다. 이름 수정 충돌 시 입력을 유지하고 사용자가 최신 버전을 확인한 후 다시 저장한다.
- OpenAPI에 누락된 결제수단 CRUD·주문 목록, 주문 methodId와 필수 Idempotency-Key를 명시했다. 새 DB 마이그레이션은 없다.

## 범위와 남은 검증

- catchsecu_test PostgreSQL만 사용했다. 사용자 개발 DB/3100 서버/상주 worker는 변경하지 않았다. QA3169는 PID43523→43789로 재시작했으며 모두 종료했다. QA 세션0을 확인했다.
- HTTP 승인은 독립 테스트 비밀로 서명한 로컬 합성 이벤트다. 실제 PG API, 카드 등록, 금액 대사, 승인/환불 sandbox 시험을 대신하지 않는다.
- 이름 수정 UI는 타입·린트·빌드까지만 검증했다. Ego 제어 공간 복구 응답 대기로 실제 클릭·화면 비교·모바일 검증은 수행하지 못했다.
- P10-T02/P10-T05를 완료 처리하지 않는다. 전체 완료17/72를 유지한다. 기존 마이그레이션 체크섬4건 불일치는 그대로 미해결이다.
