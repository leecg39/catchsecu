# P07-T03 보존·파기 처리 보완 계획

작성일: 2026-10-04. TASKS.md의 전체 범위를 유지한다. 현재 공식 완료는 15/72이며 이 작업은 구현·검증 후에도 남은 게이트를 따로 기록한다.

## 구현 순서

1. 파기 목록·상세·승인·반려·취소·일정 변경·재처리·보유 기한 변경·보존 조치를 현재 회사, 계정, 서비스 권한, 전문가 배정, 로그인/MFA/비밀번호 정책으로 검사한다. 잠금 대기 및 감사 저장 뒤 기한이 끝나면 조회·변경을 롤백한다.
2. 목록의 검색·정렬·페이지를 실제 조회에 적용한다. 지원하지 않는 쿼리와 중복 키를 거절한다. 서버가 계산한 항목별 작업 권한과 보정된 페이지를 화면에 연결한다. 증명서 상세는 현재 권한으로 다시 읽고 무결성 실패 시 내려받기를 막는다.
3. 파기 작업의 시도 번호를 실행 세대로 사용한다. 현재 lease 소유자·세대·기한을 갱신/완료/실패 시 확인한다. 같은 작업자 이름으로 재획득해도 이전 실행이 완료·재시도 상태를 덮어쓰지 못하게 한다.
4. 접수와 연결된 본인인증·전자서명 영수증, 이벤트, 암호화 요청을 같은 트랜잭션에서 삭제하고 증명서에는 건수만 남긴다. 새 마이그레이션으로 삭제 전제, 연쇄 삭제, 파기 시작 뒤 영수증 재연결 금지, 잔존 원문이 있는 증명서 생성 금지를 강제한다. 기존 적용 SQL은 변경하지 않는다.
5. 실제 PostgreSQL에서 권한 회수·세션/전문가 만료·DB 잠금/감사 지연·동시 실행·저장소 실패·원문 제거·증명서 불변성을 검증한다. 공급자 증거 fixture는 합성 DB 제약 시험으로 표시하며 외부 인증 성공으로 집계하지 않는다.
6. 개발 HTTP 검증은 별도 합성 회사·응답만 사용한다. 처리기는 tenantId/requestId를 지정해 해당 요청만 처리한다. 전체 메일/파기 처리기를 실행하지 않는다. 빌드·재시작 뒤 동일 업무 해시와 남은 원문 0을 확인한다.
7. 타입·린트·관련 및 전체 테스트·계약·마이그레이션 체크섬을 확인한다. 기존 QA hook 출력은 백업/복원하고 이번 결과는 이 폴더에 보존한다.
