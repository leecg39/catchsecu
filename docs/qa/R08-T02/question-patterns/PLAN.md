# 질문 입력 패턴 구현 계획

## 확인한 원본 범위

- 보존 번들 `main.183e9d2c.js` SHA-256 `3538d...`의 UTF-16 offset 8,327,882 부근에서 `infoPatternId` 1·2·3·4·7·8과 일반·추가질의·주민등록번호·이메일·주소·날짜 이름을 확인했다.
- 같은 렌더러는 주민등록번호를 6자리-7자리로 표시하고 생년월일을 숫자 8자리로 제한한다.
- 원본은 API의 `patternRegex` 문자열을 `new RegExp`로 실행한다. 번들에는 실제 정규식 값이나 서버 강제 규칙이 없어 이를 복원된 서버 계약으로 간주하지 않는다.

## 로컬 계약

1. API와 DB에는 확인된 `infoPatternId`만 저장한다. `patternRegex`는 계약의 strict object에서 거부한다.
2. 질문 유형 호환 목록을 DB CHECK와 Zod 계약에서 함께 검사한다.
3. 주민등록번호 형식은 100자 상한 아래에서 고정 문자 순회로 검사한다. 호출자 정규식과 동적 `RegExp`를 사용하지 않는다.
4. 생년월일·이메일·주소는 기존 전용 질문의 서버 검증을 그대로 사용한다.
5. 생략은 기존 질문의 `NULL`을 보존하고, 명시 설정·변경·삭제·복제·템플릿·게시·정정을 실제 PostgreSQL로 확인한다.
6. Ego Lite에서 편집, 공개 입력 형식, 잘못된 값 거부, 정상 제출, 새로고침과 서버 재시작을 확인한다.
