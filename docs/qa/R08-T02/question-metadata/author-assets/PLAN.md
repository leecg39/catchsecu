## 저장·보존·권한 구조

1. `AuthorAssetBlob`은 서버 전용 불변 암호화 저장키·바이트 수·MIME·SHA-256·검사 결과·상태를 갖는다. 기존 private storage와 scanner의 10MiB 상한을 늘리지 않는다. blob ID/storageKey를 클라이언트에 반환하지 않는다.
2. `AuthorAsset`은 UUID, 목적(QUESTION_MATERIAL/OPTION_IMAGE), 회사/서비스 소유 범위, 생성자, 암호화 이름, blob 참조, 업로드/삭제 상태·만료·버전을 갖는다. 공개 템플릿 자산은 별도의 명시적 system 소유 범위이며 일반 HTTP 입력으로 만들 수 없다. 준비된 자산의 이름·목적·바이트를 제자리에서 변경하지 않는다.
3. FormVersion 질문/보기, FormTemplate content, ApprovalRequest snapshot 각각에 참조를 고정한다. 승인 snapshot은 현재 초안이 바뀌어도 독립 참조를 유지한다. JSON/보기 키와 참조행의 일치, 자산 목적·소유 범위·ready/clean 상태를 DB에서도 검사한다. 구현은 서비스의 명시적 참조 동기화와 FK/DEFERRABLE 최종 집합 검증으로 일원화한다. SQL 자동 pin writer를 혼합하지 않는다.
4. 복사·템플릿 사용은 원본을 읽을 현재 권한과 대상 서비스를 쓸 현재 권한을 확인한다. 서로 다른 서비스와 system 공개 템플릿 사용도 지원한다. 원본별로 새 Asset ID를 한 번 발급하고 불변 blob을 공유한다. 소유 자산별 논리 크기로 대상 용량을 예약한다. 원본 삭제나 권한 변경은 이미 독립 복사된 대상의 바이트를 파괴하지 않는다.
5. 업로드 예약을 먼저 영속화한 뒤 파일을 쓴다. 검사/DB/감사 실패로 남은 파일도 저장키를 가진 예약행으로 찾아 정리할 수 있어야 한다. 아직 참조되지 않은 자산은 1시간 임시 보관하며, 참조가 생기면 임시 만료를 해제한다. 마지막 참조 제거 후 정리 유예를 시작한다. 정리 worker는 현재 참조를 다시 검사하고 삭제 상태를 영속화한다. 마지막 소유 자산이 사라진 blob만 물리 삭제한다.
6. 총 용량은 기존 FileObject + CompanyBusinessFile + 삭제되지 않은 소유 AuthorAsset의 합계다. pending/검사실패/정리대기도 정리 완료까지 차지한다. 교체 시 역사 파일을 먼저 차감하지 않는다. 재시도·복사 실패는 원자적으로 롤백하고 실제 사용량을 화면에 반환한다.
7. 업로드·연결/수정은 form.write, 양식/템플릿/승인 읽기는 해당 원래 읽기 권한을 사용한다. 응답 조회·정정 자산은 원래 응답의 버전과 현재 응답 접근 권한을 따른다. 공개 다운로드는 현재 활성 publication의 버전에 속한 키만 허용한다. 외부 열람은 현재 viewer session/grant와 허용 질문만 사용한다. 일반 파일 ID를 작성자 자산으로 받아들이지 않는다.
8. 다운로드는 요청마다 소유 범위와 문맥을 확인하고 바이트를 읽은 뒤 자연 만료를 다시 검사한다. URI 자체가 권한을 대신하지 않는다. private/no-store, nosniff, 안전한 Content-Disposition을 사용하고 PDF/DOCX/AI는 attachment로 보낸다. 이미지 inline은 검사한 JPEG/PNG에만 허용한다. 서버는 자료 URL이나 DOCX 외부 관계 URL을 fetch하지 않는다.
9. Company 잠금→현재 actor/policy→원본/대상 리소스→정렬된 asset/blob 잠금 순서를 가능한 범위에서 맞춘다. 기존 caller transaction의 Company 공유 잠금 upgrade 경합은 별도 양방향 시험으로 확인하고 실패 시 409와 전체 롤백을 보장한다. 고정 snapshot 격리에서 참조/삭제 경합을 놓치면 허용하지 않거나 안전한 동등 가드를 사용한다.

## 내용 검사와 실패 계약

- PDF는 선언 MIME/확장자와 PDF 구조 시작·종료를 확인하고 ClamAV를 통과해야 한다. AI는 원본에서 관측한 PDF 또는 PS 계열을 허용하되 다운로드 전용이다. 실행·렌더링하지 않는다.
- DOCX는 bounded ZIP 검사를 거쳐 `[Content_Types].xml`, `_rels/.rels`, `word/document.xml` 및 문서 형식을 확인한다. 중복/비정상 경로, 암호화, 잘못된 local/central 정보, CRC/길이 불일치, 암시적 macro 형식, 과도한 엔트리/총 압축해제 크기를 거절한다. XML은 DOCTYPE/ENTITY 없이 파싱하고 외부 관계는 해석/fetch하지 않는다. 정상 외부 하이퍼링크 자체를 일괄 금지하지 않는다.
- JPEG/PNG는 제한된 픽셀/디코드 자원 안에서 실제 디코드하되 bytes를 재인코딩하거나 EXIF를 제거하지 않는다. 크기·페이지 수 등 추가 로컬 bound는 코드/시험에 명시한다.
- 새 라이브러리가 필요하면 이미 설치된 실제 버전과 문서를 확인하고 direct dependency로 고정한다. 기존 업로드의 허용 형식/크기를 임의로 확장하지 않는다.
- 원본 자료·secret·쿠키를 오류/감사/보고서에 넣지 않는다. 파일명·URL은 원래 계약상 응답에 필요한 경우만 반환한다. 검증 실패는 422/413/415, 범위 불일치는 404/403, 버전/용량/참조 충돌은 409, 검사 서비스 장애는 503으로 구분한다.

## 회귀·미관측 범위

기존 LINK JSON, ordinary options, custom-choice 답변, PDF 영수증/CSV 의미를 유지한다. 새 nullable option 컬럼이 과거 고정 fixture에 null인지 검증한 뒤에만 기존 해시 계산에서 제외하며 baseline을 새 값으로 덮어쓰지 않는다. 과거 quality archive는 보존하고 이 단위 변경 후 current 결과가 과거 빌드의 증거임을 표시한다.

원본 질문/페이지 복제의 ‘용량 부족 시 파일 제외 복제’는 현재 양식 단위 복사와 구분한다. 해당 질문/페이지 복제 화면 구현 시 명시적 사용자 선택과 새 키 remap을 연결하며, 서버가 조용히 첨부를 버리고 성공 응답을 반환하지 않는다. 문항 설명 이미지·본문 HTML 이미지·다중 페이지는 별도 잔여 원본 기능으로 계속 추적한다. 이번 자산 구현이 이들 기능이나 전체107작업 완료를 뜻하지 않는다.

이전 Ego 전체 화면 이미지 캡처의 실패를 시각 합격으로 바꾸지 않는다. 실제 캡처가 없으면 DOM/기능 확인과 시각 미검증을 구분하여 결과에 적는다. 외부 S3/SMTP 등 실제 제공사 시험도 로컬 시험과 구분한다.
