# F3 질문 메타데이터 — 첫 구현: 추가 설명

승인된 R08-T01~T04의 질문 부가 필드를 구체화한다. 앞선 국제 연락처/PDF 검증은 별도 고정 기록으로 보존한다. 이번 첫 단위는 질문 추가 설명이며 다른 메타데이터의 전체 완료를 뜻하지 않는다.

원본 V3 편집기의 `description` 문자열은 저장 요청의 `additionalExplanation`으로 변환된다. 편집 UI는 textarea와 최대3,000자 설정, 공개 렌더는 `<pre>{additionalExplanation}</pre>`다. HTML 렌더나 원본 서버 검증은 관측하지 않았다. 정확한 UTF-16 위치/해시는 `source-review.json`에 기록한다.

1. **계약/DB**: Question.additionalExplanation nullable text 추가, 기존 행은 null로 유지한다. API는 선택적인 평문0~3,000 UTF-16 단위 문자열이며 공백·개행을 보존한다. NUL/잘못된 UTF-16은 저장 불가능하므로 명시적으로 거절한다. DB에서도 같은 길이 상한을 검사한다. 기존 게시 질문의 불변 트리거와 테넌트/버전 관계를 유지한다.
2. **CRUD/호환**: 생성·읽기·초안 수정·설명 제거를 구현한다. 동일 logical ID의 구클라이언트가 설명을 생략하면 현재 설명을 보존하고 명시적 빈 문자열은 제거한다. 없는 질문의 설명을 다른 질문에서 가져오지 않는다. null은 DTO에서 생략해 기존 승인 지문을 유지한다. 추가·수정·제거는 version/감사/승인 무효화와 같은 트랜잭션 안에서 처리한다.
3. **복제/템플릿/게시**: copy/revise/template create/update/use에 설명을 유지한다. 새 질문 ID 배정과 설명 내용 복사는 구분한다. 게시 후 설명 수정은 새 초안에만 반영한다. 승인 스냅샷·게시 지문에는 해당 버전 설명을 포함한다. 현재 동의 영수증은 질문 자체를 포함하지 않으므로 설명을 새 법률 증거 항목으로 추가하지 않는다. 설명 개정 후에도 기존 동의 evidence·PDF bytes가 유지되는지 검사한다. 질문 본문을 출력하는 기존 PDF 경로가 실제로 확인될 때에만 그 경로의 설명 출력을 별도로 연결한다.
4. **화면**: 질문 편집에3,000자 textarea·현재 길이·삭제를 추가한다. 공개 입력·미리보기·템플릿 요약·응답 정정에서 같은 버전 설명을 평문으로 렌더한다. 개행과 공백, 길고 끊어지지 않는 문자열은 보존/줄바꿈하며 HTML 입력을 실행하지 않는다. 일반 응답 조회에도 설명의 게시 시점이 유지되는지 확인한다. 질문 조건으로 숨김 처리된 설명은 보이지 않아야 한다.
5. **실패 재현/서버 검증**: 구현 전 누락 시험 실패를 저장한다. DB CRUD·3,000/3,001/보조평면 문자·직접DB 길이/게시본 변경 차단·구 DTO/승인 hash·생략과 제거·행 ID 보존·복제/템플릿·게시본/응답 정정/영수증 유지·409/권한/감사 롤백을 필요한 기존 회귀와 연결한다. DB 변경 시험은 주 에이전트가 직렬 실행한다.
6. **마이그레이션 보존**: 적용 전후 기존8개 테이블 공통 컬럼 해시, 새 컬럼 null을 검사한다. dev/test/빈 스키마118개 migration 및 구조 차이를 검증한다. 기존14개 고정 fixture는 새 컬럼이 null인지 먼저 확인한 뒤 과거 지문에서 제외한다. 기존 baseline 자체를 갱신하지 않는다.
7. **실제 수용**: 별도 로컬 QA 회사·폼에서 Ego 추가/수정/제거/새로고침/재개/공개 표시/스크립트 평문/제출·정정·새 게시본을 확인한다. 390/768/1440px, DB/API 값과 감사/버전/PDF를 대조한다. 마지막 production 재시작으로 지문 유지, 타입·린트·빌드·OpenAPI·계획 링크를 확인한 뒤 해당 범위만 검증 완료로 기록한다.

개인정보 분류는 단일 enum이 아니라 detectedItems 배열·NLP/수동 입력·동의 항목 집계를 갖는 별도 후속 단위다. 보기 이미지·참고 파일/링크·기타 직접입력·패턴도 원본 구조를 확인해 별도로 진행한다.
