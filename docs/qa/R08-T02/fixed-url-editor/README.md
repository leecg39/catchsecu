# R08 F5 고정 URL 편집 입력 보호 체크포인트

2026-10-11(KST)에 고정 URL 생성·수정 화면의 입력 유실과 version 충돌 복구를 구현하고 실제 PostgreSQL·production 서버·Ego Lite에서 검증했다. 이 체크포인트만으로 F5, R09 또는 R08 전체를 완료 처리하지 않는다.

## 구현

- 생성·수정 값의 기준본, 현재 입력, 충돌 상태를 독립 상태 모델로 관리한다.
- 이름·slug·연결 폼을 바꾸고 닫기, Escape, 배경 클릭, 취소 버튼 또는 다른 화면 이동을 시도하면 입력 폐기 여부를 묻는다. 저장 중에도 전역 이동을 막는다.
- 저장은 동시 호출을 잠그고, 게시 폼 조회 실패에는 입력을 유지한 채 다시 시도 버튼을 제공한다.
- 기존 고정 URL 저장이 `VERSION_CONFLICT`로 실패하면 사용자의 이름·연결 폼 입력을 유지하고 저장 버튼을 잠근다.
- 최신본 적용은 입력 폐기 확인 뒤 상세 API를 다시 읽어 새 version으로 편집기를 재생성한다. 적용을 취소하면 기존 입력이 그대로 남는다.
- 최신 조회 결과가 이미 사용 종료 상태이면 편집기를 닫고 목록을 갱신한다.

## 실제 검증

1. production 빌드의 `http://localhost:3120/form/fixed-url`에서 게시된 기존 폼을 선택해 고정 URL을 만들었다.
2. 저장 전에 닫기 버튼을 눌러 폐기 경고를 확인하고 `계속 편집`을 선택했다. 이름·slug·연결 폼 값이 모두 유지됐다.
3. 편집 화면에서 이름을 바꾼 뒤 같은 브라우저 세션의 별도 API 요청으로 서버 version을 1에서 2로 올렸다. 오래된 version으로 저장하자 HTTP 409가 발생했다.
4. 409 뒤 화면 이름은 `내 화면 입력 보존`으로 남았고 저장 버튼은 비활성화됐으며 `최신 고정URL 다시 불러오기`가 표시됐다.
5. 첫 최신본 적용에서 `계속 편집`을 눌러 입력 유지를 확인했다. 두 번째에는 `입력 버리기`를 확인해 서버 이름과 version 2를 불러왔고 저장 버튼이 다시 활성화됐다.
6. 이름을 다시 바꿔 version 3으로 저장했다. 서버 PID 91413을 96404로 교체한 뒤 목록, 상세 API, 공개 고정 URL을 다시 확인했다. 공개 URL은 기존 게시 폼 제목을 반환했다.
7. PostgreSQL에서 active version 3, 생성 감사 1개와 변경 감사 2개를 대조했다. 합성 자료는 정상 API로 사용 종료해 version 4, active 0개, 회수 감사 1개가 됐다. 감사 이벤트는 불변 기록으로 보존했고 원본 게시 폼은 그대로 유지했다.

## 자동 검증

- 상태 모델·게시 권한·고정 URL 경합·통합 폼 흐름: 3개 파일, 21개 시험 통과
- TypeScript와 변경 파일 ESLint 통과. 전체 린트는 오류 0개·기존 경고 29개다.
- 로컬 공급자 사용을 명시한 production 빌드: 정적 페이지 82개 통과
- 첫 production 빌드는 `ALLOW_LOCAL_MAIL=1`이 없어 운영 가드가 의도대로 중단됐다. 최종 빌드는 로컬 메일·카카오·결제 허용값을 모두 명시했다. 이 값은 외부 공급자 검증 증거가 아니다.

구조화 결과는 [verification.json](verification.json)에 있다. 실행 로그는 [시험](tests.log), [타입 검사](typecheck.log), [린트](lint.log), [production 빌드](build.log), [계획 검사](plan-check.log)로 보존했다.

## 남은 범위

- 게시·일시중지·재개·승인과 고정 URL을 하나의 version/hash/token 수용 흐름으로 다시 검증해야 한다.
- 정상·빈 목록·로딩·조회 실패·권한 거부·검증 실패·저장 실패·역할별/회사별 격리와 390/768/1440px·키보드·뒤로/앞으로를 전체 경로에서 대조해야 한다.
- 카카오·네이버 OAuth, SMTP 실수신과 그 밖의 외부 공급자 성공 조건은 `external_pending`이다.
