# F3 국내·해외 주소 실행 계획

범위: 승인된 R08-T01/T02의 주소 질문, 모델 계약·편집·제출·정정·내보내기. 이 체크포인트만으로 전체 R08 또는 목표를 완료하지 않는다.

1. 원본 계약: `source-address-review.json`의 UTF16 범위 및 `country-catalog.json`의 SHA를 근거로 국내 문자열, 해외 7필드, 181개 국가, 입력 길이와 선택 질문의 부분 입력 규칙을 연결한다.
2. 모델·서버: 질문 타입 두 개와 strict 해외 객체를 추가한다. 공백·고정 키 순서·국가명은 정규화한다. 국내 5자리 우편번호 형식/1000자, 국가 허용 목록은 독립 서버 계약임을 명시한다. migration115는 타입 제약만 확장하고 기존 게시·답변·템플릿 행은 다시 쓰지 않는다.
3. UI: 새 국내 입력은 실제 카카오 검색과 상세주소를 사용한다. 이미 저장된 문자열은 분리 근거가 없으므로 전체 주소로 보존한다. 새 주소를 검색하면 기존 전체값을 교체하며 신규 입력 중 재검색은 상세주소를 유지한다. 해외 입력은 국가와 다섯 텍스트 필드이며 필수/선택 핵심 3필드 규칙을 동일하게 적용한다.
4. 연결: 공개 제출·조건부 숨김·정정·화면/공유 표시·동기/비동기 CSV·복제·템플릿·revise를 검증한다. 해외 CSV는 7필드 JSON 셀로 내보낸다. 행렬 객체와 주소 객체를 서로 주입할 수 없어야 한다.
5. DB: 기존 제약의 실패를 보존한 뒤 개발/테스트 DB를 순차 업그레이드한다. 기존 8개 테이블 전체 행/컬럼 해시 일치, 새 전용 빈 스키마 설치, Prisma 차이를 확인한다. 기존 frozen fixture는 읽기 검증만 한다.
6. 실제 검증: 새 소유자/회사 fixture에서 Ego 편집·게시·카카오 주소 검색·제출·정정·내보내기를 실행하고 DB 값을 대조한다. 필수 누락·국가만 입력·선택 질문 상세만 입력·취소/재진입·반응형·키보드도 검사한다. 제공사 실패는 실제 결과대로 기록한다.
7. 마감: 관련 통합시험·타입·린트·독립 production build·서버 재시작·이전 fixture 해시를 확인한다. 증거/미검증 범위를 README·계획·진행표에 반영한다.

공식 SDK 근거: [카카오 우편번호 안내](https://postcode.map.kakao.com/guide). 클릭 시 `https://t1.kakaocdn.net/mapjsapi/bundle/postcode/prod/postcode.v2.js`를 로드해 `kakao.Postcode.embed`를 사용하며 `zonecode`와 `address`를 받는다. API 키가 필요 없는 주소 검색이며 본인확인 증거로 취급하지 않는다. 문서는 현재 연동 규격의 근거이고 원본 서버 검증 규칙의 근거가 아니다.

이미지 캡처는 직전 특수 질문 단계에서 Ego `Page.captureScreenshot`이 두 번 시간 초과했다. 이번 단계도 실제 확인 결과에 따라 이미지와 DOM 기반 검증을 구분한다.
