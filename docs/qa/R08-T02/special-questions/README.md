# F3 연락처·이메일·생년월일 체크포인트

2026-10-10. 국내 연락처, 도메인 선택 이메일, 직접 입력 이메일, 생년월일을 기존 질문 모델·CRUD·템플릿·공개 응답·정정·정보주체·마케팅 연결에 추가했다. R08 및 전 페이지 목표는 계속 진행 중이다.

## 원본 관측과 독립 구현

원본 번들 SHA256 `3538d47856c6ba1b4207059dc09434066c7ca692a5907ed792dd9e27c7dba78f`, REA `ev_87493e79c4f053718022b23e1e5d42acf1af245f8c7838a89cd7ebc3918df152`를 분석했다. [오프셋·발췌·미관측 범위](source-observations.json).

| 원본 유형 | 구현 및 저장값 |
|---|---|
| CONTACT | 한국어 폼의 국내 앞자리 선택/직접 입력과 나머지 번호. 문자열 `010-1234-5678`. 선택 질문에서 번호를 비우면 빈 문자열. |
| EMAIL | 아이디·도메인 각각100자, 원본5개 도메인과 직접 입력, 공백 제거, `아이디@도메인` 문자열. 직접 입력 전환 시 기존 도메인을 비운다. |
| EMAIL_DIRECT | 전체100자 단일 이메일 입력, trim한 문자열. |
| BIRTH | 8자리 `YYYYMMDD` 문자열. 원본 안내 예시는19990730이다. |

원본 서버 정규식은 관측하지 못했다. 고정 전화번호·이메일 검사와 실제 달력/윤년 검증은 **독립 구현 계약**이다. 임의 사용자 정규식을 실행하지 않는다. 원본 CONTACT의 국제전화 분기는 formLanguage에 따라 선택되므로 국제 국가목록과 언어 설정은 F5에 남아 있다. 한국어 원본을 국제전화 입력으로 바꾸지 않았다.

기존 Question.type 문자열 모델을 재사용하고 migration114에서 허용 유형과 역할 제약을 확장했다. 기존 텍스트 역할은 유지한다. 정보주체 이메일은 기존 단문형과 두 이메일 유형을 지원하며 이름은 기존 단문형을 유지한다. 마케팅 이름은 기존 텍스트, 이메일은 텍스트/두 이메일 유형, 문자·알림톡은 텍스트/연락처만 허용한다. 원본 응답의 타입을 후보 DTO에 포함해 편집 및 수동 등록 화면을 채널별로 제한했다. DB trigger에도 같은 제약을 적용했고 기존 잠금·서비스 범위·보유기한 검사를 유지했다. 알림톡 질문이 조건부로 숨겨지는 기존 누락도 초안 생성·수정에서 거절하도록 보완했다.

복사·템플릿·개정은 유형을 보존한다. 기존 게시본으로 답변을 해석하며 외부 공유와 CSV에서도 값이 유지된다. 정정은 당시 질문 타입으로 검사하고 실패 시 답변·정정 이력을 쓰지 않는다. OpenAPI에 새 유형 및 마케팅 출처의 질문 타입 응답을 기록했다.
