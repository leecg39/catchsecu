# F3 직접 그리기 실행 계획

승인된 R08-T01/T02의 질문 유형 확장 중 DRAW만 구현한다. 원본의 인증 서명 SIGNATURE 및 IDV_SIGNATURE는 별도 미완료 항목이며 이번 결과로 전체 작업을 완료하지 않는다.

1. 원본 확인: 보존 번들·REA 증거에서 `DRAW → 직접 그리기`, 인라인 흰 캔버스/검은 펜/높이 120px, 지우기·적용하기·다시 입력하기·이전, 빈 그림 거절 및 점 허용, PNG `userSignImage.png`를 확인한다. 서버 계약이나 실제 실행을 정적 분석으로 단정하지 않는다.
2. 모델: 답변은 strict `{s3Key,fileName,fileSize}|null`. 독립 저장소에서는 `s3Key`를 불투명한 FileObject UUID로 매핑하고 실제 경로는 노출하지 않는다. 서버가 잠긴 파일의 이름·크기·PNG·질문/테넌트/게시 버전·검사 결과·첨부 증명을 검증한다. 기존 FILE 문자열 계약을 보존한다.
3. UI: 마우스·터치 캔버스와 적용 전/후 미리보기를 구현한다. 기존 적용값을 유지한 재입력·이전, 필수 누락·빈 캔버스·선택값 비우기, 업로드 중 잠금, 조건부 숨김을 처리한다. 로컬 구현은 크기 변경 시 획 보존과 모든 비활성 조작 차단을 강화한다. 원본 펜 알고리즘의 동일성은 주장하지 않는다.
4. 연결: 공개 제출·정정의 실제 PNG 업로드, ClamAV 검사, 암호화 답변 및 파일 결합, 이전 이미지 이력 유지, 권한별 상세/목록/공유/CSV/다운로드/파기 경로를 연결한다. 파일명은 권한 검증된 FileInfo를 사용한다.
5. DB: migration116 전 타입 제약 실패를 기록한다. 기존 8개 테이블의 전체 행/컬럼 해시를 비교하고 개발/시험 DB를 순차 업그레이드한다. 전용 빈 스키마 설치 및 SQL 제약을 확인한다.
6. 검증: 질문 계약·복제·템플릿·게시·직접 DB 제약·동일/다른 질문 파일 오용·변조 메타데이터·PNG 이외 파일·권한 및 정정 rollback 시험을 실행한다. 관련 기존 파일/공유/파기/내보내기 회귀를 직렬 실행한다.
7. 실제 흐름: 전용 소유자/회사에서 Ego 편집·게시·실제 포인터 그리기·PNG 제출·정정·다운로드·CSV·재시작과 DB를 대조한다. 캔버스 자체 이미지를 저장·시각 확인한다. 전체 화면 캡처의 알려진 실패를 숨기거나 다른 탭 이미지로 대체하지 않는다.
8. 증거: 빌드/타입/린트/스키마/기존 12개 fixture 보존을 확인하고 README·품질 기록·진행표를 갱신한다. 통과 항목과 미검증 범위를 구분한다.
