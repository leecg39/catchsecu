# 구성원·초대 검증

2026-10-02. 독립 로컬 앱의 구성원·초대 기능을 구현하고 검증했다. 전 페이지 완료 기록은 아니다.

## 구현

- 구성원 검색·상태 필터·페이지 조회, 역할·서비스 범위 변경, 정지·활성화·제외.
- 초대 생성, 재발송, 취소, 만료 판정, 가입·이메일 인증·로그인 후 초대 수락.
- 초대 이메일과 검증된 계정 일치 확인, 토큰 해시 저장, 재발송 시 기존 링크 무효화.
- 회사 경계와 역할 상승 방지, 버전 충돌 감지, 반복 요청 중복 방지.
- 소유권 이전 시 비밀번호 재확인. DB 트리거로 마지막 활성 소유자 제거 차단.
- 제외한 구성원 기록을 유지하고 서비스 권한과 해당 회사 세션을 해제한다. 재참여에는 새 초대가 필요하다.

## 실제 확인한 흐름

1. Ego에서 소유자로 초대 생성 → 로컬 worker의 시험 메일함 전달.
2. 초대 링크에서 신규 가입 → 인증 메일의 링크 방문 → 로그인 → 초대 화면 복귀 → 수락.
3. 조회자로 구성원 관리 방문 → 권한 없음 확인.
4. 소유자로 역할을 편집자로 변경하고 두 서비스 지정 → 새로고침 후 값 유지 확인.
5. 구성원 제외 확인 → 제외 상태와 서비스 권한 해제 확인.
6. 독립 DB 조회로 가입 인증·초대 수락·역할 변경·제외·세션 제거·감사 이벤트 대조.

## 검사 결과

- [실제 PostgreSQL 통합 테스트](integration.log): 35개 통과. 새 구성원·초대·소유권 검증 8개 포함.
- [배포용 빌드](build.log): 통과, TypeScript 검사 포함.
- 린트: 오류 0, 기존 이미지·조사 스크립트 경고 21개.
- 계정 A/B의 접근 거부, 동시 수정 200/409, 초대 중복 수락 방지, 만료·취소·재발송, 권한 회수 후 수락 차단, 직접 SQL의 마지막 소유자 제거 거부를 검증했다.
- pg 8.23의 동시 query 경고는 Prisma adapter 트랜잭션 경로에서 발생한다. 현재 테스트는 통과하며, pg 9 업그레이드 전 재점검이 필요하다.

## 남은 범위

- 메일은 로컬 시험 모드다. 외부 SMTP 전달·반송·도메인 설정은 검증하지 않았다.
- 전문가 배정 기능, 계정 탈퇴·회사 폐쇄, 보안 정책 전체와 관리 영역 통합 게이트는 아직 남아 있다.
- 원본 유료 구성원 화면은 관찰하지 못했으므로 새 관리 화면은 기존 디자인 규칙을 따른 독립 구현이다.
- 소유권 이전과 정지·복구는 DB/API 통합 테스트로 확인했으며, 이번 브라우저 기록은 위 여섯 단계에 한정된다.
