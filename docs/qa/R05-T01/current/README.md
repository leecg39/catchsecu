# R05-T01 MY·프로필·활동 검토·탈퇴 모델 대조

현재 개발/테스트 PostgreSQL에서 `User`, `Session`, `Account`, `AccountClosure`, `ActivityReview`, `ActivityReviewMessage`를 대조했다. 두 DB의 70개 컬럼·28개 제약·23개 인덱스·10개 트리거가 일치한다. 기존 migration으로 필요한 관계와 보존 규칙을 집행하므로 새 migration은 추가하지 않는다.

| 모델 | 범위·입력·관계 | 변경·보존 규칙 |
| --- | --- | --- |
| User | 인증된 본인의 이름·연락처·부서·직책·언어만 PATCH. 엄격한 DTO가 이메일·관리자 권한 변경을 거부한다. | 사용자 행 잠금과 version으로 동시 수정을 직렬화한다. 회사 소속 없이도 자기 프로필을 사용할 수 있다. 폐쇄 계정의 재활성화는 DB에서 거부한다. |
| Session | 사용자 FK와 유일한 토큰. 응답에 토큰을 포함하지 않는다. | 본인 세션만 회수하며 매 요청의 살아 있는 사용자·세션을 재확인한다. 폐쇄 계정의 새 세션 생성은 트리거가 거부한다. |
| Account | 제공자·외부 계정의 복합 유일성과 SSO 제공자 FK. 조회는 본인 및 현재 직접 소속 회사로 제한한다. | 최근 로그인과 다른 유효한 로그인 수단이 있어야 해제할 수 있다. 연결 해제는 모든 본인 세션과 대기 인증 증명을 함께 회수한다. |
| AccountClosure | 사용자당 한 기록, 사용자 FK, 완료 시각 ≥ 요청 시각. 입력 사유는 암호화한다. | 이메일·비밀번호·version 확인 후 즉시 폐쇄 상태로 전이한다. 모든 활성 회사 소유권과 마지막 플랫폼 관리자 권한을 먼저 인계해야 한다. 기록 수정·삭제 및 참조 사용자 삭제를 거부하며, 계정의 기존 회사·감사 이력은 보존한다. 별도 사유 보유 만료일이나 자동 익명화는 구현된 것으로 주장하지 않는다. |
| ActivityReview | 회사·서비스·원본 감사의 처리자·요청자·수신자·파기 승인자의 복합 FK. 같은 원본 사건의 진행 중 검토는 하나다. | requested → responded → resolved 또는 requested/responded → cancelled. 종결 시 회사 보유 기한을 기록하고, 기한 경과 후 awaiting → kept/destroyed로 결정한다. 범위·제목 변경과 종료된 파기 상태의 재변경을 DB에서 거부한다. |
| ActivityReviewMessage | 같은 회사의 검토·작성자 FK. 본문 암호화, 목록·감사·안내 메일에는 본문을 포함하지 않는다. | 요청·답변·처리 메시지는 추가만 허용한다. 승인된 파기 트랜잭션에서만 원문을 삭제하고 검토·승인자·감사 이력은 유지한다. |

검토 대상자의 관리자 승격 뒤 본인 건 파기/보존 승인이 허용되던 API 계약 불일치는 [R05-T02 재현·수정 기록](../../R05-T02/current/README.md)에서 별도 검증한다. 모델 스키마 변경으로 해결할 문제가 아니라 현재 행의 수신자와 행위자를 함께 검사해야 하는 서버 규칙이다.

- [현재 모델·품질 검증 집계](verification-summary.json)
- [개발 DB 메타데이터](../model-audit/catchsecu_dev.json) · [테스트 DB 메타데이터](../model-audit/catchsecu_test.json)
- [초기 모델 회귀 69건](model-regression.json): 프로필·세션·폐쇄·회사 격리·메시지 불변성·파기 상태를 실제 PostgreSQL에서 검사했다. 새로 추가한 4개 검사는 탈퇴 기록의 유일성/시각/FK/수정·삭제 금지, 폐쇄 사용자 재활성화/세션/소속 차단, 실패 트랜잭션의 프로필 롤백을 다룬다.

이 기록은 독립 구현의 모델 계약에 대한 증거다. 원본 서비스 내부 DB와의 동일성이나 실제 외부 IdP·SMTP 성공을 뜻하지 않는다.
