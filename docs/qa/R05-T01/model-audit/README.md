# R05 프로필·계정 폐쇄·활동 검토 모델 대조

실제 개발 DB와 분리된 테스트 DB의 PostgreSQL 메타데이터를 읽어 비교했다. 6개 모델, 70개 컬럼, 28개 제약, 22개 인덱스, 10개 트리거가 일치한다. 이 범위에서는 새 migration이 필요하지 않았다.

- `User` / `Session`: 본인 프로필 버전, 이메일·세션 토큰 유일성, 폐쇄 계정의 세션 생성 차단. 프로필 PATCH는 사용자 행 잠금과 버전을 함께 확인한다.
- `Account`: 제공자별 외부 계정 유일성과 SSO 제공자 FK. 연결 해제는 본인·현재 회사·최근 로그인·다른 로그인 수단을 확인하고 모든 본인 세션을 폐기한다.
- `AccountClosure`: 사용자당 폐쇄 기록 하나, 완료 시각 제약, 사유 암호화, 수정·삭제 금지. 사용자 폐쇄 트리거가 활성 회사 소유권 및 마지막 플랫폼 관리자 인계를 요구한다.
- `ActivityReview`: 회사·서비스·원본 감사·요청자·수신자 복합 FK와 진행 중 원본 이벤트당 하나의 검토. 요청→답변→처리/취소, 보유 기한→승인 대기→파기/보존 상태 전이를 제한한다.
- `ActivityReviewMessage`: 본문 암호화, 일반 수정·삭제 금지. 파기 승인 트랜잭션에서만 원문을 삭제하고 검토/감사 기록을 보존한다.

[개발 DB](catchsecu_dev.json) · [테스트 DB](catchsecu_test.json)

이 기록은 로컬 모델 검증이다. 원본 서비스 내부 스키마와의 동일성이나 외부 SSO 인증을 증명하지 않는다.
