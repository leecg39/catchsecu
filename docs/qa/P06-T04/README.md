## 구현

- 생성 재전송도 현재 계정/세션·회사/서비스·폼 상태·파일 권한과 실제 공유의 발급자/게시본/세대·회수/만료를 확인한다. 보관 409, 파일 권한 회수 403, 변경/회수/만료된 요청 410이다. 정상 재전송은 같은 공유 ID만 반환한다.
- 생성 캐시는 `shareGrant` 자원에 연결한다. 이메일/항목/기한 변경·재발송·회수는 신규 캐시와 발급자 범위의 이전 형식 캐시 원문/본문 해시를 제거한다. 기존 코드·challenge·세션 무효화와 이력 보존은 유지한다.
- `permissions.canCreate/canSelectFiles/reason`, `actions.edit/resend/revoke`, 질문 `selectable`을 서버에서 반환한다. 보관 폼의 읽기·회수는 가능하다. 파일 권한이 없으면 파일 추가/재발송은 거부하며 기존 파일을 범위에서 제외하거나 권한을 회수할 수 있다.
- 공유/열람 로그/외부 응답 페이지를 현재 마지막 페이지로 보정한다. 이메일 검색은 공백/대소문자를 정규화한 전체 일치, 최대 254자다. 중복/알 수 없는 쿼리는 422다.
- 공유 잠금·감사/메일 저장 후 로그인 기한을 검사하며 인증 성공 감사 후에도 challenge·공유/발급자 기한을 확인한다. 종료 요청은 변경·메일·인증 세션·성공 감사를 롤백한다. 잘못된 코드의 횟수와 일회 소비는 유지한다.
- 화면은 서버의 현재 작업/항목 권한과 페이지를 사용한다. 생성 성공 응답이 유실되거나 잘못된 성공 본문을 받으면 원래 본문/키로 재확인한다. 확인 전 새 입력/닫기를 막고 최초 확정 입력 거부는 새 입력을 허용한다.
