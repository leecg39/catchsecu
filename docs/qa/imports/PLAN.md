# CSV 수집 구현 계획

이전 goal turn은 수집 근거 모델·API·두 화면과 실제 테스트 증거를 추가한 **progress**였다. 현재 Task는 P07-T01이며 원본 R061~R063은 유료 제한 화면이므로 다음을 독립 계약으로 구현한다. 전체 181개 경로 목표는 유지한다.

## 데이터와 처리 순서

1. ImportJob·ImportRow·ImportEvidence를 만들고 회사/서비스/업로드 파일/처리 목적/원자료 제공자/응답을 복합 FK로 연결한다. 원본은 기존 AES-GCM 저장소와 ClamAV를 사용한다.
2. 업로드 작업을 생성하고 바이트를 업로드·검사한다. UTF-8(BOM 허용), EUC-KR/Windows-949 중 사용자가 인코딩을 선택한다. 최대 10MB·1만 데이터 행·100열·셀 1만자다. 크기 초과나 파싱 불가능 파일은 반영하지 않는다.
3. 헤더를 수집 목적의 항목에 매핑하고 텍스트·이메일·전화번호·숫자·날짜를 지정한다. 필수 항목, 중복 헤더/매핑, 열 수, 빈 행과 파일 내 중복을 검사한다. 잘못된 행은 사유를 저장한다.
4. 원 수집일은 컬럼 또는 명시적으로 입력한 날짜에서 받는다. 동의 근거이면 행별 동의 값과 근거 설명을 요구한다. 다른 근거를 동의했다고 기록하지 않는다. 기간이 일수가 아니면 실제 보유 종료일을 컬럼 또는 고정 날짜로 지정한다. 만료된 자료를 새로 반영하지 않는다.
5. validate는 암호화한 임시 행과 당시 목적/제공자 설정을 저장하고 미리보기를 제공한다. 이 단계에서 Submission은 생성하지 않는다. 설정 수정은 검증을 초기화한다.
6. 명시적 commit은 현재 설정 버전·권한을 확인하고 작업을 고정한다. worker가 원본 파일 삭제를 실제 완료한 뒤 행을 작은 트랜잭션으로 반영한다. 공개 링크 없는 내부 import FormVersion에 기존 Submission/Answer를 연결한다. 같은 job/row의 중복 응답은 DB unique로 차단한다.
7. 반영된 행의 임시 원문은 즉시 비운다. 중복 실패행은 원 행의 Submission에 연결한다. 실패행은 최대 24시간만 보관하며, 연결된 응답이 파기/만료되면 열람을 차단하고 파기 worker가 연결 원문도 제거한다. 실패 CSV의 모든 셀은 인용/이스케이프하고 수식 시작 문자를 무해화한다.
8. 임시 작업 취소는 원본·행 원문 삭제를 요청한다. 완료 작업 보관은 응답을 유지하며, 응답의 실제 삭제는 기존 승인·파기 흐름을 사용한다. worker 재시도·임대 회수·권한 회수·기한 종료를 처리한다.

## 권한과 화면

- import.read/import.write를 owner/admin/editor/privacy 역할에 둔다. 서비스별 권한은 기존 ServiceGrant로 제한한다. viewer·발신·결제 역할은 CSV 원문에 접근하지 못한다. 기존 공개 폼 응답의 submission 권한은 확장하지 않는다.
- 기존 editor/privacy의 전체 역할 권한 템플릿과 일치하는 서비스 배정만 migration에서 새 권한을 추가한다. 부분 권한은 유지한다.
- `/form/info-upload`: 업로드 목록/생성/헤더·컬럼 매핑, `/agreement`: 수집 목적/근거/기간, `/recipient`: 원자료 제공자/검증 미리보기/반영/실패 CSV. 같은 jobId를 URL로 유지하며 새로고침과 뒤로가기를 지원한다.
- `/form/manage`에서 업로드 목록으로 이동하고 완료 작업은 기존 응답 관리로 연결한다. 입력 파일·행을 localStorage에 보관하지 않는다.

## 검증

실제 PostgreSQL과 ClamAV에서 원본 바이트·암호화, UTF-8/BOM/EUC-KR·인용/개행·빈 행·초과 크기·열 수·타입·중복·동의·기간, 검증만으로 응답 0, 부분 성공·두 worker·재시도 중복 0, 회사/역할/서비스 경계, 파일 삭제 실패, 취소/만료·실패 CSV 수식·응답 파기까지 검사한다. Ego에서 실제 파일 선택부터 반영·응답 확인·실패 CSV 다운로드·재시작을 조작하고 DB/파일과 대조한다. 이 전체 흐름이 끝나기 전에는 P07-T01을 완료로 표시하지 않는다.

## 구현 근거

- [csv-parse sync](https://csv.js.org/parse/api/sync/), [공식 옵션](https://csv.js.org/parse/options/). 상한 10MB 안의 메모리 파싱을 사용하고 행 반영은 worker에서 나눠 처리한다.
- csv-parse 7.0.3을 npm registry에서 확인하고 고정한다.
