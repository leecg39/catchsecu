# P11-T02 — 회사 2FA·임시 복구 예외·보안 현황

2026-10-04. 구현과 서버 검증을 마쳤다. 정상 원본 대조·실제 Ego 화면 조작·P11-T01 선행 전체 조건은 미검증이므로 Task 상태는 진행 중이다.

## 구현

- 기존 SecurityPolicy.requireMfa를 회사 인증 정책 API에 연결했다. 직접 소속 owner가 본인 2FA 등록·현재 비밀번호·tenantId·version을 확인한 뒤 변경한다.
- MfaException 모델에 현재 회사 구성원·등록 관리자·암호화 사유·기한·version을 저장한다. 등록·조회·수정·삭제·검색·상태 필터·페이지를 API와 화면에 연결했다.
- 예외는 다른 미등록 구성원에게 발급하며 최초 등록부터 최대 24시간이다. owner 예외도 같은 기한을 적용하고, 예외만 받은 owner는 정책/예외를 변경할 수 없다.
- 만료와 삭제는 기존 세션의 다음 회사 요청부터 적용한다. 서비스·파일의 transaction 안에서 현재 예외를 다시 검사하며, 처리가 길어져 예외 기한을 넘으면 변경·감사를 롤백한다.
- 동일 생성 요청은 현재 결과를 반환하며 삭제/만료 뒤 부활을 거부한다. 삭제는 예외 행과 생성 캐시의 암호문·요청 해시를 실제 제거한다.
- 마지막 인증 owner의 권한 제거·비활성화·인증 해제를 PostgreSQL trigger로 막는다. 개인 등록에서 받은 실제 복구코드로 로그인하고 같은 코드의 재사용이 거부되는지 확인했다.
- `/security/two-factor`, `/security/two-factor/setting`, `/security`, `/security/compliance`을 연결했다. 보안 확인 7항목은 현재 정책·등록·예외·IP·복구 관리자에서 계산하며 개선 동작의 실제 화면 링크를 제공한다.
