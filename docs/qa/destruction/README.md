# 보존·파기 구현 및 검증

2026-10-02. **로컬 PostgreSQL과 비공개 파일 저장소에서 승인 → 실제 삭제 → 증명서 발급까지 검증했다.** P07-T03과 P11-T01의 부분 구현 증거이다. S3·외부 공유·백업 복원 후 재파기와 선행 전체 게이트가 남아 있어 전체 Task 완료 수는 올리지 않는다.

원본의 파기 일정·증명서 정상 화면은 라이선스 제한으로 확인하지 못했다. [사전 작업 계획](PLAN.md)에 정의한 독립 백엔드 계약을 구현했다.

## 구현한 동작

- 파기 요청, 관리자 승인·반려, 예약 변경·취소, 보존 조치, 재시도, 증명서를 DB와 API에 연결했다. 일정 변경은 승인을 초기화한다. 실행이 시작되면 취소·보존 조치·원문 수정은 차단한다.
- 만료 시각부터 답변·메모·정정 원문·동의 영수증·첨부파일 열람을 차단한다. 보존 조치가 있으면 만료 후에도 자료를 유지한다. 파기가 시작된 자료에는 보존 조치를 추가할 수 없다.
- 자동 파기는 기본적으로 꺼져 있다. 보유 기한 만료를 처음 처리할 때 회사 정책에 따라 승인 대기 또는 예약으로 접수한다. 이미 승인 대기 중인 요청은 자동 설정을 켜도 별도 승인이 필요하다. 수동 요청은 항상 승인받는다.
- 취소·반려한 만료 요청은 같은 보유 기한 버전에서 자동으로 다시 만들지 않는다. 다시 파기하려면 응답 상세에서 새 요청을 만든다. 취소로 만료된 원문 열람이 되살아나지 않는다.
- 현재 회사 관리자만 승인·반려할 수 있다. 요청자와 승인자가 달라야 한다는 규칙은 이 계약에서 강제하지 않는다. worker는 실행 직전에 현재 승인자의 소속·역할과 회사 정책을 다시 검사한다.
- 파기일 변경은 회사 정책이 허용할 때, 만료 전에 원래 동의받은 기한 이내에서만 가능하다. 변경 전후 값과 사유는 암호화 이력으로 남기고 파기 때 함께 제거한다.
- worker는 DB 잠금·60초 임대·시도 횟수로 경합과 중단을 처리한다. 파일 삭제 실패 시 원문 접근 차단을 유지하고 재시도한다. 한도를 소진한 작업은 실패로 표시하고 담당자가 재처리를 요청할 수 있다.
- 답변, 메모, 정정 원문·이력, 동의 영수증·변경 이력, 암호화 파일 객체, 파일명·해시·크기, 파기 사유와 관련 중복 요청 응답 캐시를 제거한다. 파일 정정 이전 첨부도 같은 응답에 속하면 포함한다.
- 원문 없는 식별자·최소 감사 기록·재실행 방지 표식은 남긴다. 증명서는 실제 삭제가 완료된 트랜잭션에서만 생성하며 DB 수정·삭제를 금지한다. HMAC은 수량과 식별자·시각의 변경 여부를 확인한다.

프로젝트 루트에서 `npm run db:migrate` 뒤 `npm run worker`를 실행한다. worker는 만료 응답 접수·임시 파일·응답 캐시 정리를 주기적으로 수행하고 파기·메일 작업을 처리한다. 이번 브라우저 검증은 로컬 메일 모드로 실행했다. 실제 외부 발송은 수행하지 않았다.

기존 데이터 업그레이드 시 원래 보유 기한은 당시 `retentionUntil`로 고정한다. 기존의 `pendingDestruction`은 승인되지 않은 legacy 요청으로 옮긴다. 업그레이드만으로 파기를 실행하지 않는다. 과거 상태를 확인할 수 없는 legacy 요청을 취소하면 보수적으로 `withdrawn`으로 둔다.

이전 버전의 중복 요청 기록은 원문 소속을 구분하지 못하므로 migration에서 응답 암호문과 요청 해시를 비운다. 재실행 방지 표식은 유지하고 기존 키 재생은 410을 반환한다. 이후 응답 캐시는 24시간 뒤 또는 연결된 파일·응답의 파기 시 제거한다.

## 남은 범위

- 증명 범위는 현재 DB에서 원문 행을 삭제하고 비공개 저장소 객체를 제거한 결과이다. DB의 MVCC·WAL, 디스크 덮어쓰기, 백업, 이미 내려받은 외부 사본은 포함하지 않는다. 백업 복원 후 재파기는 P14-T04/P07-T04에서 검증해야 한다.
- S3, 외부 공유·정보주체 인증, 보유 기간 미지정 폼의 사후 지정, 서비스별 `RetentionRule` CRUD는 아직 미구현이다.
- 향후 응답 알림·외부 발송 작업에 개인정보 원문을 넣으면 해당 작업에도 응답 소속과 파기 연계를 추가해야 한다. 현재 인증·초대 메일은 응답 원문을 포함하지 않는다.
- 최소 재실행 방지 표식의 장기 정리와 암호 키 교체 절차는 별도 운영 작업이다. 증명서 검증은 현재 HMAC 키를 사용한다.
- pg 드라이버의 기존 동시 query 폐기 예정 경고가 남는다. 테스트 실패는 없으며 pg 9 전환 전 점검 대상이다.

전체 181개 경로의 CRUD와 외부 공급자 검증은 계속 진행 중이다.
