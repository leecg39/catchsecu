# 보존·파기 구현 작업

2026-10-02. TASKS.md P07-T03, P11-T01의 후속 구현이다. 기존 원본 기록의 파기 증명서·일정 화면은 라이선스로 가려져 있었다. 아래는 승인된 독립 백엔드의 동작이며 원본의 숨겨진 동작을 확인했다고 주장하지 않는다.

1. 요청·예약·승인·취소·실패·완료와 증명서를 DB 모델 및 복합 FK로 연결한다. 회사·서비스·최신 역할 권한과 버전 경합을 검사한다.
2. 보유 기한은 게시본의 동의 보유일수로 산정한다. 기본값은 만료 후 승인 대기이다. 회사 최상위 관리자가 현재 비밀번호로 자동 파기를 켤 수 있다. 일정 변경은 회사 정책이 허용할 때 동의받은 원래 기한 이내로 제한한다.
3. 담당자는 파기를 요청하고 관리자는 승인·반려한다. 실행 전 예약 취소·변경과 보존 조치를 허용한다. 파기 시작을 DB에 확정한 뒤에는 원복·보존 조치를 허용하지 않는다.
4. 처리기는 DB 임대와 잠금으로 경합을 제어한다. 보존 조치·정책·현재 승인 권한을 시작 직전에 재검사한다. 파일 실패는 접근 차단을 유지하며 재시도하고, 끝나지 않은 작업에 증명서를 발급하지 않는다.
5. 답변, 정정 원문과 이력, 메모, 동의 기록, 파일명·해시·바이트, 관련 중복요청 응답 캐시를 삭제한다. 원문 없는 감사·파기 증명·중복 실행 방지 표식만 남긴다. 증명서의 범위는 현재 애플리케이션 DB와 파일 저장소이며 백업·WAL의 물리 덮어쓰기를 포함하지 않는다.
6. 응답 상세, 파기 일정, 파기 증명서 메뉴를 실제 API에 연결한다. 만료·처리 중·완료 상태의 원문은 모든 읽기 경로에서 차단한다.
7. 실제 PostgreSQL·저장소에서 만료·보존·권한·동시 승인/취소·처리기 재시작·삭제 실패·재처리·캐시 재생을 검사한다. Ego에서 생성된 합성 응답으로 요청부터 증명서 다운로드까지 수행하고 DB와 바이트 삭제를 별도로 대조한다.

제출된 원문은 합성 QA 응답만 삭제해 검증한다. 백업 복원 후 재파기, S3, 보유 기간 미지정 폼의 사후 지정, 외부 공유 기능은 각 후속 작업에서 검증한다.
