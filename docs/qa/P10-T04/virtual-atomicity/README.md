# 가상 결제·환불 감사 및 기한 원자성

검증일: 2026-10-06(Asia/Seoul). 실제 PG 수용 완료를 뜻하지 않는다.

## 문제와 수정

가상 승인·환불은 권한 확인 트랜잭션을 끝낸 뒤 별도 트랜잭션에서 결제 이벤트를 반영하고, 그 후 사용자 감사 기록을 저장했다. 감사 저장에 실패해 HTTP 500이 반환되어도 주문·구독·원장 또는 환불 정산은 이미 커밋됐다. 권한 확인 잠금과 최종 기한 검사도 실제 변경 전에 끝났다.

공급자 서명·스키마 검사와 이벤트 적용 함수를 분리하고, 가상 경로는 기존 withBillingAccess 트랜잭션 안에서 서명 검사·결제 반영·사용자 감사를 수행하도록 수정했다. 실제 웹훅도 같은 검증·적용 함수를 사용한다. 가상 경로는 모든 변경 뒤 세션·정책 기한을 다시 확인하므로 만료 시 함께 롤백한다. API·스키마·migration 변경은 없다.

## 재현 및 검증

- 수정 전 감사 저장 실패 주입: 2개 실패·기존 5개 통과(`baseline.log`). 승인 후 pending 기대에 paid, 환불 후 requested 기대에 refunded로 실패했다.
- 수정 후 결제·환불·권한·마감 회귀 5파일 53개 통과(`regression.log`).
- 처리 도중 세션 만료를 가상 시계로 주입하는 승인/환불 2개 추가. 최종 가상 결제 9개 통과(`final.log`). 관련 테스트를 합치면 서로 다른 55개이며, 최종 9개에는 앞선 53개의 7개가 포함된다.
- 감사 저장 실패 및 만료 시 주문/구독·환불·원장·공급자 이벤트·사용자 감사가 모두 원래 상태인 것을 PostgreSQL에서 확인했다.
- Node 24.19.0, 전체 타입 검사·변경 파일 린트 통과. DB 시험은 localhost catchsecu_test에 한정했다.
- 적대적 검토: 서명 검사는 외부/가상 양쪽 모두 유지되고 외부에 무서명 이벤트 적용 API가 노출되지 않는다. 권한 잠금은 가상 변경 완료까지 유지되며 최종 기한 검사도 같은 트랜잭션에서 실행된다.

## 남은 범위

실제 PG sandbox 수용, 실브라우저 재검증은 수행하지 않았다. 별도 웹훅 간 동시 이벤트 및 가상 경로와의 경합 직렬화는 다음 검토 대상이다. 외부 공급자 게이트의 완료 상태는 올리지 않았다.
