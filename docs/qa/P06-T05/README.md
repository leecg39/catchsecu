## 구현 결과

- 회사·서비스·응답 잠금 대기와 성공 감사 저장이 끝난 뒤에도 실제 정보주체 세션 기한을 검사한다. 인증 세션 INSERT 뒤 링크 기한·현재 조회 범위를 다시 확인한다. 늦게 끝난 인증/조회/철회는 성공 자료와 감사·일회 소비·철회 이벤트·suppression을 함께 롤백한다.
- 반환할 동의·처리·철회 이력의 가장 빠른 보유 종료 시각을 검사한다. DB 잠금으로 정정/파기를 기다리게 하고 실제 시간으로 종료된 자료는 반환하지 않는다.
- 동의/처리 이력 목록은 현재 보유 자료의 마지막 페이지로 보정한다. 화면의 페이지 표시와 이전/다음 이동은 서버가 반환한 page/pageSize를 사용한다.
- 목록은 page/pageSize만 허용한다. 세션·철회 상세·변경 요청에는 검색 쿼리를 받지 않는다. 알려지지 않은/중복 키는 422다. 동의·처리·철회 응답의 안전 DTO와 페이지 계약을 OpenAPI에 기록했다.
- 인증 메일 처리기는 사용·만료된 요청과 현재 조회 범위가 사라진 요청을 전달 전에 거부한다. 조회 쿠키 수명은 실제 DB 세션의 남은 시간 안으로 제한한다.
- 동일한 진행 중 철회 요청을 재사용하고 취소/확정 재시도는 동일 상태를 반환한다. 다른 정보주체/세션은 요청을 읽거나 확정할 수 없다. 정정된 응답의 오래된 version은 확정을 거부한다.

조회 범위는 본인확인 요청 때 고정한 DataSubject의 회사·서비스·이름/이메일 HMAC 연결이다. 그 연결 안의 현재 보유 동의만 조회하며 새 회사/서비스의 정보주체 연결을 확인 후 추가하지 않는다. 이름/이메일 존재 여부와 관계없이 동일한 202·브라우저 쿠키를 반환한다. URL UUID만으로 인증할 수 없고 답변·연락처·관리자 메모·정정 원문·인증 비밀을 DTO에 포함하지 않는다.

## 실패 시험 기록

수정 전 23개 검사 중 19개가 실제 동작 차이를 재현했다. 최초 native 잠금 검사 3개는 PostgreSQL 통계 스냅샷 갱신이 빠져 대기를 확인하지 못했다. 통계를 갱신한 별도 검사에서 세 경우 모두 잠금 대기 후 잘못된 200을 재현했다. 최종 상태는 모두 401이다. 새 메일 처리기 4개 검사는 사용/회사 중지/서비스 보관/보유 종료를 확인한다.

첫 수정 후 기존 쿠키 검사는 고정 1,800초 기대 때문에 실패했다. 실제 DB 남은 시간을 넘지 않는 양수 수명 검사로 고쳤다. 빌드와 동시 검사에서는 보유기간이 조회 전에 끝난 빈 200 응답 두 건이 있어 시험 기한/감사 지연을 2초/2.5초로 조정했다. 앞서 시작한 전체 검사는 중단했으며 성공 건수에 포함하지 않는다.

HTTP/DB 검증 스크립트의 HMAC 비교 대상 오류와 실패 시 읽기 전용 DB 검사에서 세션을 정리하던 오류를 수정했다. 재시작 검사와 DB 대조를 순서대로 실행한다. Better Auth 로그아웃의 JSON 형식 누락(415)을 고치고 준비 세션도 종료하도록 연결했다. 실패한 합성 소유자의 남은 세션만 namespace/회사/역할을 확인해 두 차례 3+1건 정리했다. 별도 처리기 시험에서 204 빈 응답을 JSON으로 읽던 검사 도우미를 고치고 다시 실행했다. 세 번의 합성 자료 중 마지막 성공한 71건만 최종 HTTP 집계에 포함한다.

이전 공유 회귀 hook이 기록 시간을 갱신한 잠금 증거는 이번 폴더에 보관했다. 이전 파일은 기록된 SHA와 정확히 같은 원래 바이트로 복원했으며 기존 P06-T04 증거 37개는 그대로 유지한다. [보존 확인](historical-evidence-preservation.json).
