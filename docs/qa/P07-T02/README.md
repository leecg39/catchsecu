# P07-T02 마케팅 동의·차단 목록 보완

현재 작업은 진행 중이다. 공식 완료 수는 15/72이며, 전체 경로 구현 완료로 표시하지 않는다.

## 구현한 동작

- 목록·상세·원본 응답 선택·생성·제외·일괄 철회·삭제·CSV·통계를 현재 회사·회원·서비스·계정·MFA·비밀번호·선택 회사·세션으로 검사한다. 감사와 생성 캐시 저장, DTO 처리 뒤에도 세션·배정·비밀번호 기한을 검사한다.
- 조회할 서비스가 없는 통계도 현재 사용자를 인증한다. 공통 사용자 검사를 분리하고 파기 목록의 기존 호출 계약을 유지했다.
- 중복·지원하지 않는 검색 조건은 422다. 등록/동의 시각 정렬, 방향, ID·정규화 이름/연락처 완전일치 검색과 마지막 페이지 보정을 제공한다. 상세·변경 요청에는 검색 조건을 허용하지 않는다.
- 목록/항목의 현재 권한을 서버에서 반환한다. 화면은 최신 목록에서 선택을 계산하고 처리 직전에 상세·version·작업 권한을 다시 확인한다. 출처 선택과 페이지도 현재 응답을 사용한다.
- 처리 중 보유 기한이 끝난 연락처·근거·선택용 답변은 반환하지 않는다. CSV는 NFKC와 선행 제어 문자를 포함한 수식 문자 방어를 적용한다.
- 생성 재실행은 현재 버전을 반환한다. 삭제·원본 기한 종료는 410이며, 새 출처로 재동의한 경우는 409다. 원자 철회와 같은 상태의 반복 요청은 중복 이력을 만들지 않는다.
- API 삭제는 DB에서 큐 원문과 동의를 먼저 삭제한 뒤 로컬 발송 사본을 정리한다. 파일 삭제 실패는 Job.localCopyErasedAt이 빈 기록으로 남으며 상세에서 재시도한다. 이 상태의 큐는 다시 발송할 수 없다.
- 파기 증명서는 연결된 마케팅 Job의 사본 정리 기록이 확인되어야 발급할 수 있다. 이전 63개 SQL은 보존하고 64번째 migration을 추가했다.
- 특정 합성 회사/Job만 처리하는 작업 범위를 제공한다. 발송 결과와 실패 저장은 현재 임대·작업자·증가한 attempts를 검사한다. 마케팅 발송은 원본/연락처 잠금 뒤 Job을 다시 확인하고, 로컬 파일 게시와 SMTP 호출 직전에 동의·기한·임대를 확인한다.
- 이메일 차단 조회에도 중복 쿼리 검사·페이지 보정·감사 뒤 보유 기한/세션 검사와 발송 잠금을 적용했다.

## 남은 게이트

원본 응답 정정·파기 처리와 물리 사본 정리의 확정 순서, 운영 복구 사본까지의 통합 대조는 P07-T04에 이어서 점검한다. 이번 보완의 DB 확정 후 파일 정리는 마케팅 목록의 개인정보 삭제 API에 적용했다.

현재 원본 사이트의 정상 화면 대조, 실제 Ego 화면 조작, 선행 P06-T05 전체 게이트, 운영 저장소/백업의 사본 삭제·복구 정책과 실제 SMTP/SMS 공급자 검증이 남았다. 로컬 mailbox는 합성 수신 검증이며 외부 도달 성공으로 표시하지 않는다. 삭제 후 파일 정리는 한 번에 최대 100개를 처리하고 나머지는 정리 대기 수와 재시도로 관리한다.

Ego 작업 창 재개 질문이 대기 중이다. [ego-browser SKILL.md](/Users/user01/.agents/skills/ego-browser/SKILL.md:74)의 “stop and ask the user” 지침에 따라 기존 작업 창의 제어 승인을 기다린다.
