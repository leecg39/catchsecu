## 재실행 범위

전체 회귀는 두 번째 실행 입력의 54파일 817개를 검사했다. 이후 변경된 next.config.ts, request-query.ts, marketing.test.ts와 새 request-query-keys.ts, proxy.ts는 입력 차이에 기록한다. 최종 코드의 marketing.test.ts 49개와 campaigns.test.ts 55개, 합계 104개를 다시 검사한다. 새 1개는 Next의 실제 matcher와 Proxy 범위를 확인하며, 기존 25개 신규 PostgreSQL 사례와 구분한다. 최종 빌드의 실제 HTTP로 두 API의 예약 키 거부와 범위 밖 회사·계정·로그인 페이지를 확인한다.

설치된 Next 문서는 unstable_doesProxyMatch를 안내하지만 실제 시험용 모듈은 unstable_doesMiddlewareMatch를 내보낸다. 타입 오류를 보존하고 실제 내보내기에 맞춰 수정했다. 이전 production HTTP에서 예약 키가 200으로 처리된 실패 기록도 보존한다. 최종 빌드에서 해결된 결과가 확인되어야 이 항목을 통과로 기록한다.

## 완료 판정에 남은 항목

원본 정상 화면·현재 Ego 조작, 외부 SMTP/SMS 실제 도달, 운영 저장소/복구 사본과 선행 전체 게이트는 확인되지 않았다. 원본 응답 정정·파기의 SQL/물리 정리 통합 대조는 P07-T04에 이어간다. 이 점검으로 Task 전체를 완료 처리하지 않는다.
