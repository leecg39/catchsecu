## 구현한 동작

- 발신자 목록·상세·등록·수정·대표 설정·중지·재인증·이메일/DNS 확인·증빙 준비/연결/삭제·정리 재시도는 현재 회사·회원·서비스·계정·MFA·비밀번호·선택 회사·세션을 검사한다. 잠금·감사·캐시 처리 뒤에도 실제 기한을 확인한다.
- 생성 재실행은 현재 권한과 최신 발신자 버전을 반환하고 삭제 후에는 410을 반환한다. 증빙 재실행은 현재 업로드 상태와 기한을 검사한다.
- 중복·지원하지 않는 검색 조건과 상세/변경 요청의 검색 조건은 422다. URL 변환 전에 예약 키를 검사하고, 이름/등록 시각 정렬과 마지막 페이지 보정을 연결했다.
- 서버에서 현재 작업 권한과 사본 정리 대기를 반환한다. 화면은 처리 전에 최신 권한과 version을 다시 확인하며, 새 내용 위에 이전 수정본을 조용히 덮어쓰지 않는다.
- 만료 DNS 확인값과 임시 업로드 이름을 반환하지 않는다. 조회만 가능한 사용자는 DNS 비밀과 번호 증빙 내용을 받지 않는다. 만료 DNS 원문은 정리 처리기에서 제거한다.
- 인증 코드·DNS 확인·대표 설정·증빙 연결은 감사 처리 중 기한이 끝나면 변경을 롤백한다.
- 확인 메일은 SQL에서 원문과 이전 코드를 먼저 무효화한 뒤 실제 로컬 사본을 정리한다. Job.localCopyErasedAt이 빈 기록은 실패 뒤에도 남는다. 인증 메일/증빙 사본은 별도 정리 API와 화면에서 재시도하며, 삭제된 발신자의 반복 DELETE도 중복 이력을 만들지 않는다.
- 확인 메일은 회사/서비스/발신자/증거/Job을 잠그고 주소·채널·세대·환경·실행 시도·현재 임대를 검사한다. 파일 게시와 SMTP 호출 직전에 확인 기한과 임대를 다시 검사한다. 발신자가 지정된 마케팅 메일도 마지막 시점에 발신자 기한을 재검사한다.
- 기존 64개 migration과 모델을 사용한다. 발신자와 검증 이력의 DB 보호 규칙, 이전 작업 유형으로의 변경 금지를 유지한다.
