# P08-T01 발신자 CRUD·확인 점검 계획

P07-T02 검증 뒤 현재 코드와 완료 조건을 대조하고 구현을 진행 중이다. 정식 완료는 15/72이며 현재 UI·실제 공급자·운영 사본 게이트는 남아 있다.

## 확인한 진입점

- src/contracts/senders.ts와 src/server/senders.ts: 목록·상세·생성·수정, 기본 발신자·비활성·재인증·삭제, 이메일/DNS 확인과 번호 증빙 파일.
- src/server/sender-access.ts와 src/server/sender-providers.ts: 현재 발신자 버전/상태·채널·서비스와 검증된 공급자 사용.
- src/server/jobs.ts: 발신자 확인 메일과 현재 마케팅 동의·발신자 확인 뒤 발송.
- tests/server/senders.test.ts: 실제 PostgreSQL 회귀 사례.

## 실행할 점검

1. 현재 회사·회원·서비스·계정·MFA·비밀번호·선택 회사·세션과 원본/증빙 기한을 모든 읽기·변경·확인 경로에 적용한다. 잠금 대기와 감사/캐시/파일 처리 뒤 최종 기한을 검사한다.
2. 중복/미지원 검색 조건, 현재 작업 권한·페이지 보정·정렬과 생성 재실행을 계약 및 화면에 연결한다. 민감한 주소와 증빙은 현재 권한으로만 반환한다.
3. 등록→편집→인증 대기→확인→재인증→비활성→삭제의 version·불변 이력·이전 확인 코드/발송 무효화를 검사한다. 인증 대기·만료·사용 중 발신자의 실제 전달 차단을 확인한다.
4. 확인 메일과 증빙 파일의 원문/로컬 사본 만료·삭제·실패 재시도를 검증한다. 새 마케팅 사본 정리 기록과 발신자 확인 메일의 정책을 구분해서 검사한다.
5. 자기 합성 회사의 HTTP CRUD·현재 확인 상태·재시작 보존과 실제 PostgreSQL 경합, 관련 회귀·타입·린트·빌드·입력/결과 해시를 기록한다. 기존 계정/회사와 이전 QA를 보존한다.

## 완료 게이트

실제 DNS/SMTP/SMS 공급자·번호 증빙 확인, 운영 저장소/복구 사본 정리, 원본 정상 동작·현재 Ego 화면과 선행 전체 게이트는 검증 후 완료 판정한다. 공급자가 정해지기 전 로컬 발신자 확인을 외부 실제 전달 성공으로 기록하지 않는다.

## 현재 코드에서 확인한 문제와 수정

- 잠금/감사/캐시 후 현재 세션·전문가·비밀번호 기한 검사 누락: 공통 검사에서 받은 기한을 보존해 마지막 비동기 처리 뒤 재검사한다.
- 생성 재실행의 이전 버전·삭제 결과: 현재 발신자 상태/권한을 잠금 아래 확인하고 최신 버전을 반환하거나 삭제 후 410을 반환한다.
- 확인 메일 파일을 SQL 확정 전에 삭제: 큐 원문을 먼저 무효화하고 확정 뒤 지속적인 사본 정리 기록으로 실패/재시도를 관리한다. 증빙 정리도 같은 재시도 화면에 연결한다.
- 실제 게시 직전 인증/임대 만료: 확인 메일과 발신자가 지정된 마케팅 메일은 파일 게시/SMTP 진입 직전에 재검사한다.
- 페이지/정렬·엄격한 검색 조건·현재 작업 권한과 만료 DNS 값: 서버 결과를 화면에 연결하고 만료 확인값/업로드 이름을 응답에서 제외한다.
