# 운영 로컬 공급자 허용값 검증 및 외부 설정 재확인

기준일: 2026-10-06(Asia/Seoul). 기존 일부 기록의 10월 16일 표기는 이번 확인 날짜로 사용하지 않는다.

## 계획·재현·수정

P11-T05 잔여 재점검 중 운영 차단 조건이 문자열 존재 여부만 검사함을 발견했다. `ALLOW_LOCAL_PAYMENT=false` 또는 `0`으로 설정해도 가상 결제 서버가 시작된다. 메일·카카오도 동일하다. 문서화된 `1`만 허용하도록 세 조건을 수정했다.

수정 전 31개 중 18개 실패, 수정 후 31개 통과. 비어 있음·미설정·0·false·true·yes·공백 포함 값은 차단하고 정확한 1만 허용한다. 개발 환경은 유지하며 다른 공급자의 허용 플래그로 결제를 활성화할 수 없음을 확인했다.

## 적대적 검토 및 검증

- 허용값의 truthiness·공백·공급자 간 혼용 경계를 31개 테스트로 검사했다.
- 지원 런타임 Node 24.19.0에서 환경·가상 결제·보안 게이트·platform 관련 4파일 40개 통과(`regression.log`). 최초 재현은 호스트 기본 Node 25.4.0이며 최종 회귀는 지원 버전으로 재검증했다.
- 전체 타입 검사에서 기존 QA 스크립트의 `svcNames` 암시적 any 오류가 발견되어 string[]로 명시했다. 해당 파일의 기존 prefer-const 및 미사용 변수도 정리했다. 브라우저 QA를 다시 실행했다는 의미는 아니다.
- 전체 타입 검사·변경 파일 린트 최종 통과. 최초 오류 기록과 최종 로그를 분리했다.
- 181경로·72작업·의존성 순환 0 검증 통과(`plan.log`). 이번 변경은 UI·Next.js API를 변경하지 않아 브라우저·production 빌드는 재실행하지 않았다.
- PostgreSQL 테스트에서 기존 pg 동시 query deprecation 경고가 나타났으며 테스트 실패는 없었다.

## 외부 자원 재확인

사용자가 지정한 `.env.local`을 사용했다. 비밀값·이메일·전화번호·계정 식별자는 결과에 기록하지 않았다. 서비스 설정은 변경하지 않았다.

| 자원 | 실제 결과 | 남은 수용 조건 |
|---|---|---|
| SMTP | nodemailer verify 연결·인증 성공, 발송 0건 | 앱은 local 모드. 지정된 테스트 수신함으로 발송·수신·반송·수신거부 검증 필요 |
| SOLAPI | 서명한 발신번호 조회 HTTP 200, ACTIVE 1개, 발송 0건 | 승인된 시험 수신번호와 receipt 검증 필요 |
| SSO | DB에 로컬 시험용 SAML 1개·가상 GPKI 6개 | 실제 IdP 설정 및 테스트 사용자 필요 |
| PG | PAYMENT_PROVIDER=local | 실제 PG sandbox 연결 필요 |
| S3 | endpoint/access key 미설정 | 테스트 버킷·접근 설정 필요 |

따라서 기존 “모든 외부 자격증명 부재” 주장은 현재 상태와 다르다. SMTP·문자 자격증명은 존재하고 읽기·연결 검증에 성공했다. 이것을 실발송 수용 완료로 올려 계산하지 않는다. P11-T05 실제 IdP 수용과 후속 전체 게이트는 미완료를 유지한다.

## 다음 계획

1. 가상 결제의 권한 확인과 상태 변경 사이 경합 및 감사 원자성을 검토한다.
2. SMTP·문자 발송은 사용자 지정 테스트 수신 대상과 명시적 발송 지시가 확보되면 실수신·이벤트까지 검증한다.
3. 실제 IdP·PG·S3 설정이 확보되면 P11-T05부터 외부 수용과 후속 게이트를 순차 해소한다.
