# 초기 PDF 바닥글 오류 기록

실제 브라우저 다운로드 파일을 pdfinfo로 검사하여 저장된 pageCount 1과 실제 2페이지가 다름을 발견했다. 여러 페이지 시험 문서는 5페이지로 계산됐지만 실제 파일은 10페이지였다. PDFKit은 하단 여백 밖의 바닥글을 새 페이지로 넘겼다.

바닥글을 그릴 때만 하단 여백을 0으로 설정하여 페이지 추가를 막고 원래 값을 복원했다. PDF.js로 파일을 직접 읽는 테스트를 추가하여 실제 페이지 수와 본문·바닥글만 있는 페이지가 없는지를 검사한다.

이 폴더의 초기 PDF 3개와 메타데이터는 그대로 보존했다. localhost catchsecu_dev에 이 실행에서 생성한 합성 QA 문서 2종의 PDF 3개만 존재하는 것을 잠금 안에서 확인한 뒤 시험용 PDF 캐시를 비웠다. 원본 문서·게시 버전·본문 해시·공개 링크는 변경하지 않았다. 수정 후 내려받은 파일과 대조 결과는 상위 폴더에 저장한다. 운영 데이터나 사용자 자료는 정리 대상이 아니다.
