# 공지사항 DB·API·화면: P13-T01 부분 검증

2026-10-03. 원본에서 관찰한 공지 10건을 로컬 PostgreSQL에 초기 데이터로 옮기고 `/notice`, `/notice/:id`를 API 조회 화면으로 바꿨다. 시스템 운영자 전용 `/admin/notices`에서 작성·수정·미리보기·게시·게시 취소·정렬·보관·첨부를 처리한다. P13-T01은 원본 화면 대조와 전체 수용 게이트가 남아 있어 완료로 표시하지 않는다.

## 구현과 계약

- Migration 44 `Notice`: 본문, 분류, 제목, 게시 상태·시각, 정렬 순서, 작성자, 버전 및 DB 제약·인덱스.
- Migration 47 `NoticeAttachment`: 공지별 최대 10개 PDF/PNG/JPG/TXT/CSV 첨부의 이름·형식·크기·해시·비공개 저장 키와 삭제 상태. 최대 10MB, 실제 파일 형식·SHA-256·ClamAV 검사를 거쳐 암호화 저장한다.
- `scripts/seed.ts`: 캡처한 원본 10건의 ID 59~49와 한국 시간 게시일을 보존해 멱등 초기화한다. 원본의 `<변경 내용>`은 HTML 이스케이프 후 표시한다. 기존 운영자 변경분은 재실행해도 덮어쓰지 않는다.
- `GET /api/v1/notices`: 인증된 사용자는 게시물만 검색·페이지 조회한다. 운영자는 `scope=admin`으로 초안·보관 목록도 본다. `GET /:id?preview=1`은 운영자 전용이다.
- `POST /api/v1/notices`는 운영자 플래그와 멱등키를 요구한다. `PATCH /:id`는 버전을 확인해 수정·게시·게시 취소한다. `DELETE /:id`는 `If-Match` 버전으로 보관한다. 변경과 감사 이벤트는 같은 DB 트랜잭션에 기록한다.
- 서버는 허용된 HTML 태그와 http/https 링크만 저장한다. 일반 계정의 초안·보관 상세는 404, 운영자 작업과 미리보기는 403이다. 운영자 전용 경로의 서버 렌더링도 같은 권한을 검사한다.
- `PUT /:id/attachments/:attachmentId`는 운영자만 공지 버전·클라이언트 생성 UUID·파일 이름/크기/해시·바이너리를 확인하고 첨부한다. 같은 UUID·파일 재요청은 중복 생성하지 않는다. `DELETE`는 접근을 먼저 차단하고 비공개 파일을 지운다. 파일 삭제 실패 시 worker가 `deleting` 상태를 재처리한다.
- `GET /:id/attachments/:attachmentId`는 로그인·게시 상태를 확인하고 저장된 파일의 크기·SHA-256을 다시 검사한다. 운영자만 `?preview=1`로 초안을 받는다. 공지를 보관하면 첨부 링크를 404로 바꾸고 저장 파일을 제거한다.

## 남은 수용 조건

원본 공지 10건에는 첨부가 없어 새 첨부 UI와 원본 화면의 직접 대조는 아직 못 했다. 전체 역할·재시작·새 브라우저 E2E도 남았다. 외부 운영 공지의 실제 갱신은 하지 않았고, 로컬 합성 DB에서만 작성·보관했다.
