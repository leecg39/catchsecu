# 프로젝트 구현 현황 점검 — 2026-10-06

현재 프로젝트는 인증·DB·권한 기반을 갖추고 폼, 응답, 문서, 개인정보 관리, 발송, 결제, SSO의 내부 업무 코드를 연결한 풀스택 개발 단계다. 외부 공급자별 추가 구현과 실제 환경 검증, 전체 화면 수용, 운영 복구 검증이 남아 있어 출시 완료 상태는 아니다.

점검 기준은 커밋 `73f9931`과 현재 작업 디렉터리다. 점검 시작 시 `main`의 작업 트리는 깨끗했고 로컬 `origin/main` 참조와 일치했다. 원격 서버를 새로 조회하지는 않았다. 제품 소스와 기존 Task 완료 상태는 변경하지 않고 이 점검 폴더만 추가했다.

## 확인된 현재 문제

1. **기존 개발 서버의 생성 파일 누락.** 서버 로그에 `.next/dev/required-server-files.json`의 `ENOENT`가 반복된다. 동일 소스로 만든 별도 production 서버는 정상 동작한다. 기존 개발 서버의 재시작·산출물 재생성이 우선 조치다. 파일이 사라진 원인 자체는 이번 점검에서 확정하지 않았다. [로그 발췌](dev-error-excerpt.txt).
2. **적용 이력 체크섬 4건 미해결.** `20261006100000_payment_methods`, `20261006110000_paid_activation`, `20261006120000_refund_closing`, `20261007000000_sso_providers`가 현재 SQL 파일과 다르다. 99개 이력 중 rollback 3개를 제외한 적용 완료 96개만 비교했다. 기존 DDL 일치 보고와 별개로 적용 당시 원문 검증은 남는다. [기존 조사](../P14-T04/migration-drift/README.md).
3. **문서의 과거 설명이 현재 코드와 혼재.** 루트 README의 368개 테스트와 SSO·조건부/행렬 질문·환불·이관 관련 미구현 목록 일부는 최신 범위를 반영하지 않는다. 해당 내부 코드는 이미 존재하므로 미구현으로 단정할 수 없다. 반대로 코드나 HTTP 200만으로 정식 완료 처리할 수도 없다.

## 이어서 진행할 순서

1. 개발 서버를 정상화하고 현재 코드·DB·문서의 기준점을 고정한다.
2. 이미 구현한 폼 생성→편집→게시→응답→정정/철회→파기의 실제 화면 흐름과 SSO·결제 관리 화면을 현재 권한/오류/모바일 조건으로 검증한다.
3. 공급자별 미구현 어댑터를 완성하고 실제 테스트 환경에서 결제·환불·SSO·본인인증·문자·카카오·알림 수신을 검증한다. SMTP 실수신과 문자 발신번호 조회에는 과거 성공 기록이 있으나 전체 업무 수용은 별도다.
4. 181개 경로의 정상/오류/권한 증거와 전체 회귀를 연결하고, 마이그레이션 이력·백업 복원·재파기·키 교체·최종 출시 검증을 마무리한다.
