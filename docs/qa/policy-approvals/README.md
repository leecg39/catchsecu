# 세션·2FA 정책과 폼 승인 검증

2026-10-02. 로컬 PostgreSQL과 Ego Lite에서 검증했다. P04-T03, P11-T01/T02의 일부 구현이며 전체 Task 완료를 뜻하지 않는다.

## 구현

- 회사 정책 조회·변경·기본값 복원. 최상위 관리자, 현재 암호, 회사 ID, 버전을 검사한다. 새 회사와 복원 정책의 비활성 세션 기본값은 30분이다. 기존 회사의 유효한 설정은 보존한다.
- 세션 30~120분, 회사의 2FA 필수 여부, 게시 승인 여부, 담당 역할, 필수 증빙 번호, 요청 기본 양식을 저장하고 서버에서 집행한다.
- 필수 2FA를 켜려면 관리자가 먼저 인증 앱 등록을 완료해야 한다. 필수 회사에 소속된 계정은 2FA를 해제할 수 없다.
- 인증 API와 회사 전환도 비활성 세션을 먼저 검사한다. 인증 라이브러리의 자동 세션 갱신은 끄고, 검사를 통과한 회사 요청에서 활동 시각을 갱신한다. 세션의 절대 유효기간은 로그인 후 7일이다.
- 승인 요청은 전체 질문·선택지·동의 목적·보유기간·응답 한도와 검토 당시 제목을 고정해서 저장한다. 요청 메시지와 결정 사유는 암호화한다.
- 요청 생성·조회·반려·승인·취소·재요청·게시를 연결했다. 승인 내역은 임의 수정/삭제할 수 없다.
- 초안을 저장하거나 승인 관련 회사 정책을 바꾸면 대기/게시 전 승인이 무효화된다. 세션 시간 변경은 승인을 무효화하지 않는다.
- 게시 시 현재 정책·검토본 해시·초안 ID·승인자의 현재 역할/서비스 권한을 확인한다. 게시본에 승인 ID를 연결하고 한 번 사용한 승인은 재사용할 수 없다.
- 회사→정책→폼 순서의 DB 잠금으로 편집·정책 변경·결정·게시 경합을 처리한다. 승인 증거와 상태 전이는 DB 트리거도 보호한다.

## 명시적인 현재 동작과 남은 범위

- 지정된 승인 역할은 자신의 요청도 검토할 수 있다. 원본에서 요청자와 승인자의 분리를 강제하는 조건을 확인하지 못했기 때문에 독립 계약에서 역할/서비스 권한을 기준으로 정했다. 브라우저 검증은 서로 다른 요청자와 승인자로 수행했다.
- 이미 게시한 버전은 새 초안의 검토가 끝날 때까지 유지한다. 정책은 다음 초안 게시부터 적용한다.
- 이 검사 이후 암호 변경 주기·유예·재사용 제한을 [후속 작업](../password-policy/README.md)에서 구현·검증했다. 사후 파기일 정책은 2026-10-12에 구현했다 — `SecurityPolicy.allowRetentionDesignation`(기본값 끄기, 원본 기본값과 동일)이 `PATCH /forms/:id/retention`을 403으로 차단하고 목록 권한 `canDesignateRetention`으로 버튼을 숨긴다. `retention-designation.test.ts` 4/4.
- IP 정책, SSO, 원본의 조건부 재승인 범위, 외부 공급자 시험도 남아 있다. 현재 승인 정책은 초안 수정마다 재승인을 요구한다.
- 폼 파일 업로드·본인확인 공급자·모든 문서 연결은 별도 작업이다. 연결되지 않은 기능의 게시 거부를 유지한다.
