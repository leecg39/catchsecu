# 알림톡 템플릿 등록·상세·수정 후속 수용

2026-10-06. 상세·수정 경로가 미구현 안내로 연결된 문제를 해결했다. 등록 경로도 기존 작성 화면에 연결하고 목록에서 상세로 이동할 수 있게 했다. 외부 채널 확인·승인/반려는 사용자 요청에 따라 로컬 공급자로 대체한다.

## 구현

- 서버의 실제 템플릿·채널명·심사 상태·의견·저장 버전을 표시한다. 이름/본문/5개 이하 버튼을 기존 입력 계약으로 저장하고 수정 후 재심사를 요구한다.
- 저장 실패·버전 충돌 때 입력을 유지한다. 변경이 있을 때 최신 불러오기/화면 이동 전에 폐기를 선택하도록 안내한다. 심사 중·보관 상태는 편집을 잠근다.
- 변수 값을 입력해 실제 미리보기 API를 호출하고 메시지·버튼을 표시한다. HTTPS가 아닌 웹 버튼을 저장하지 않는다.
- 심사 요청·반려 수정·삭제/보관을 기존 API와 연결한다. 새 실제 발송은 하지 않는다.
- 서버 동시 수정은 버전/상태 조건을 같은 UPDATE에 적용해1건만 저장한다. 템플릿 심사/템플릿 콜백/삭제도 조건부 변경으로 중복 및 충돌을 차단한다.
- 현재 회사/계정/세션/정책/MFA/서비스·전문가 권한을 다시 검사한다. 상세 조회·수정·심사 제출·삭제의 트랜잭션 종료 전에도 기한을 검사한다. 잘못된 하위 경로는404로 거절한다.

- [최종 회귀](tests.log):4파일29개 통과. 템플릿/화면·메시지 내용·공급자 감사 원자성을 포함한다. [타입](type.log), [린트](lint.log), [점검기 린트](scripts-lint.log), [최종 빌드](build.log) 통과.

- 브라우저에서 변수 미리보기, 미저장 내용 보호, 잘못된 버튼 URL 차단, 저장 후 초안, Mock반려→수정→재승인,409 충돌 입력 유지와 명시적 최신 불러오기, 보관 잠금, 초안 삭제 및 잘못된/존재하지 않는 ID를 확인했다.
