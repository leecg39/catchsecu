# 발송 직전 만료·처리 임대 경계

2026-10-06, 외부 발송은 Mock으로 대체하고 격리 PostgreSQL에서 실제 작업·원장을 검증했다.

## 수정

문자 잔고 잠금과 이메일 첨부 읽기를 기다리는 동안 원천·캠페인 기한이 지나면 발송을 취소한다. 알림톡·문자·메일은 I/O 직전 현재 상태를 다시 검사한다. 미발송이 확정된 처리 임대 만료는 예약 잔액을 유지하고 재처리한다. 최대 처리 횟수에 도달하면 예약을 해제하고 취소한다. 이미 시작된 외부 전송의 불확실 상태는 자동 재전송하지 않는다.

기존 알림톡은 임대 만료 시 예약을 해제한 뒤 같은 예약을 재사용해, 영수증은 생기지만 청구되지 않는 복구 경로가 있었다. 예약 유지·최대 횟수 종결로 수정했다. 재처리 대기와 중단 사유는 한국어로 표시한다.

## 검증

- 올바른 실패 재현: 7실패/64skip. 문자 원천·캠페인·대체발송 3건, local/SMTP 메일 원천·local 캠페인 3건, 알림톡 임대 재선점 1건.
- 수정 후 신규 11통과/64skip. 추가로 local/SMTP 메일 임대, 문자 임대, 알림톡 최대 횟수 종결을 검증했다.
- 영향 범위 8파일143시험 통과. 캠페인·카카오·문자 어댑터·메일 감사·정산·메시지 내용 포함.
- 타입·변경 파일 린트·최종 production 빌드 종료0. runtime 의존성 감사0건.
- Ego56/p1 최신 전용 Mock 서버에서 문자·이메일·알림톡 이력 화면 3경로 기본 표시 통과. 이력은 빈 목록이며 신규 사유가 실제 표시되는 전체 발송 화면 시험을 주장하지 않는다.

시간 전진은 Date만 모의하고 실제 DB 잠금/첨부 대기를 확인했다. 처음 작성한 시험 2건은 불변 expiresAt 갱신으로 fixture가 실패했으므로 제품 실패로 집계하지 않았다. 이후 처음부터 짧은 기한으로 생성해 재현했다. 원장 시간 정렬은 fake Date와 실제 DB 시계가 다르므로 원장 종류·예약 참조·잔액을 검사했다.

## 적대적 검토와 범위

동일 작업의 미발송 재선점에서 예약 해제 후 재사용을 막았다. Job 행 잠금 동안 처리자·상태가 바뀌지 않으며, 발송 기한은 잠금/첨부 대기 후 다시 확인한다. 신규 예약·capture는 원장 제약을 그대로 사용한다. 미확인 SMTP 전송을 안전한 재처리로 확대하지 않았다.

수동 재요청의 새 delivery attempt가 같은 원장 source를 재사용하는 위험은 별도 후속 검증 대상이다. 이 보고서로 해결했다고 표시하지 않는다. 전체1,748시험은 이번 수정 전 소스 기준의 별도 보고서이며 신규 시험을 더해 전체 재실행 수치로 표시하지 않는다. 원본 화면 대조·실외부 수용·전체 게이트 체크박스는 유지한다.
