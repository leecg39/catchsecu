# 조직 이메일 등록과 로그인 원자성

외부 조직 인증은 Mock 디렉터리로 대체한다. 실제 GPKI/새올 공급자 수용은 아니다.

등록 티켓 제출 뒤 로그인에 실패해도 이메일·디렉터리 버전·등록 감사가 남던 문제를 수정했다. 이메일 수정, 티켓 소비, JIT 계정·소속, 로그인 세션·감사를 같은 트랜잭션에서 처리한다. 회사→공급자→디렉터리 순서로 잠그고 현재 접근·공급자·디렉터리 버전·티켓 기한을 확인한다. 완료 전 만료/감사 실패도 모두 롤백한다. 실패한 입력은 유효 기한 안에서 수정해 재시도할 수 있으며 성공한 티켓은 재사용할 수 없다.

## 재현 및 검증

- 최초 신규5개: 문제4개 재현/동시 등록 통제1개 통과(red.log). 공급자 정지·이메일 충돌·로그인 감사 실패·마지막 기한 만료에서 등록 변경이 남았다.
- 확대13개: 제품 문제5개와 시험 fixture 문제1개가 실패했다(red-expanded.log). 회사 폐쇄가 추가 제품 문제다. IP 시험은 활성 규칙 없는 정책을 만들려다 DB 제약에서 거절된 것으로 제품 문제에 합산하지 않는다.
- 첫 수정 후12개 통과/같은 IP fixture1개 실패(first-green-fixture-error.log). 허용 규칙을 포함한 정상 정책 fixture로 정정한 뒤 거절/롤백을 확인했다.
- 최종7파일220개 전부 통과(regression.log), 실패0/skip0/종료0. 조직13개와 OIDC/SAML/회수/초대·연결/보안 게이트의 영향 범위를 포함한다. 타입·린트·빌드 종료0. 린트 기존 경고2개는 숨기지 않았다.
- 실제3189 새 빌드: health200, 존재하지 않는 등록 티켓401/세션 쿠키 없음(http.json). 브라우저 새 실행을 의미하지 않는다.
- 이번3개 소스의 검증 중 해시 변경 없음(result.json). 새 전체1,782개 실행으로 표시하지 않는다. 이전1,774개 회귀 증거와 이번220개 영향 범위는 분리한다.

새 DB 마이그레이션은 필요 없다. 기존 공급자 설정·SSO 계약·최초 로그인 흐름은 유지한다. 실제 외부 연동·원본 화면·잔여9경로 브라우저 검증과 개발 도구high5는 별도 후속이다.
