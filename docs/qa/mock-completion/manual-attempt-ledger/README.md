# 수동 재요청 원장 분리

2026-10-06, 격리 PostgreSQL·로컬 발송으로 검증했다.

## 문제와 수정

문자·알림톡·문자 대체발송이 확정 실패한 뒤 수동으로 다시 요청하면, 첫 요청에서 해제한 예약을 같은 원장 source로 재사용했다. 실제 발송 영수증이 생겨도 capture가 실패하고 이후 복구가 청구 없이 완료될 수 있었다.

최초 발송과 최초 대체발송의 키는 유지한다. 새 수동 attempt에는 별도 키를 사용한다. 발송·영수증 복구·중단 작업 정리·문자 webhook이 공통 계산을 사용한다. 이전 빌드가 같은 키로 미정산 예약한 건은 기존 예약을 복구하며, 이미 해제된 예약은 재사용하지 않는다. webhook은 캠페인→수신자 잠금으로 재요청과 직렬화하고 현재 문자 발송 예약만 정산한다.

## 증거

- 수정 전 6실패/75skip: 문자·알림톡·대체발송의 정상 재요청 및 영수증 생성 뒤 worker/cleanup 복구. 실제 원장 capture0·잔액 미차감으로 실패했다.
- 수정 후 신규6통과/75skip. 재요청 중복 키·예약 참조·청구1회·잔액·파일 바이트 보존 확인.
- 정산 전체13통과: 신규 webhook 접수/실패/미확인 3건과 이전 빌드 예약 복구2건 포함.
- 최종 영향 범위: 서버7파일142시험 및 별도 UI1파일12시험, 합계8파일154시험 통과. 처음 실행 인자의 UI 확장자 오류로 해당 파일이 제외되어, 정확한 경로로 추가 실행했다. 이를 하나의 전체 실행으로 표시하지 않는다.
- 타입·변경 파일 린트·production 빌드 종료0. 의존성 변경은 없고 앞선 runtime audit0 증거를 유지한다.

앱/시험 소스는 최종 회귀·빌드 동안 동결했다. 추가 브라우저 QA 준비 도구의 타입 오류(작업 범위 tenantId 누락)를 수정했고 전체 타입 검사를 다시 통과했다. 실제 외부 수신·원본 화면 대조·전체1,748시험의 재실행을 의미하지 않는다.

## 적대적 검토와 다음 경계

해제된 예약은 새 요청과 공유하지 않고, 자동 작업 재선점은 같은 요청의 예약을 유지한다. 복구도 발송과 같은 키를 사용해 새 파일 생성·중복 차감을 막는다. 원장/영수증 불변 제약을 완화하지 않았다.

SmsReceipt가 수신자별 단일 기록인 현재 설계에서는 이미 공급자 실패 결과가 기록된 수신자의 수동 재요청과 늦게 도착한 이전 결과의 경계가 별도 검증 대상이다. 이번 로컬 재요청 수정으로 그 경계까지 해결했다고 표시하지 않는다. 다음 작업에서 실제 Mock 공급자 결과를 사용해 재현한다.
