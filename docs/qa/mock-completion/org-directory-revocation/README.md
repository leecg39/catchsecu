# 진행 중인 조직 로그인과 디렉터리 회수

PIN 확인 뒤 SSO 완료 전에 디렉터리가 삭제·변경되어도 성공하던 두 경합을 재현했다. SSO 완료 트랜잭션 안에서 회사/공급자 잠금 후 디렉터리를 잠그고 현재 존재·버전·자격 스냅샷을 다시 확인한다. 회수가 먼저 완료되면 로그인·JIT 계정·세션 발급을 거절한다. 정상 로그인과 기존 연결 흐름은 유지한다. 기존 세션의 별도 회수 정책을 새로 정의하는 변경은 아니다.

- red.log: 신규2개 실패(expected401/409, actual200), 필터로 기존13개 미실행. 이를 전체 시험 실패/skip 통과로 집계하지 않는다. 실제 대기·재개 장벽으로 PIN 확인과 SSO 완료 사이에 DB 삭제/변경을 배치했다.
- green.log: 조직 인증15개+보안 통합2개, 2파일17개 모두 통과/skip0/종료0.
- 타입·변경파일 린트·최종 빌드 종료0. 린트 기존 경고1개는 보존했다.
- 직전 조직 등록 원자성7파일220개는 a955b29 기준이며, 이번 후속까지 모든220개를 다시 실행했다고 표시하지 않는다. completeSso 공통 구현은 이번 후속에서 바꾸지 않았다.

실제 조직 공급자는 Mock으로 대체하며 브라우저 새 검사·원본 화면·전체 게이트 완료를 의미하지 않는다. 기존3100 서버는 변경하지 않았다.
