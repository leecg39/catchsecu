# Ego 실제 브라우저 Mock 검증

2026-10-06, 사용자의 “56번 제어권 회수해서 계속 진행” 지시에 따라 기존 공간56을 회수했다.

- [최종 결과](report.json): 19개 사례 전부 통과. 1440/768/390px 총57회 화면 검사, 각 사례 새로고침·뒤로가기 통과. 측정한 콘솔/실행 오류·실패 리소스·오류 알림·가로 넘침0.
- 결제4, 실제 게시 문서3, 공개 폼/고정URL5, 파일4, 공유목록1, 정보주체2. 문서3종은 `/document/view/:token`의 서로 다른 게시물이다. 원본 P/C/OC3경로의 완료 증거가 아니다.
- 모바일 결제·첨부·문서·폼과 데스크톱 공유목록 캡처를 직접 검토했다. 실제 토큰·쿠키·캡처는 `.local/ego-mock-pages/<runId>/`에만 저장했다.
- 제품 전체181경로, 역할별 전체 거부, 원본 UI 대조, 출시 게이트의 통과를 의미하지 않는다.

## 실패와 수정

1. `network-idle-attempt.json`은 초기 부분 관찰이다. CLI 중단 뒤에도 내부 스크립트가 계속되어 후속 실행과 겹쳤다. `network-idle-completed.json`이 해당 내부 실행의 종료 기록이며 제품 결함 판정에 사용하지 않는다.
2. 이후 독립 실행의 [15통과/4실패](fixture-path-failures.json)를 분석했다. 문서 P/C/OC의 임의 유형 매핑은 계약상 금지되어 있었고, 고정 URL에는 등록 slug가 필요했다. fixture가 이를 잘못 연결했다.
3. 실제 게시 URL을 사용하고 고정 URL을 API로 등록/조회하도록 수정했다. API36검사를 통과한 새 fixture로19개를 재실행했다. 제품 경로/권한은 변경하지 않았다.
4. 실행기는 DOM의 기대 본문을 기다리며, 실행별 독립 기록과 오류 종료를 사용한다. 타임아웃/CLI 중단 시 내부 작업의 종료를 확인하기 전 같은 페이지에 새 실행을 시작하지 않는다.

변경된 실행기·fixture의 린트 및 프로젝트 타입 검사 통과. 전체 서버 회귀를 이번 화면 검증 후 다시 실행한 것으로 표시하지 않는다.
