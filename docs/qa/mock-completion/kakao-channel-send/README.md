# 알림톡 채널 관리·단건 Mock 발송 후속 수용

2026-10-06. 채널 수정·삭제 화면을 기존 API에 연결하고 단건 Mock 발송의 권한/상태 검사·영수증·감사·재시도를 하나의 DB 트랜잭션으로 처리했다. 실제 공급자 발송이나 수신자 도달을 증명하는 작업은 아니다.

## 구현과 검토

- 채널 수정 폼에서 현재 이름·검색 ID·버전을 읽는다. 입력 검증/409 충돌 시 값을 유지하고, 최신 내용 불러오기나 취소/이동 전에 수정 폐기를 선택하게 한다. 요청 중 서비스 변경·다른 채널/템플릿 조작을 잠근다.
- 검색 ID 변경 시 확인과 연결 템플릿의 승인이 해제된다는 설명을 표시한다. 삭제/보관은 명시적 대상·버전 확인 후 실행하며 사용 중인 템플릿이 있으면 거절한다. 이력이 있으면 보관, 없으면 삭제한다.
- 같은 이름의 여러 채널이 있어도 버튼에 검색 ID를 포함해 구분한다. 첫 브라우저 실행에서 이름만 있는 버튼4개가 모호하다는 오류를 발견하고 수정했다. 해당 초기 보고서는 `.local/kakao-channel-browser-initial.json`에 보존했다.
- 단건 `/kakao/templates/{id}/send` 계약에 `{version}`과 `Idempotency-Key`를 요구한다. 실제 발송 공급자가 없으면503, 현재 승인/확인이나 버전이 맞지 않으면409다. 로컬 공급자에서는 `mock:true`와 `local_delivered` 메타데이터를 반환한다.
- 새 `KakaoMockReceipt`는 당시 템플릿/채널 버전·범위·독립 영수증 ID·시각·요청 ID와 본문/버튼의 조회용 HMAC을 저장한다. 본문·연락처는 저장하지 않는다. 기존 단건의 본문 파일 생성/덮어쓰기를 제거했다. 조회용 HMAC은 암호화 키 회전과 분리된 기존 lookup key를 사용한다.
- 회사/계정/세션/현재 정책·MFA·서비스 권한과 종료 기한을 검사하고 채널 및 템플릿을 잠근 뒤 영수증·사용자 감사·재시도 결과를 함께 커밋한다. 동일 키 재생에도 현재 권한을 검사하며 메시지 본문을 돌려주지 않는다. 다른 내용은409다.
- DB 제약/트리거는 다른 서비스·채널·현재 승인 버전의 삽입과 영수증 변경/삭제를 거절한다. 영수증이 있는 템플릿은 수정 후 초안으로 돌아가도 삭제 대신 보관해 과거 증거를 유지한다. 실제 수신자 캠페인은 기존 `/campaigns` 흐름을 유지한다.
