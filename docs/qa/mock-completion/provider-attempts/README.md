# 문자 공급자 회차와 불확실 응답 처리

현재 작업의 구현 범위는 공급자 결과가 이미 기록된 문자의 수동 재요청과 응답 손실 처리다. 실제 외부 공급자 호출은 Mock 응답으로 검증했다.

- 공급자 영수증을 발송 회차별로 보관한다. 재요청 결과에는 회차가 필요하며, 새로 도착한 과거·미래 회차 결과는 거부한다. 이미 기록한 이전 결과의 재전송은 현재 발송과 정산을 바꾸지 않는다.
- 네트워크 오류·잘못된 응답·서버 오류는 접수 여부가 불확실하므로 자동 재발송하지 않는다. 예약금은 유지하고 늦은 서명 결과로 정산한다.
- 영수증 변경·삭제와 다른 회사의 발송 참조는 DB에서 거부한다. 기존 마이그레이션 파일은 변경하지 않았다.

검증 근거:

- [변경 전 재현](red.log): 신규 4실패, 기존 관련 1통과, 12skip. [수정 후 집중 시험](green.log): 2파일 20개 통과.
- [최종 영향 범위 회귀](regression-final.log): 단일 worker·파일 순차 실행에서 **8파일 158개 모두 통과**, 종료 코드 0.
- [타입 검사](typecheck.log), [변경 파일 린트](lint.log), [계약 검사](contracts.log), [최종 빌드](build.log): 종료 코드 0. 빈 타입·린트 로그는 진단 없음이다.
- [신규 설치·집중 업그레이드](migration-report.json): 102개 마이그레이션 설치 및 체크섬 일치. 과거 형식의 관련 3개 테이블에서 영수증 3건의 기존 필드 보존, 회차 추론, 미래 작업 제외, 새 회차 입력, 불변·회사 참조 제약을 확인했다. 전체 기존 DB 업그레이드 리허설을 뜻하지 않는다.
- [실제 전용 Mock DB 업그레이드](mock-migration.json): 101→102, 이력 테이블과 새 attempt 필드를 제외한 128테이블 1,502행의 기존 필드 해시가 같았다.
- [Ego 56 최신 빌드 기본 검사](browser-smoke.json): 도움말 화면과 상태 API200, 가로 넘침·오류 알림 없음. 기존 3100 개발 서버는 유지했다.

첫 빌드와 회귀는 저장 공간 부족으로 실패했다([빌드](build-enospc.log), [회귀](regression-enospc.log)). 사용하지 않는 생성 빌드만 정리한 뒤 다시 실행했다. 이어진 회귀도 DB 초기화 경합·시간 초과에 따른 실패가 발생하여 [실패 기록](regression-contention.log)을 보존하고, 빌드가 끝난 뒤 단일 시험 worker로 다시 검증했다. 시험DB 초기화 시도는 Prisma 보호가 거부하여 실행되지 않았고, 이를 우회하지 않았다. 임시 SQL 편집을 원상 복원하고 새 격리 스키마에서 설치·업그레이드 검증을 완료했다.

[비밀값 노출 검사](secret-scan.json)는 설정·Mock 인증 자료의 실제 값과 이번 파일 내용을 비교했다. 공개 기록에 비밀값을 담지 않았다.

전체 1,748개 회귀는 이전 소스 기준이다. 이번 수정까지 전체 시험 또는 최신102개 복구를 완료했다고 표시하지 않는다. 실제 외부 수용과 원본 화면 대조도 미완료다. 사용자 요청에 따라 이 현재 작업을 커밋·푸시한 뒤 목표를 일시정지한다.
