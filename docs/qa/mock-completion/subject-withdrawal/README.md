# 동의 철회 확인·결과 화면

2026-10-06, 기존 동적 fixture를 유지하고 전용 폼·정보주체·응답을 별도로 만들었다. Ego56/p1에서 조회 요청 → 실제 로컬 메일 파일 → 같은 브라우저 인증 → 철회 화면을 검증했다.

- 확인 `/infoOwner/form-interrupt`, 결과 `/infoOwner/formComplete` 2경로·1440/768/390 6크기·새로고침 통과.
- 철회 요청→취소→기존 동의 유지, 재요청→확정→완료 영속화, 완료된 확인 주소 재방문→확정 버튼 없음, 동의 이력→철회 완료·재요청 버튼 없음의 4흐름 통과.
- 최종 실제 HTTP 조회200·철회 상태completed. 가로 넘침·화면 오류·alert·실패 리소스0.
- 타입·준비/브라우저 도구 린트 통과. 준비 도구의 첫 인증403은 로컬 BETTER_AUTH_URL 설정 누락이었다. 주소 일치 guard를 추가했고 실제 상태 전이가 성공한 뒤 기록했다.

`prepare-mock-subject-workflow.ts`는 loopback 전용DB·로컬 메일·전용 저장소만 허용한다. 비밀값·메일 링크·세션은 ignored `.local/mock-subject-workflow.json`에0600으로 저장하며, 공개 보고서에는 요청 해시만 기록한다. 준비 뒤 Ego에서 조회 요청을 하고 `link` 모드로 해당 메일만 전달한 다음 인증 링크를 연다. 브라우저 스크립트는 정상 인증된 전용 이력 화면에서 시작한다.

이번 흐름은 애플리케이션 내부 동의 철회 수용이다. 실외부 SMTP 전달·원본 화면 일치·전체72개 게이트 완료를 의미하지 않는다. 재방문171/181·미재방문10이며 fullAcceptance는 그대로false다. 앱 소스는 기존 시험 중 변경하지 않았고, 새로운 정산 빌드에도 동의 철회 소스 변경은 없다.
