# 청구서 상세·환불 화면 검증

2026-10-06. 실제 결제 주문이 있어도 준비 안내만 보이던 청구서 경로를 구현했다. `/bill/:id`, `/creditBill/:id`, `/bill/:id/refund`에서 기존 주문·구독·환불 API를 사용한다. 결제 내역과 결제 결과에 상세 링크를 연결했다.

- 조회 권한 없는 사용자는 데이터 요청 전에 거절한다. 쓰기 권한이 없으면 환불 입력을 숨긴다. 서버의 현재 권한 검증도 유지한다.
- 완료 환불과 처리 대기 요청을 구분하고 대기 금액을 추가 요청 가능 금액에서 제외한다. 요청별 중복 방지 키는 실패 시 유지한다.
- 신규 화면 시험9개, 타입·변경 파일 린트·production 빌드 통과. 전체112파일1695개 회귀는 이번 화면 변경 전 기준이며 합산 전체 통과로 표현하지 않는다.
- 같은 Ego56/p1에서3경로×1440/768/390px, 새로고침·뒤로가기 통과. 오류/가로 넘침 없음([보고서](report.json)).
- 실제 PDF 다운로드38,529바이트 및 PDF 헤더·해시 확인([다운로드](download.json)). 원문 파일·캡처는 비공개 로컬 폴더에 보관한다.
- 필수2항목 누락과12,001원 초과 입력 차단. Mock1,000원 환불 요청1건 저장, 처리 대기 표시와11,000원 잔여금액이 새로고침 후 유지됨([환불](refund.json)). 실제 공급자 환불 정산 증명이 아니다.
- 연속 클릭 도구는 첫 저장 뒤 화면 갱신으로 버튼이 분리돼 오류를 반환했다. 변경을 재시도하지 않고 조회로1건을 확인했다. 두 네트워크 요청이 전송된 시험으로 주장하지 않는다.
- 잘못된 ID, 존재하지 않는 주문, 비로그인 접근 차단 후 Mock 소유자 로그인 복원([거부 사례](denials.json)).

재현 가능한 화면 점검기는 `scripts/qa-ego-invoices.mjs`다. 기존 비공개 Mock fixture와 같은 DB·저장소·서버를 필요로 한다. 원본 화면 대조 및 모든 역할의 브라우저 수용을 뜻하지 않는다.
