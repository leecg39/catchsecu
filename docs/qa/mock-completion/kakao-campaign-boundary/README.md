# 알림톡 캠페인 승인·보유 기한 경계 수용

2026-10-06. 예약·실제 Mock 캠페인 발송에서 승인 검증 후 채널/템플릿 변경이 끼어드는 경계를 수정했다. 보관된 채널·템플릿의 반복 삭제와 재활성화 요청도 거절한다.

## 재현과 수정

- [수정 전 경쟁·보관 시험](red-race-and-archive.log):4개 실패. 잔고 행을 별도 연결에서 잠그고 작업자가 해당 잠금에 도달한 것을 DB에서 관찰한 뒤 채널/템플릿 변경이 먼저 저장되는 것을 재현했다. 예약은 감사 INSERT 앞에 임시 DB 장벽을 두었다. 반복 채널 삭제는 실제200이었다.
- 채널→템플릿 순서로 공유 잠금을 잡고 다시 읽는다. 선택/미리보기/예약/실제 발송에서 같은 범위 검증을 사용하며 작업의 커밋까지 잠금을 유지한다. 먼저 저장된 승인 변경은 다음 발송을 취소하고 영수증 파일을 만들지 않는다.
- [수정 전 만료 시험](red-expired-delivery.log):잔고 잠금 대기 중 합성 원천의 보유 기한을 지나게 했을 때 실제 결과가 local_delivered였다. Date만 약21초 전진시켰고60초 작업 임대 안에 있었다. 실제 외부 전송이 아니라 합성 로컬 영수증과 원장을 검사한다.
- 잔고 예약 후 발송 직전에 현재 상태·원천 보유 기한·작업 임대 기한을 다시 읽는다. 원천 만료는 SOURCE_UNAVAILABLE로 취소, 홀드 반환, capture0, 파일 부재와 잔액 보존을 검증했다.
- 보관 상태의 반복 DELETE와 PATCH는409다. 버전과 감사 수가 변하지 않는다. 화면에서도 수정·삭제 동작을 숨긴다.

## 이어갈 작업

문자 발송의 잔고 대기 및 이메일 첨부 읽기 동안 기한이 흐르는 경계를 별도로 재현·검토한다. 역할별 UI·아직 재방문하지 않은 인증/공개53경로·원본 대조 제한128항목도 남았다. 재방문128/181은 전체 수용 완료를 뜻하지 않는다. 외부 공급자 증명은 사용자 지시대로 Mock으로 대체하지만 실제 공급자 수용이라고 표시하지 않는다. 원래 TASKS17/72와55개 미체크는 좁은 시험 결과로 닫지 않는다.
