# P06-T06 본인인증·전자서명 실행 계획

2026-10-04. 이전 P06-T05는 백엔드·HTTP·격리 처리기 검증을 보완했다. 현재 P06-T06에는 모델/공급자 어댑터/검증 영수증이 없고 verify 폼의 게시·접수는 503으로 차단된다. 공급자 이름은 사용자에게 질문했으며 아직 확인되지 않았다. 이 작업의 완료 조건과 전체 72개 작업·181개 경로 범위를 유지한다.

## 1. 서비스별 연동 설정과 공통 모델

- 서비스별 VerificationIntegration을 만든다. 공급자 이름·sandbox/production 구분·pending/disabled 상태·version·불변 설정 이력과 현재 준비 상태를 관리한다. 고객 입력으로 ready/인증 성공을 설정할 수 없다. 비밀 자격증명과 공급자 URL을 브라우저에서 받지 않는다.
- VerificationAttempt는 회사/서비스/폼/게시 버전·브라우저 nonce·요청 HMAC·서명 대상 문서 해시·공급자 요청 참조·현재 상태·기한을 고정한다. 환경/설정 세대가 바뀐 이전 요청을 재사용하지 않는다.
- VerificationEvent는 공급자 event ID·원문 해시·검증 결과를 기록하고 중복/변조 이벤트가 새로운 증거를 만들지 못하게 한다.
- VerificationReceipt는 성공한 요청의 공급자·환경·문서/검증 증거 해시·검증/서명 시각과 Submission 연결을 저장한다. 회사/서비스/게시 버전이 다른 자료를 복합 FK로 연결할 수 없다. sandbox 결과는 운영 접수 영수증으로 사용할 수 없다.
- 같은 회사의 서비스별 설정 CRUD와 안전한 현재 준비 상태를 실제 폼 편집기에 연결한다. 구성원/서비스 grant·현재 세션·보안 정책·version·보관/회수와 잠금 후 실제 기한을 검사한다.

## 2. 공급자 어댑터

- 공급자가 확인되면 해당 공급자의 공식 문서와 테스트 자격증명·계정·허용 callback 주소를 대조해 요청 생성/결과 조회/서명 검증/취소 어댑터를 구현한다. 원본 Catchsecu가 어떤 공급자를 썼는지는 확인되지 않았다.
- 참고 조사: [PortOne V2 본인인증 조회](https://developers.portone.io/api/rest-v2/identityVerification), [DocuSign Connect 서명 검증](https://www.docusign.com/blog/developers/manually-authenticating-hmac-signatures-docusign-connect-webhook-configurations). 이는 실제 공급자 선정·원본 공급자 확인·sandbox 통과 증거가 아니다.
- 인증 결과는 서버의 공급자 조회/서명 검증으로 확인한다. 브라우저의 result/success/이름/인증 완료 주장을 근거로 승인하지 않는다. 공급자 payload/오류/자격증명을 일반 로그에 남기지 않는다.
- 전자서명은 서버가 생성한 정확한 동의 문서/답변 snapshot을 대상으로 요청한다. 공급자 envelope와 수신자·환경·문서 해시를 고정하고 완료 시 실제 공급자 상태와 증거를 재확인한다.

## 3. challenge·callback·접수 연결

- 공개 활성 게시본과 브라우저를 고정한 일회 요청을 생성하고 필수 동의/첨부·문서 선택·답변 HMAC을 묶는다. 만료·폼 종료·설정 변경·브라우저 불일치·위조/반복 callback을 거부한다.
- callback 수신은 raw body와 공급자 서명/nonce/event ID를 확인한다. 이벤트 잠금과 현재 공개 상태 검사 뒤 영수증을 저장한다. 같은 요청의 중복 효과·과금·동의 접수가 발생하지 않게 한다.
- 접수와 검증 영수증 소비는 같은 transaction에서 처리한다. 다른 payload/게시 버전의 영수증은 사용할 수 없고 한 영수증으로 두 접수를 만들 수 없다. 접수 응답 유실 후 동일 키 재시도는 기존 접수만 반환한다.
- 기존 비인증 폼과 파일/CSV·동의 영수증의 동작을 유지한다. 인증/서명 모델의 암호화 원문과 임시 문서는 만료/파기·보존 정책에 맞춰 지우고 최소 검증 사실만 보관한다.

## 4. 화면·관리

- 폼 편집기의 기존 본인인증/전자서명 설정에서 서비스별 공급자/환경·대기 사유·설정 CRUD를 표시한다. 설정 미완료는 정확한 대기 상태로 표시하며 법적 효력이나 외부 성공을 추정하지 않는다.
- 공개 폼은 정확한 답변/동의로 인증·서명을 시작하고 기한·진행·실패·취소를 표시한다. /identification/:result는 저장된 요청과 브라우저에 해당하는 현재 상태만 조회한다. URL 문자열만으로 성공을 표시하지 않는다.
- 관리자 응답은 검증 영수증의 안전한 상태/해시/시각을 표시한다. 현재 권한·보유 기간을 지키고 인증 개인정보/공급자 비밀/임시 URL은 제외한다.

## 5. 검증·완료 판정

- 실제 PostgreSQL에서 회사/서비스/FK·권한·설정 CRUD·설정 세대 변경·공급자 미설정 대기를 검증한다.
- 공급자 protocol 시험은 sandbox의 성공과 분리한다. 서명 위조·본문 변조·event 중복·callback 순서 변경·만료/회수 중 대기·영수증 재사용·접수 실패 롤백을 검사한다.
- 관련/전체 회귀·타입·변경 범위 린트·production 빌드·독립 합성 계정 HTTP·재시작·원본 해시/migration 대조를 수행한다. 실제 provider sandbox와 현재 Ego 화면 검증 전에는 P06-T06 완료로 표시하지 않는다.
- Ego TaskSpace 34 재개 승인은 대기 중이며 브라우저를 호출/우회하지 않는다. 사용자 관리자와 기존 업무 자료를 바꾸지 않고 production 전역 발송/파기 처리기를 실행하지 않는다. 명시적 supplier 검증 증거가 없으면 인증 폼 게시·접수 차단을 유지한다.
