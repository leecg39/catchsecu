# P05-T02 동의서·처리방침 CRUD·게시 — 진행 중

이후 [P04-T02](../P04-T02/README.md)에서 단계별 편집기·초안 재시도 API와 계약 표를 보완했다. 이 보고서의 소스 해시·계약 수치는 해당 문서 검증 당시의 기록이다.

2026-10-03. 문서·문구의 현재 권한 검사와 만료 후 재게시를 보완하고, 동의 당시 문서·표시 문구·영수증 PDF를 실제 DB와 API로 대조했다. 선행 P05-T01과 수정 후 브라우저 게이트가 남아 공식 완료는 15/72다.

## 이번 변경

- `documentScope`를 공통 `currentServiceScope`에 연결했다. 공통 함수가 회사·구성원·grant·사용자·세션을 잠그고 현재 역할, 이메일 인증, 세션 만료, 전문가 배정/서비스 범위를 검사한다. 공통 함수에서 문서 모듈을 참조하던 의존성도 제거했다.
- 문서·문구 CRUD, 미리보기·게시·회수·이력·PDF·서비스 동의 표시·폼의 문서 선택이 회수된 Context를 사용할 수 없다. 생성 요청 재전송도 같은 검사를 수행한다. 공유 권한이 있는 사용자에게도 만료된 링크의 URL을 반환하지 않는다.
- `hasActivePublication`은 **최신 게시 버전**에 활성·미만료 링크가 있는지 나타낸다. 최신 링크가 종료되면 동일한 현재 내용으로 새 번호의 불변 게시본과 링크를 만들 수 있다. 이전 버전의 다른 유효 링크는 이 판정을 막지 않는다.
- 화면의 게시 버튼과 종료 안내에 이 상태를 연결했다. OpenAPI에 문서 목록·상세·변경·게시의 실제 응답 스키마를 추가했다. 본문은 일반 텍스트로 렌더링하여 HTML·스크립트가 실행되지 않게 한다.
- 게시 버전·폼의 문서 바인딩·당시 표시 문구·암호화한 동의 영수증·저장된 PDF의 불변 계약을 유지했다. 새 migration은 없으며 기존 56개를 사용한다.

CRUD 시험은 합성 소유자의 QA 서비스에서 세 종류의 문서 3개·게시본 5개·문구 v4·감사 19개를 독립 DB 연결과 대조했다. 필수 문서 동의 누락, 사용 중인 처리방침 회수, 오래된 version, 같은 게시 내용의 중복 요청을 거부했다. 최초 문구를 복사한 뒤 원본 문구만 수정하고, 동의서를 개정·회수·비공개·보관·복원·재게시했다. 서비스 표시와 처리방침을 변경해도 이미 게시한 폼의 본문·문서 해시·당시 표시가 유지됐고, 동의 영수증 PDF와 이전 문서 PDF의 SHA-256이 일치했다.

만료 시험은 별도 합성 처리방침을 사용한다. 이전 버전은 기한 없이 열어 두고 최신 버전을 61초 뒤 만료시킨다. 실제 시간이 지난 뒤 최신 URL 410, 이력의 URL 제거, 선택 목록 제외와 `hasActivePublication=false`를 확인한다. 동일 최신 내용으로 재게시하면 새 링크가 열리고 만료된 링크는 계속 닫힌다. 기존 유효 버전도 계속 열리는지 대조한다. Date 시각을 변경한 통합 시험과 production의 실제 경과 시간은 구분하여 기록했다. 최종 API 합계는 89개(51+18+20)다. HTTP 로그의 재게시 사례 이름에 남은 “모든 링크”는 최신 게시본의 링크를 뜻하며, 앞선 사례에서 이전 버전의 유효 링크를 확인했다. 재실행용 스크립트의 사례 이름만 정확히 수정하고 실행 원본은 보존했다.

검증 스크립트는 [qa-document-gate.ts](../../../scripts/qa-document-gate.ts)다. Node.js 24와 `.env.local`에서 `prepare` → `expiry` → 실제 서버 재시작 → `finish`를 실행한다. 개발 DB·localhost·합성 계정을 검사하며 시험 세션은 모두 로그아웃한다. 사용자 관리자 계정/세션과 원본 사이트에는 변경을 가하지 않았다.

## 실패를 재현하고 수정한 과정

- [권한 수정 전](gate-before.txt): 최초 10개 중 9개 실패, 1개 통과. 이전 세션·전문가 배정과 재전송 검사가 누락되고 만료 URL이 남았다. [첫 보완](gate-after.txt)은 신규 10개와 관련 총 63개를 통과했다.
- [모든 링크가 만료된 경우](expiry-before.txt)와 [실제 HTTP](http-expiry-before.txt)에서 동일 내용의 재게시가 409로 막혔다. 서버와 화면을 보완한 뒤 [관련 64개](expiry-all-closed-after.txt), [실제 61초 만료](http-expiry-all-closed.json)를 통과했다.
- [이전 링크가 유효한 경우](latest-expiry-before.txt)를 분리 실행해 최신 버전만 만료되어도 재게시가 막히는 것을 확인했다. 최신 게시본 기준으로 판정을 바꾼 뒤 65개가 통과했다.
- `full-before-expiry.*`의 525개 통과는 추가 만료 보완 전의 기록이다. `full-concurrent-fixture.*`의 526개 통과와 `latest-expiry-concurrent-fixture.txt`는 같은 시험 DB를 동시에 사용해 최종 근거에서 제외했다. 두 실행이 끝난 것을 확인하고 개별 실패 재현 → 보완 회귀 → 최종 전체 회귀를 순서대로 다시 실행했다.
- 생성·수정·게시·보관·복원과 실제 PDF 비교는 성공했으며 현재 전체 회귀의 최종 결과만 완료 근거에 사용한다.
