# 감사로그의 실제 업무 참조 연결

2026-10-10. 기존 로그에서 비어 있던 폼 이름과 응답 식별자를 서버의 실제 관계로 연결했다.

- 폼·응답·첨부·내보내기 사건에서 현재 회사와 서비스가 모두 일치하는 폼을 조회한다. 현재 이름이며 과거 시점의 제목 스냅샷은 아니다.
- 회사 전체 감사 권한에만 폼 이름·내부 응답 ID를 제공한다. 제한 역할·회사와 서비스가 다른 참조·없는 객체는 null이다. 기존 원문·토큰·임의 detail 비노출 정책을 유지했다.
- 회사/폼 CSV는 화면과 같은 필드를 사용하며 수식 방어를 적용한다. 본인 전용 활동은 기존 최소 필드를 유지한다.
- 일반 로그에도 사건 상세를 연결했고, 조회 실패를 건수0으로 표시하지 않도록 고쳤다. IP·외부 고객번호·사유 원문은 수집·노출을 추정하지 않았다.
- Prisma 스키마 변경 없이 현재 관계를 이용했다. OpenAPI 3개 조회 응답의 DTO도 명시했다.

검증: `tests-final.json`의 PostgreSQL/화면 48개 통과. 회사 격리·서비스 범위·최신 권한·폼/응답/첨부/내보내기 참조·없는 ID·수식 방어·제한 역할 CSV·403 표시를 포함한다.

Ego production UI에서 `submission.corrected`로 검색한 3건과 상세를 확인하고 CSV를 내려받았다. `browser.json`, `browser-audit.png`, `browser-audit.csv`가 증거다. [독립 DB 대조](../../R11-T04/browser-flow/db-after-conflict.json)에서 사건 ID·폼 이름·응답 ID가 일치했다.

390/768/1440폭에서 페이지 가로 넘침 없이 테이블 내부 스크롤을 확인했다(`responsive.json`). Viewer는 `/access-not-allow?reason=role`로 이동해 폼 이름을 받지 못했다(`viewer-denied.json`). 실제 이 경로는 앱 역할 gate에서 먼저 차단되며, 컴포넌트 내부 403의 건수 표시는 별도 화면시험으로 검증했다.

전체 R22의 모든 종류/검토요청/보존집행까지 완료했다는 의미는 아니다. 원본 미관찰 IP 정책이나 비공개 DB를 복원했다고 주장하지 않는다.
