# P04-T03 승인·게시·고정 URL 검증 계획

2026-10-03. 기존 승인/게시/고정 URL 모델과 화면을 점검한다. 선행 P04-T02/P11-T01의 전체 완료 게이트는 별도로 유지한다.

## 코드에서 확인한 점검 대상

- 게시·승인 요청·고정 URL 생성의 멱등 캐시 재전송에는 현재 서비스 권한을 다시 검사하는 함수가 연결되어 있지 않다. 실제 권한 회수 뒤 재전송 시험으로 결과를 확인한다.
- 승인 이력과 고정 URL 조회는 요청 초기에 읽은 Context의 권한을 사용한다. 세션/이메일 인증/전문가 배정이 바뀐 경우를 실제 PostgreSQL에서 시험한다.
- 고정 URL 변경은 현재 연결과 새 폼을 transaction 밖에서 조회한다. 변경과 서비스 권한 회수·폼 게시 상태 변경을 잠금 안에서 검사하도록 정리한다.
- 고정 URL의 version-only PATCH와 범위를 벗어난 페이지, 중단·재개·만료·한도·새 게시본 연결은 실제 동작을 확인한다.

## 작업

1. 권한 회수 후 재전송, 오래된 Context 읽기/쓰기, 전문가 배정 범위, 세션 종료의 실패를 먼저 재현한다. 비밀 토큰·검토 메시지를 로그에 출력하지 않는다.
2. 승인 조회와 고정 URL CRUD를 공통 현재 서비스 범위 검사에 연결한다. 권한·세션과 서비스/폼/고정 URL 잠금을 같은 transaction에서 유지한다. 기존 불변 검토본/응답과 version 충돌 계약을 보존한다.
3. 멱등 재전송에도 현재 권한을 검사하고 고정 URL의 입력/검색/페이지 계약을 문서화한다. 실제 서버 페이지를 화면의 페이지 상태에 반영한다.
4. Production API에서 게시 → 고정 URL 생성 → 새 게시본 자동 연결 → 다른 폼 연결 → 중단/재개 → 종료를 수행한다. 구버전 응답과 게시/승인 기록, 같은 키 재전송의 추가 쓰기 없음, 재시작 후 DB를 대조한다.
5. 실제 만료·동시 마지막 응답 한도·권한/회사 경계와 기존 승인 시험을 실행한다. 타입·린트·빌드·전체 회귀와 계약 표를 갱신한다.

## 완료 게이트

정상 원본 승인/고정 URL 화면 대조와 기존 Ego 창의 수정 후 desktop/390px 조작, 선행 Task 전체 게이트가 남는다. 이들까지 증거가 갖춰질 때만 정식 완료로 집계한다.
