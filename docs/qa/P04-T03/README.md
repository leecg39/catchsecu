## 구현

- 게시·승인 요청·고정 URL 생성의 같은 키 재전송도 현재 계정/세션/전문가/서비스 권한과 서비스·폼 활성 상태를 검사한다. 게시 권한이나 작성 권한 회수 뒤 과거 캐시의 공유 토큰·검토 메시지·고정 URL 결과를 반환하지 않는다.
- 승인 상세·목록·폼 이력과 고정 URL 조회는 transaction 안에서 현재 범위를 확인한다. 승인 화면의 요청/검토/취소 가능 여부도 현재 구성원·grant·회사 정책으로 계산한다. 세션 종료·이메일 인증 회수·전문가 만료와 배정 외 서비스는 이전 Context로 접근하지 못한다.
- 고정 URL 생성은 현재 게시본을 잠금 안에서 검사한다. 변경/종료는 Form을 먼저 잠그고 FixedUrl을 잠근다. 다른 서비스의 폼으로 연결할 때는 현재 원래 서비스와 대상 서비스의 게시 권한이 모두 필요하다. 재게시의 자동 연결과 고정 URL 편집이 경합해도 최신 게시본 연결과 version 충돌을 유지한다.
- version만 있는 고정 URL PATCH는 422로 거부한다. 목록의 이름·상태·서비스·정렬·페이지는 서버에서 처리하고 승인/고정 URL의 범위 밖 페이지를 마지막 페이지로 보정한다. 화면은 서버가 반환한 페이지를 표시한다.
- 기존 불변 검토본·게시 버전·암호화 응답, 승인 전 게시 차단·반려/재요청·중단/재개·공개 만료·응답 한도는 유지한다. 모델 변경과 새 migration은 없다.

## 검증

전체 41개 파일·565개가 통과했고 실패/대기는 0이다. 신규 PostgreSQL 시험 17개와 최종 전체 결과에서 추출한 관련 4개 파일·50개를 포함한다. 타입·린트 오류 0·production 빌드·계약/작업표 검사를 통과했다. 전체 회귀는 하나의 시험 DB에서 파일을 순서대로 실행했다.

Production API 91개(준비 78개·최종 재시작 후 13개)를 실제 서버와 PostgreSQL에서 확인했다. 합성 소유자로 독립 시험 회사를 만들고 승인 전 차단·증빙·반려·재요청·승인·동일 키 재전송, 새 게시본 연결·다른 폼 연결·동시 편집, 중단/재개·실제 시각 경과 후 만료·동시 마지막 응답 한도를 확인했다. 회사 간 상세 404와 미인증 관리 401도 검사했다.
