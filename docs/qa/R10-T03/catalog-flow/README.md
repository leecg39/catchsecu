# 수집 목적·제공/수탁자 CRUD 보완

2026-10-10. 자체 production 서버와 Ego 공간 3에서 합성 회사·서비스를 사용했다.

- 미저장 입력이 닫기에서 사라지는 문제와 409 후 오래된 버전 재제출을 재현했다. 편집기 이탈 보호, 충돌 입력 보존, 최신 자료 재조회와 저장 잠금을 구현했다. 보관/복원 오류도 목록을 새로 조회해야 재시도할 수 있다.
- 실제 화면: 수탁자 생성 → 수정 충돌 → 재조회/수정 → 수집 목적 생성/연결/수정 → 연결된 수탁자 보관 거부 → 목적 보관 → 수탁자 보관 → 수탁자/목적 복원 → 이력/새로고침 확인.
- purpose v4·recipient v6, 개정본 4/6개, 감사 10건. 독립 DB에서 화면 값·관계·과거 30일/수탁자 v4 스냅샷을 대조했다. 거부된 쓰기는 개정본이나 성공 감사를 만들지 않았다.
- 실제 HTTP 26개: owner 조회/이력, 비로그인·서비스 권한 없는 viewer·다른 회사 접근/쓰기 거부, 오래된 수정/삭제 409, tenant 필드 주입 422, 이름 중복 409.
- PostgreSQL 업무시험 15개와 fixture 계약시험 5개 통과. 전체 타입·변경 린트·production 빌드 통과. 390/768/1440px 편집기를 확인했다.
- 서버 재시작 후 두 자료·연결·모든 개정본·감사 전체 지문이 동일하다. db-after-restart.json 참조.

실제 UI 결과는 browser.json, 충돌 전후는 conflict-before/after.json, 응답은 http.json, DB는 db.json과 db-after-restart.json, 화면은 editor-390.png와 responsive.json에 보존했다.

수집 근거 부분의 수용 증거다. R10 전체의 문서 유형·게시·공개 경로·문구·PDF·서비스 연결 수용은 별도로 진행한다. 원본 정상 상태의 디자인/행동 일치 완료를 뜻하지 않는다.
