# 문구 CRUD와 처리방침 적용 검증

2026-10-10. 로컬 전용 회사·계정과 Ego Lite 공간3의 실제 production UI에서 검증했다. 문서 전체 유형의 최종 수용 완료를 의미하지 않는다.

- 기존 문구 추가 모달을 닫으면 미저장 입력이 사라지는 문제를 [재현](unsaved-before.json)했다. 모달 닫기·페이지 이동 보호와 입력 취소 확인을 추가했다.
- 문구를 생성하고, 다른 요청으로 개정을 변경한 상태에서 UI 저장을 시도했다. 409 이후 입력이 유지되고 저장이 잠기며, 최신 자료 불러오기 취소/확인 후 정상 저장되는 것을 확인했다. [생성](created.json), [충돌 복구](conflict.json).
- UI 보관→보관 문구 읽기 전용→복원→재편집을 확인했다. 현재 문구는 개정6이다. [최종 문구](final.json).
- 별도 처리방침 초안을 만들고 저장된 문구를 UI에서 적용해 게시했다. 이후 원본 문구를 수정해도 문서 초안과 게시본 본문이 유지된다. [첫 게시](policy-published.json), [최종 게시](policy-final.json).
- 서비스 표시 설정에 연결된 게시본의 회수는 거부된다. 연결 해제 후 회수·재게시를 확인했으며 이전 링크는410이다. 문서 개정5, 초안 개정2, 게시본2개이고 게시본 해시는 동일하다.
- [관련 서버 회귀34개](tests.json)가 통과했다. 추가 HTTP29개·독립 DB 감사18건·서버 재시작 검증은 [표시 설정 검증](../../R10-T04/display-flow/README.md)에 함께 기록했다.
- [390/768/1440px 검사](responsive.json), [390px 모달](editor-390.png)을 실제 확인했다. 새 production 빌드와 변경 파일 lint/type 검사가 통과했다.

기존 동의서 게시 검증 자료(`document-flow`)와 별도 문서를 사용했다. 원본 사이트 자료는 변경하지 않았다.
