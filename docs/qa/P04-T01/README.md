# P04-T01 폼·버전·질문·템플릿 CRUD — 진행 중

2026-10-03. P03-T01 완료 후 기존 폼 CRUD를 재점검하고 조건부 질문·행렬형 단일/복수 선택·선택 수 제한을 구현했다. 원본의 페이지 분기 방식·공용 템플릿 실제 내용과 전체 브라우저 게이트가 남아 정식 완료로 집계하지 않는다.

## 폼·템플릿 CRUD 보완

- 폼 복제는 Form·Version·Question·Option뿐 아니라 공개 계약의 질문 ID도 새로 생성한다. 마케팅 이름·이메일·전화 질문 참조도 새 ID로 변경한다. 최신 초안을 복제하고 원본 보관·편집과 독립적으로 유지한다. 최대 200자 제목의 기본 복사 이름도 상한을 지킨다.
- 폼 보관·공개 중지/재개·복제와 템플릿 등록/수정/삭제/사용은 transaction 안에서 현재 회사·구성원·서비스 권한, 이메일 인증·사용자 상태·살아 있는 세션·전문가 배정 상태/만료를 확인한다. 권한을 회수한 뒤 기존 Context를 재사용해도 거부한다. 재전송한 생성·복제·템플릿 요청도 서비스 권한을 재검사한다.
- 템플릿을 transaction 안에서 잠그고 최신 내용과 version을 확인한다. 보관 서비스의 변경·삭제, 공용 템플릿 변경, 내용 없는 version-only 저장을 거부한다.
- 즐겨찾기는 현재 서비스 조회 권한을 검사하고 구성원별로 저장한다. 검색·정렬·페이지 필터는 서버에서 처리한다. 공개 중지/재개는 현재 폼 상태·version·게시 링크 만료를 검사한다.
- 게시본 직접 변경을 막는 기존 PostgreSQL 불변 제약을 유지한다. 기존 응답·복제 폼은 원본 템플릿 삭제 후에도 남는다.

## 폼·템플릿 CRUD 검증 근거

- `gate-before.txt`: 새 시험 6개 중 5개 실패로 질문 ID 재사용, 권한 회수 뒤 폼 보관, 로그아웃 후 템플릿 수정, 보관 서비스 템플릿 삭제, 내용 없는 저장을 재현했다.
- `gate-after.txt`: 수정 후 신규 10개와 기존 폼·템플릿·승인 회귀를 포함한 3개 파일·68개 시험 통과.
- `typecheck.txt`, `lint.txt`, `http-typecheck.txt`, `http-lint.txt`: 타입·변경 파일·검증 스크립트 린트 오류 0.
- `../P03-T03/profile-job-title-migrations.txt`: 직책 필드 Migration 54의 빈 설치·53→54 업그레이드·실패 복구·seed·복합 FK 검증 통과.
- `full-test.txt`, `full-test.json`: Node.js 24.19.0에서 전체 PostgreSQL 회귀 34개 파일·488개 시험 통과. 소요 300.87초. 파일 수는 JSON의 describe 묶음 수와 구분했다.
- `build.txt`: 로컬 메일을 명시적으로 허용한 production 빌드 통과. 외부 SMTP 검증으로 집계하지 않는다.
- `http-prepare.json`: production HTTP 41개 확인 항목 통과. 회사 생성·6종 질문 저장·폼 독립 복제/재전송·원본 수정/보관·게시 중지/재개·필수/선택지/원본 ID 거부·실제 응답·즐겨찾기/검색/정렬·템플릿 생성/수정/복제/삭제를 확인했다. 프로필 직책 저장·길이 제한과 구현 화면 HTTP 200도 포함한다.
- `restart.json`, `http-finish.json`: PID 4811→5420의 실제 서버 재시작 후 HTTP 6개 확인 항목 통과. 독립 DB에서 직책 유지, 활성 회사·폼 3개·템플릿 0개·응답 1개·답변 6개·독립 질문 ID 18개를 대조했다. 삭제한 템플릿에서 복제한 폼과 보관 원본도 유지됐다.
- `plan-check.txt`: 181개 경로·72개 Task·누락 0·의존성 순환 0. `verification.json`: 검증한 소스 해시와 검증 범위를 기록했다.

HTTP는 이전 P03에서 인증한 합성 구성원 계정으로 새 시험 회사를 생성했다. 시험용 HTTP 세션은 검증 후 로그아웃했다. 사용자 관리자 계정과 기존 브라우저 세션은 변경하지 않았다. 시험 계정·쿠키·암호·공개 토큰은 출력하지 않고 `.local/`은 Git에서 제외한다.

## 조건부 질문·행렬·선택 수 제한

[질문 규칙 구현·검증](question-rules.md)에 별도 증거를 기록했다. 9개 질문 유형의 정의·게시본·암호화된 응답·정정·공유를 연결했다. 복제는 조건이 참조하는 질문과 행렬의 행 ID도 새로 발급한다. production HTTP 31개와 PID 28858→29754 재시작 후 독립 DB 대조가 통과했다.

조건부 질문은 독립 백엔드의 명시한 계약이다. 원본에 안내된 페이지 분기와 화면·동작이 같다는 검증은 아직 하지 못했다. 기존 `verification.json`과 `full-test.*`는 CRUD 보완 당시의 소스·시험 기록이며 이번 질문 규칙 증거는 `questions-*` 파일로 구분한다.

## 남은 작업

- 원본의 페이지 이동·분기 방식과 실제 질문 편집/응답 화면 대조. 조건부 질문·행렬·선택 수 제한의 서버 검증은 통과했으며 Ego 조작 검증은 남아 있다.
- 구조화한 행렬 답변의 즉시 CSV 내보내기·동일 필터·현재 권한/보유 상태·다운로드 감사는 [P06-T02 검증](../P06-T02/README.md)에 구현·검증했다. 원본 다운로드 흐름·브라우저 조작과 대량 비동기 내보내기는 후속 범위다.
- 공용 템플릿 25개의 실제 질문 구성은 미관찰 상태다. 현재 카드는 미리보기이고 내용을 추론해 운영 템플릿으로 등록하지 않았다.
- Ego의 기존 작업 창 제어 재개 응답 후 생성→편집→게시→복제→템플릿 등록/수정/삭제→즐겨찾기/필터→오류/권한/모바일 조작을 확인한다. HTTP 화면 200은 이 브라우저 증거를 대신하지 않는다.
