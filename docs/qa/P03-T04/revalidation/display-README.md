# P03-T04 동의서 표시 설정 후속 검증

2026-10-04. 동의 표시 기능의 부분 구현·검증이다. Task 전체 완료를 뜻하지 않는다.

## 변경 사항

동의 표시 조회/저장에 현재 회사·세션·회원·서비스 권한과 보안 정책 검사를 연결했다. 쓰기는 회사 잠금을 먼저 취해 공유 서비스 잠금의 동시 승격을 직렬화한다. 감사 기록 뒤 세션 등 유효기간과 연결한 처리방침 게시 만료를 다시 검사하며 실패하면 설정과 감사 모두 롤백한다. 조회의 공개 링크도 반환 직전에 유효성을 판단한다.

화면은 저장 중 중복 요청을 막고, version 충돌 시 편집·저장을 잠근 뒤 최신 설정을 불러오는 기능을 제공한다. 조회/처리방침 목록 실패 시 재시도할 수 있다. 네트워크 오류 안내를 한국어로 보완하고 입력 필드에 접근성 이름을 붙였다.

## 확인한 결과

- 새 PostgreSQL 경계 시험 8개 중 수정 전 6개가 실패했고 보완 후 모두 통과했다. 관련 documents/form-documents/subprocessor-notices를 포함한 4파일 52개 통과. 이전 회귀와 겹치므로 합산하지 않는다.
- 최종 v10 production 빌드와 TypeScript, 변경 3파일 ESLint, git diff --check 통과. 마지막 변경은 UI 네트워크 오류 문구이며 서버 52개 통과 이후 서버 코드는 바뀌지 않았다. Prisma schema/migration 변경 없음.
- 실제 Ego 공간45/p1에서 서비스 A 수집 탭의 5개 문구·회사명 표시·내부 처리방침, 제3자 제공 탭의 외부 HTTPS 링크·회사명, 서비스 B의 별도 문구 저장과 전환 복원을 확인했다. 처리방침 fixture는 실제 HTTP 생성/게시로 준비했으며 그 문서 생성 화면까지 시험한 것은 아니다.
- 다른 요청으로 A 수집 설정을 version1→2로 바꾼 후 기존 화면 저장409, 버튼 비활성화, 최신값 재조회 후 version3 저장을 확인했다. 잘못된 URL은 화면에서 거부됐고 타 서비스 문서·위험 URL·201자 문구는 production HTTP422로 거부됐다. 거부 후 version3 유지, 타 서비스 게시본은 선택 목록에서 제외됐다.
- 네트워크 offline에서 탭 전환 후 한국어 오류를 확인하고 online 복원→재시도→저장값 복원을 확인했다. 최종390px 화면의 clientWidth/scrollWidth는375px이며 페이지 가로 넘침은 없다. 탭 자체는 내부 가로스크롤을 사용한다. 최종 desktop/mobile 캡처를 시각 검사했다.
- production v9 PID36070에서 준비한 자료를 v10 PID45099/port3111에서 다시 조회했다. 독립 DB에서 설정3행(A수집v3/A제3자v1/B수집v1), 감사5건 및 전체 행·감사 해시 일치를 확인했다. SHA256: f4601d6dc5c09a47ce66ee821d99612ea036d52bd51adb841eda830e65dc2ddb.
- 이전 자체 QA3109/3110은 종료했고 사용자3100 PID30204는 유지했다. 실제 외부 메일/공급자 호출은 하지 않았다.

## 실패 기록과 한계

첫 baseline의 게시 기간60초 fixture는 최소 게시 기간 규칙에 걸렸다.90초로 수정한 display-authority-baseline.log가 실제6개 실패 근거다. display-authority-before.log도 보존했다. 최종 모바일 첫 검사는 scrollWidth가 innerWidth와 정확히 같아야 한다는 과도한 검사로375/390에서 실패했다. 스크롤바를 고려한 넘침 검사로 고쳤으며 제품 CSS는 변경하지 않았다. 이전 display-read-error.txt의 영어 오류는 후속 수정 전 자료이고 최종 근거는 display-read-error-final.txt다. node-pg deprecation 경고는 원래 로그에 보존했다.
