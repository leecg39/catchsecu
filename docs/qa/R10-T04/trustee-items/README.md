# 서비스 수집 항목과 재수탁자 저장·게시 검증

2026-10-10. R10 후속 부분 검증이다. 전체 문서 유형·역할·원본 동등성 수용 완료를 뜻하지 않는다.

## 구현과 출처

- 원본 `Eft`가 서비스 전체 항목을 조회하고 `zmt`가 재수탁자의 필수/선택 항목·처리 근거를 저장함을 확인했다. [원본 근거와 독립 설계 구분](../../R10-T01/source-field-audit/README.md).
- `GET /api/v1/documents/options?serviceId=...`의 `policyItems`는 현재 회사·허용된 서비스의 활성 수집 목적에서 필수/선택 항목을 가져온다. 이름의 NFKC·대소문자 중복을 각 구분 안에서 제거한다. 새로운 수탁자와 재수탁자에만 초기값을 복사한다.
- 기존 입력, 목록 재시도 중 작성 내용, 목적 선택 변경에 따른 입력은 보존한다. 직접 입력과 서비스 항목 선택을 모두 지원한다. 구분별100개 초과 초기 목록은 자르지 않고 수동 선택을 안내한다.
- 재수탁자의 requiredItems/optionalItems/legalBasis를 JSON 초안·공개 스냅샷·본문·PDF에 연결했다. 선택 속성으로 추가해 기존 JSON에 빈 필드를 주입하지 않는다. 새 직접 입력 행은 위탁 항목이 있어야 게시할 수 있다. 링크형 재수탁자의 숨겨진 항목은 공개에서 제거한다.
- 네트워크 실패가 영문 `Failed to fetch`로 보이던 문제를 API 클라이언트에서 한국어 재시도 안내로 수정했다. 요청 취소·HTTP 권한 거부·충돌의 기존 의미는 보존한다.

## 실제 실행

Ego Lite space3/p1, 로컬 전용 합성 계정·회사에서 수행했다. 준비 단계의 수집 목적2개는 [실제 API로 생성](prepared.json)했고 문서 작업은 UI로 실행했다. 원본 사이트에는 쓰지 않았다.

1. 목적 A만 선택했으나 A+B의 필수2개/선택2개가 신규 수탁자와 재수탁자에 채워짐을 확인했다. 중복 이메일은1개였다.
2. 부모의 선택 항목을 삭제한 뒤 서비스 목록에서 다시 추가했다. 재수탁자 항목은 직접 수정하고 목적 B를 켰다 꺼도 유지됨을 확인했다.
3. 옵션 GET만 브라우저에서 차단했다. 기존 입력은 보였고 새 수탁자 추가는 비활성화됐다. 입력을 바꾼 뒤 차단 해제·재시도로 목록과 추가 버튼이 복구됐으며 입력이 유지됐다.
4. 저장→게시 v1. 재수탁자를 UI에서 삭제→저장하고 초안에서 제거됐으며 기존 게시 v1은 유지됨을 확인했다.
5. 재수탁자를 다시 추가하고 필수 항목을 `재수탁 최종 항목`으로 수정, 선택 항목을 비워 저장→게시 v2.
6. 독립 Node/PostgreSQL 검증기로 초안 payload·공개 JSON·본문·PDF 텍스트·정규화 SHA-256·감사5건을 대조했다. [검증 전 상태](verified.json).
7. 별도 서버 프로세스로 재시작한 뒤 동일 검사·PDF 전체 바이트·DB 상태 지문이 같았다. [재시작 결과](verified-after-restart.json).
8. 390/768/1440px에서 새 입력부의 가로 넘침이 없고 저장한 값이 보임을 확인했다. 390px 이미지는 직접 열어 확인했다. [화면 증거](../../R10-T03/trustee-items/README.md).

## 자동 검증과 한계

- 문서/구조화 계약/실제 PostgreSQL 권한 경합 등4파일58개 통과. 네트워크 오류 계약3개도 통과. [시험 기록](../../R10-T02/trustee-items/README.md).
- production 빌드, 소스·시험·검증 스크립트 typecheck, 변경 파일 lint 통과. 로컬 메일·가상결제 설정이며 외부 제공사 수용은 포함하지 않는다.
- 새 DB migration은 없다. 재수탁자 추가 속성은 기존 DocumentPolicyDraft JSON과 불변 게시 스냅샷에서 지원한다.
- 원본 서비스 항목 API의 실제 중복 제거 정책·piReasonType enum과 독립 구현의 자유 텍스트·직접 입력은 구분한다. 전체 원본 필드·역할·다중 서비스 화면 동등성을 완료로 집계하지 않는다.

재검증: `node --env-file=.env.local --import tsx scripts/qa-rea-policy-items.ts --after-restart`. `--prepare`는 합성 시험 자료 준비 옵션이다. 일반 검증은 업무 데이터를 바꾸지 않으며 로그인 및 PDF 캐시 접근은 발생한다.
