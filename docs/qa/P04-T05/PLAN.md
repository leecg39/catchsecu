# P04-T05 폼 모듈 전체 검증 계획

선행 P04-T04와 P06-T02의 화면·원본·전체 수용 조건이 남아 있다. 아래 항목의 준비 및 개별 결함 수정은 이어서 진행하되, 선행이 완료되기 전 P04-T05를 완료로 집계하지 않는다.

## 검증 대상

1. 합성 계정의 별도 시험 회사·서비스에서 폼 생성 → 같은 ID의 단계별 초안 저장 → 서비스 템플릿 등록/사용 → 게시된 동의서 연결 → 승인 요청/반려/재요청/승인 → 게시 → 고정 주소와 응답 공유 → 초안 새 버전 → 재승인/재게시 → 일시 중지/재개/보관을 확인한다.
2. 단문·장문·객관식·체크박스·드롭다운·날짜·파일·행렬 단일/복수 선택의 실제 응답과 조건·선택 수를 확인한다. 파일은 실제 검사 엔진과 원본/다운로드 바이트를 비교한다. 질문·선택지·행·분기와 템플릿 복사의 ID는 독립 DB에서 비교한다.
3. 현재 역할·서비스 grant·전문가 배정·만료·정지·이메일 인증·세션·회사/서비스 상태를 변경한 다음, 이미 읽은 Context와 멱등 재요청에서도 권한을 다시 검사하는지 확인한다.
4. 동일 버전 저장·승인·게시·고정 URL 변경·응답 마감 경합을 검사한다. 게시/승인/동의 영수증과 기존 응답의 불변성, 감사의 단일 기록, 실패 transaction의 원자성을 확인한다.
5. production API와 서버 재시작 전후의 DB를 대조한다. 폼/버전/게시/승인/질문/고정 URL/동의/응답/파일/감사/요청 캐시의 연결과 해시를 함께 기록한다. 비밀번호·쿠키·공개/초대 토큰·개인정보 원문을 공개 증거에 저장하지 않는다.
6. Ego 기존 창의 제어가 명시적으로 재개되면 desktop·390px에서 같은 흐름을 실제 조작한다. 네트워크 결과 유실, 재시도, 재접속, 브라우저 저장소 초기화 이후 DB 복원과 localStorage에 도메인 데이터를 의존하지 않는 동작을 확인한다. 정상 원본과 화면 차이를 별도 기록한다.

## 먼저 점검할 코드

- `src/server/templates.ts`: 목록은 오래된 Context의 `serviceScope`를 사용한다. 상세·사용은 현재 scope를 검사하지만 보관 서비스에 대한 전문가의 읽기 범위를 폼과 일치시키는지 점검한다. 검색 후 페이지 범위 보정도 확인한다. 실제 실패를 재현한 뒤 수정한다.
- `src/components/forms/FormEditor.tsx`, `Workflow.tsx`, `TemplateGallery.tsx`: 목록의 현재 작업 권한과 편집/게시 흐름의 권한 안내를 비교한다. 생성·저장 멱등 응답의 권한을 캐시하지 않으면서 상세 GET으로 작업 권한을 복원하는지 확인한다.
- `src/lib/use-form-draft.ts`: 저장 결과를 알 수 없는 상태, 이동·재접속, 409, 다른 폼을 거친 재시도의 키와 초안 ID 유지 여부를 확인한다.

## 기록 및 완료 기준

실패 재현·수정 후 PostgreSQL·실제 API·production 빌드/타입/린트·전체 회귀·재시작·소스/증거 SHA-256를 저장한다. 기존 P04-T01~T04, P05-T02, P06-T02 기록은 검증 당시 증거로 유지한다. 정상 원본·실제 브라우저·외부 연동이나 선행이 빠진 항목은 통과로 기록하지 않는다.
