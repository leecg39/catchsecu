# P04-T05 단계별 권한과 production 전체 흐름

2026-10-03. 폼 모듈은 진행 중이며 공식 완료는 15/72다.

## 구현

- 폼 상세·목록 GET의 `actions.publish`는 현재 역할·서비스 게시 grant·활성 서비스·폼/초안 상태를 반영한다. 작성 grant와 독립이다. 승인·질문·문서·검사 공급자의 실제 조건은 게시 transaction에서 다시 확인한다. 생성·저장 캐시에 작업 권한을 넣지 않는다.
- 설정 화면의 작성·게시·공유·응답 버튼은 해당 폼 GET 권한을 사용한다. 주기적 조회·창 재활성화·저장/승인 변경 후 권한을 갱신하며 실패하면 변경 버튼을 차단한다. 권한 회수 후 수정한 값은 화면에 남겨 둔다.
- 작성 권한 없이 게시 권한만 있을 때 저장된 초안을 게시할 수 있다. 게시 직전에는 최신 GET의 권한과 version을 확인한다. 다른 버전은 409 안내, 불확실한 전송은 동일 키, 성공 응답 유실 후에는 현재 공유 상태를 조회해 한 번의 게시 결과로 이동한다. 중복 클릭은 같은 진행 요청을 사용한다.

## 실제 production API 103개

[준비 90개](http-prepare.json)와 [서버 재시작 후 13개](http-finish.json)가 통과했다. 스크립트는 localhost의 `catchsecu_dev`, local 메일 설정, 합성 계정 및 해당 시험 회사 이름/소속을 강제 확인한다. 사용자 관리자 계정을 변경하지 않는다.

수집 목적·문서 작성/게시→아홉 질문과 필수 문서 연결→같은 ID 초안 저장→템플릿 등록/멱등 사용·독립 질문/행/분기→템플릿 삭제→반려/재요청/승인→게시 성공 응답 유실/조회 복구→고정 URL→필수 파일 준비/원본 바이트/ClamAV 검사→숨은 답변·선택 수·문서 동의 실패 422→멱등 제출→소유자 다운로드→외부 공유 OTP/선택한 두 항목 및 첨부 열람→새 초안/재승인/재게시→기존 공유 버전 유지→중단/재개/보관→공개 410·열람 401→미참조 원본 초안 완전 삭제를 실행했다.

최종 독립 DB에는 대상 폼 1개·불변 게시 버전 2개·게시 링크 2개·승인 3개·제출 1개/암호화 답변 9개·동의 영수증·첨부·고정 주소·공유 권한이 연결되어 있다. 원본 폼과 템플릿은 삭제됐고 파생 폼은 보관 상태다. 최초 게시 버전과 응답 암호문 해시, 첨부 SHA-256, 공유 버전 연결, 문서 버전 해시를 대조했으며 서버 재시작 후 같은 업무 DB 해시를 확인했다. 영수증은 생성/개수까지 검사했으며 이 기록을 영수증 PDF 바이트의 전후 비교 근거로 사용하지 않는다.

게시 전용/작성 전용의 두 좁은 grant는 해당 합성 구성원 DB의 시험 준비로 설정하고 GET·저장/게시 거부는 실제 HTTP로 확인했다. 구성원 역할·정상 grant와 보안 정책은 API로 복원했다. OTP는 해당 합성 공유 초대/인증 큐 두 건의 수신자를 확인한 뒤 로컬에서 읽어 API로 검증했다. 외부 이메일 전달은 검증하지 않았고 전체 worker를 실행하지 않았다. 합성 계정과 외부 열람 세션을 종료했다.

첫 준비에서 문서 게시 응답의 버전 ID 위치를 잘못 사용했고, 다음 실행은 앞선 목적과 이름이 같아 정상 409로 종료됐다. 문서 버전 목록 GET과 실행별 이름을 사용하도록 시험 코드를 수정했다. 두 실패는 통합 흐름 성공으로 집계하지 않는다.
