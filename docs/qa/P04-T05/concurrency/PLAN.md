# P04-T05 통합 경합·영수증 바이트 검증

공식 완료는 15/72이며 본 검증으로 전체 수용 게이트를 대체하지 않는다.

1. `catchsecu_test`의 합성 회사·작성자/소유자와 게시 문서, 아홉 질문·행렬 행·선택 수·분기·필수 파일·필수 문서 동의를 구성한다. 실제 API handler·PostgreSQL·ClamAV를 사용한다.
2. 폼 행을 별도 PostgreSQL 연결로 잠근 뒤 두 요청을 시작한다. `pg_stat_activity`에서 두 요청의 잠금 대기를 확인하고 해제한다. 같은 version 저장 두 건, 승인 요청/저장, 승인 결정/저장, 승인 결정 두 건, 게시/저장을 검사한다. 결과 코드·version·승인 snapshot/hash·게시본·쓰기 감사·실패 transaction 보존을 확인한다.
3. 최초 게시본에 파일을 제출하고 실제 영수증 PDF와 암호화 증거·응답·게시 버전 해시를 기록한다. 새 게시/경합 뒤 기존 바이트와 연결이 유지되는지 대조한다.
4. 시험 DB에서 새 게시본 응답 제출과 기존 응답 파기·영수증/첨부 읽기를 겹친다. 파기 장벽 전 성공한 다운로드의 원본 바이트, 장벽 이후 410, 기존 답변/영수증/파일/캐시 정리와 새 응답/버전 보존·불변 증명서를 확인한다. production의 전역 파기 worker는 실행하지 않는다.
5. production의 별도 합성 폼에서 실제 최초/새 게시·영수증 PDF 다운로드와 같은 version 경합·보관을 실행한다. 서버 재시작 후 PDF·DB 해시와 권한/공개 종료를 비교한다. 자격증명·쿠키·공개 토큰은 `.local`의 비공개 checkpoint만 사용한다.
6. 변경 소스에 맞는 타입·린트·계약/계획과 필요한 회귀를 실행한다. 새 제품 결함이 있으면 실패를 재현해 고친 뒤 전체 회귀·빌드·실제 API를 다시 확인한다. 제품 변경 없이 검증만 추가되면 관련 시험과 이전 전체 회귀의 범위를 명시한다.

Ego TaskSpace 34는 명시적 재개 응답 전까지 조작하지 않는다. 실제 화면·정상 원본·공용 템플릿과 선행/외부 연동은 별도 미검증으로 유지한다.
