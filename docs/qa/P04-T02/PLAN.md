# P04-T02 단계별 편집기 저장·복구 계획

2026-10-03. 선행 P04-T01/P05-T01의 서버 기반을 사용하며, 이들의 원본·브라우저 게이트와 본 작업의 수정 후 화면 검증은 별도로 남긴다.

## 확인한 누락

- 질문 편집기와 동의/설정 화면은 수동 저장만 한다. 자동저장·저장 실패 재시도·충돌 복구 UI가 없다.
- `/form/ai/basic-frame/v3`는 질문 편집기로 연결되지 않는다. `/recipient`도 수집 동의 설정을 그대로 보여 준다.
- 초안 PATCH는 version만 검사한다. 저장은 성공했지만 응답을 받지 못한 요청을 다시 보내면 409가 나므로 자동저장에 그대로 사용할 수 없다.
- 보관된 원본 관찰에서 basic-frame의 질문 편집기는 확인했다. v3/recipient/agreement/set/setting은 오류 화면으로 기록되어 정상 흐름의 원본 동일성은 미확정이다.

## 구현

1. 초안 저장을 transaction 내부 함수로 분리한다. PATCH `/forms/:id`와 `/draft`에 선택적 Idempotency-Key를 지원하고 같은 내용·키의 재시도는 한 번의 변경/감사만 만든다. 재전송도 현재 세션/권한/활성 서비스를 재검사한다. 다른 키의 같은 version은 계속 409다.
2. 공통 편집 상태가 저장 요청을 직렬화한다. 입력 후 1.2초 자동저장, 유효하지 않은 초안 안내, 저장 중 추가 입력 보존, 응답 유실 후 같은 키/내용 재시도, 저장 성공 후 최신 version 사용을 구현한다. 충돌은 자동 덮어쓰기를 멈추고 수정본 보관·최신본 불러오기를 제공한다.
3. 생성/basic-frame/v3를 질문 편집기에 연결한다. recipient는 제3자 제공 동의 문서, agreement는 수집·이용 문서/보유 설정, set/setting은 응답 설정, share는 게시 링크를 보여 준다. 같은 formId를 유지하며 앞뒤/다음 이동 전 저장을 끝낸다. 새 폼 최초 저장은 응답 이후 URL에 ID를 반영한다.
4. 생성/편집과 동의/설정에 공통 자동저장·복구 UI를 연결한다. 이탈 시 미저장 상태를 안내하고 내부 링크 이동 전 저장을 시도한다. 템플릿은 기존 전체 질문/설정 저장·복제를 유지한다.
5. 실제 PostgreSQL에서 동일 키 동시 저장·응답 유실·키 불일치·다른 기기 충돌·권한 회수·보관 경계를 시험한다. 편집 상태 시험은 가짜 타이머/지연 응답으로 추가 입력·오류·복구를 확인한다.
6. Production API에서 모든 단계의 동일 ID/내용과 공개 버전 불변·409·재시도·독립 DB/재시작을 대조한다. 타입·린트·빌드·전체 회귀와 계약 표를 확인한다.
7. 과거 재전송 캐시에 공유 토큰이 포함된 상태에서 게시 권한을 회수하는 시험을 추가한다. 초안 응답은 신규 저장과 기존 캐시 전달 모두 토큰을 제거하며 공유 화면은 현재 게시 권한으로 다시 조회한다.

## 남은 완료 게이트

기존 Ego 창의 제어 재개 응답 후 자동저장 상태, 앞뒤 이동/새로고침/다른 기기, 충돌 안내/복구, 전체 단계와 390px를 조작한다. 원본 정상 화면 대조와 선행 Task 게이트까지 통과한 후에만 P04-T02를 완료로 집계한다.
