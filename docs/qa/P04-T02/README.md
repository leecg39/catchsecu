## 구현

- 생성/basic-frame/v3가 질문 편집기를 사용하며 `formId`와 기존 `edit` 링크를 읽는다. 제공 동의 → 수집 동의 → 설정 → 공유는 동일 폼 ID와 서버 version을 사용한다. 제공/수집 문서의 선택을 나누고 다른 단계의 선택은 유지한다.
- 유효한 제목·질문·설정은 입력 후 1.2초에 서버로 자동저장한다. 미완성 입력은 안내하고 이 화면에 유지한다. 수동 저장·앞뒤/다음 이동은 저장 완료를 기다린다. 내부 링크 이동은 미저장 상태에서 저장을 시도하고, 실패하면 편집 유지/저장하지 않고 이동을 제공한다. 새로고침·창 이탈은 미저장 경고를 연결했다.
- 공통 편집 상태가 요청을 직렬화한다. 저장 중 추가 입력을 유지하고, 확인된 최신 version으로 후속 저장한다. 응답 유실은 동일 키/내용/version으로 재시도한 뒤 추가 입력을 새 요청으로 저장한다.
- 최초 생성의 결과가 불확실할 때는 서비스 선택을 고정한다. 같은 생성 요청을 확인한 뒤 같은 폼의 추가 입력을 저장한다. 서버가 생성을 확정 거부하면 다른 서비스를 선택해 새 키로 생성할 수 있다.
- 다른 기기의 변경과 충돌하면 자동 덮어쓰기를 멈춘다. 수정본 JSON 다운로드와 최신본 불러오기를 제공한다. 최신본을 불러오면 미저장 내용이 교체된다는 안내를 표시한다.
- PATCH `/forms/:id`와 `/forms/:id/draft`는 선택적 Idempotency-Key를 지원한다. 저장·감사·암호화 재전송 결과를 한 transaction으로 묶으며 재전송도 현재 권한/세션/활성 서비스를 검사한다. 키 없는 수동 저장은 기존 version 충돌 계약을 유지한다.
- 초안 저장 응답은 공유 토큰을 포함하지 않는다. 과거 재전송 캐시에 토큰이 들어 있더라도 전달할 때 제거한다. 공유 링크 조회는 현재 게시 권한으로 서버에서 다시 검사한다.
- 게시 이후 자동저장은 새 초안을 만들고 공개 본문·문서·동의 표시는 고정한다. 템플릿의 전체 질문/설정 저장·복제는 기존 구현을 유지한다. 새 migration은 없다.

## 실패 기록

- [첫 fixture 실패](draft-fixture-before.txt)는 빈 질문 제목이 기존 입력 계약에서 거부된 422다. 유효한 질문으로 고친 뒤 제품 실패를 다시 재현했다.
- [보완 전](draft-before.txt) 7개 중 3개 실패·4개 통과: 동일 키 동시 저장, 성공 응답 유실 복구, 같은 키/다른 본문 거부가 누락됐다. 보완 후 서버 시험 7개가 통과했다.
- [편집 상태 fixture](state-fixture-before.txt)는 JavaScript의 기본 매개변수로 새 폼 시험에 기존 폼이 주입된 문제다. 명시적 null을 사용해 수정했으며 제품 결함과 구분한다.
- [생성 서비스 보완 전](service-binding-before.txt)은 추가한 두 상태 시험 중 서비스 고정이 실패했다. 당시 [전체 회귀](full-before-service-binding.txt)도 547개 중 같은 1개 실패·546개 통과였다. 보완 후 [당시 서버·편집 상태 20개](state-after-before-token-redaction.txt)가 통과했다. 새 생성의 실제 201 응답을 폐기한 뒤 같은 키 재시도·다른 서비스 선택 차단·추가 입력 유지를 production API와 독립 DB에서 검증했다. `*-before-service-binding.*`는 최종 보완 전의 별도 증거다.

- [공유 토큰 보완 전](token-before.txt)은 과거 암호화 캐시에 토큰이 저장된 뒤 게시 권한만 회수하는 신규 사례의 실제 실패다. 응답에 토큰이 포함되는지 boolean으로 비교해 비밀 값은 로그에 출력하지 않았다. 저장할 때와 재전송할 때 모두 토큰을 제거한 뒤 [서버·편집 상태 21개](token-after.txt)와 전체 548개가 통과했다. `*-before-token-redaction.*`는 토큰 보완 전의 전체 547개·API·재시작 기록이다.
