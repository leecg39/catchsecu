# P04-T02 브라우저 검증 목록 — 실행 대기

기존 Ego 작업 공간의 제어를 재개한 뒤 실행한다. 아래 항목은 API·상태 시험 통과만으로 완료 표시하지 않는다. 합성 시험 계정을 사용하고 실제 사용자 관리자 계정의 데이터는 수정하지 않는다.

| 화면·상황 | 조작 | 확인할 결과 |
|---|---|---|
| 생성·basic-frame·v3 | 서비스 선택, 제목·질문 작성, 1.2초 대기 | 저장 상태가 바뀌고 URL에 formId가 반영됨. 새로고침 후 같은 ID·내용 |
| 저장 중 추가 입력 | 저장 응답을 기다리는 동안 본문 수정 | 추가 입력이 유지되고 서버 최신 version으로 후속 저장 |
| 최초 생성 응답 유실 | 실제 성공 응답을 클라이언트가 받지 못하도록 시험 환경에서 재현 | 서비스 선택 고정, 재시도로 같은 ID, 추가 입력 유지 |
| recipient | 제공 동의 문서 선택 후 agreement 이동 | 같은 formId, 제공 문서 선택 유지 |
| agreement | 수집 동의 문서·목적·보유 기간 입력, 앞뒤 이동 | 제공/수집 문서가 서로 유지되고 새로고침 후 복원 |
| set·setting | 응답 한도·제출 안내 변경 후 이동 | 저장 완료 뒤 이동, 두 경로에서 같은 서버 값 |
| share·게시 후 초안 | 게시 링크 조회, 이전 단계에서 본문 변경 | 현재 권한에 따라 공유 링크 표시, 기존 공개 본문은 유지 |
| 두 기기 충돌 | 같은 version으로 각 화면에서 다른 값 저장 | 두 번째 화면에 409 안내, 수정본 다운로드·최신본 불러오기 |
| 잘못된 입력 | 빈 제목·질문 또는 보유 기간 0 입력 | 자동저장 대신 입력 안내, 수정 중 내용 유지 |
| 이동·창 이탈 | 미저장 상태에서 내부 링크·새로고침 | 내부 이동은 저장 완료 대기. 실패 시 계속 편집/이동 선택. 창 이탈 경고 |
| 390px | 위 단계·상태·복구 버튼을 좁은 화면에서 조작 | 읽기·입력·선택·복구 가능, 가로 넘침 없음 |

각 사례에는 화면 캡처, 실제 API의 formId/version, 독립 DB 대조를 남긴다. 보관된 원본에서 오류로 기록된 v3/recipient/agreement/set/setting은 로그인한 정상 화면을 다시 관찰하고 차이를 기록한다. 새 작업 공간이나 다른 브라우저로 기존 제어 제한을 우회하지 않는다.
