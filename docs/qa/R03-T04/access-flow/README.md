# 접근 요청 독립 HTTP·DB·재시작 대조

2026-10-10. `scripts/qa-rea-access-requests.ts`의 `--prepare`는 로컬 메일 전용 새 계정/회사를 준비한다. 비밀값은 권한0600의 무시된 로컬 파일에만 저장한다. 기본 실행과 `--after-restart`는 화면에서 만든 업무 결과를 대조하며 성공해야 하는 업무 쓰기를 새로 만들지 않는다.

- `verified.json`, `verified-after-restart.json`: 각각 HTTP19개 통과. 새 로그인 조회·상태 필터·페이지 보정·권한 반영, 익명/조회자 검토/타회사·타인 취소 거부, 낡은 버전·이미 승인된 서비스·잘못된 입력을 확인했다.
- 요청4건은 순서대로 취소/거절/취소/승인이고 모두 version2다. 세 번째 취소는 UI 충돌 재현용 별도 HTTP 세션에서 실행했다.
- 조회자 멤버 version2·서비스 권한1건이며 capabilities는 현재 viewer 역할과 같다. 승인/거절 답변도 DB 원문과 실제 UI가 일치했다.
- 감사8건은 각 생성/결정과 일치한다. 실패 요청은 요청 개정·부여 권한·감사 기록을 늘리지 않았다.
- 새 서버 프로세스에서도 상태 지문 `98191b48443a36e6e78fbf79d1654bfeff56235111f0de000b1fd627fb73bcc2`가 일치했다. 별도 브라우저 재조회 증거도 R03-T03에 있다.

기존 회사/서비스 fixture와 분리했으며 원본 사이트 자료에 쓰지 않았다. [권한 경계 회귀89개](../../R03-T02/access-authority/README.md)와 [실제 화면](../../R03-T03/access-flow/README.md)을 함께 확인한다. 이 검사는 전체 R03 또는 외부 제공사 수용 완료를 뜻하지 않는다.
