# P07-T01 CSV 수집 보완 계획

작성일: 2026-10-04. 공식 완료 15/72를 유지하고, 실제 증거가 있는 항목만 갱신한다.

## 구현과 검증

1. 파일 등록·헤더 검사·컬럼/출처 설정·검증·반영·재시도·정리 API에서 현재 회사, 계정, 서비스, 로그인/MFA/비밀번호 정책을 잠그고 완료 직전 기한을 다시 검사한다. 생성 요청 재실행은 현재 작업 상태를 반환한다.
2. 목록은 제목/ID 검색, 상태 필터, 지원하는 정렬과 페이지 보정을 적용한다. 중복·알 수 없는 쿼리와 비표준 If-Match를 거절한다. 행 미리보기와 실패 CSV는 감사 저장 후에도 보관 기한과 연결 응답의 보유 기한을 검사한다.
3. ImportJob에 계속 증가하는 leaseGeneration을 추가한다. 현재 실행 번호·작업자·임대 기한을 모두 만족하는 실행만 반영·실패 상태를 저장한다. DB 트리거도 유효한 임대 없이 응답·행을 반영하지 못하게 한다. 합성 QA는 회사/작업 ID를 지정한 처리만 실행한다.
4. UTF-8/EUC-KR, 빈 행, 10MB/10,000행/100열 제한, 타입/동의/출처, 파일 내 중복, 50행 단위 반영, 부분 실패, 원본 삭제 실패, 권한 회수, 같은 작업 재실행의 응답 중복 0을 실제 PostgreSQL로 검증한다. 별도 새 업로드는 별도 수집이라는 기존 정책을 유지한다.
5. 화면의 수정·검증·반영·재시도·정리 버튼을 서버가 계산한 권한과 상태에 연결한다. 오래된 폼/확인창을 새 권한으로 초기화하고 서버가 보정한 페이지를 사용한다.
6. 기존 QA 파일을 보존하고 이번 실행의 로그·해시를 별도 저장한다. 로컬 합성 회사에서 HTTP 업로드→ClamAV→검증→원본 삭제→반영→실패 CSV→재실행을 확인하고 기존 업무 데이터가 바뀌지 않았는지 대조한다.

## 남은 완료 조건

- 기존 Ego 창을 재개할 명시적 승인이 필요하다. 현재 화면 코드 수정은 실제 브라우저 검증으로 인정하지 않는다.
- 원본 사이트의 현재 동작 재확인, 운영 비공개 저장소·백업 복구 후 삭제 검증은 별도 증거가 필요하다.
- 선행 작업 P06-T01/P05-T01/P01-T04의 남은 게이트와 위 조건이 통과하기 전에는 이 Task를 완료로 표시하지 않는다.
