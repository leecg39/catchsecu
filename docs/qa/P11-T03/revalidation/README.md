# P11-T03 SSO 회사 설정 — 현재 권한·활성화·경합 보완

2026-10-06. 회사 SSO 설정 CRUD의 서버 집행과 화면 안내를 보완했다. 전체 Task는 진행 중이며 목표는 활성 상태다.

## 변경

- 사전검사 실패 설정은 이름·스코프·시크릿을 함께 보내도 활성화할 수 없다. 409 응답이며 설정·버전·감사를 변경하지 않는다.
- 조회·생성·수정·삭제·재검사는 현재 회사/소속/역할/계정/이메일 인증/세션/보안 정책을 트랜잭션 안에서 확인한다. 변경은 직접 소속 owner에게만 허용한다. 완료 직전에도 세션·정책 기한을 확인한다.
- 회사→구성원/정책→설정 순서로 잠근다. 같은 version의 동시 수정 중 하나만 성공하고 나머지는 409다.
- 외부 사전검사 요청 동안 DB 잠금을 유지하지 않는다. 검사 전후에 권한을 확인하고, 저장 직전에 설정 version을 재검사한다. 검사 중 권한 회수·설정 변경은 생성/저장과 감사를 거부한다.
- 인증서·시크릿·스코프 변경은 연결을 비활성화하고 사전검사 결과를 초기화한다. 재검사 성공 뒤 명시적으로 활성화한다. 사용 중 설정의 재검사가 실패해도 비활성화한다.
- 화면은 인증 설정 변경에 따른 재검사/활성화를 안내한다. 등록은 성공하고 사전검사만 실패한 경우 목록으로 돌아가 등록 결과를 보여주어 같은 등록 폼을 다시 제출하는 일을 방지한다.

HTTP 시험은 이 라운드에서 생성한 합성 회사/관리자에 제한했다. QA 스크립트는 로컬 catchsecu_dev와 127.0.0.1 서버만 허용한다. 시험 암호는 Git에서 제외된 .local 파일에만 저장하고 보고서에 출력하지 않는다. 사용한 HTTP 로그인 세션은 로그아웃했다. 기존 사용자 서버를 종료하거나 전역 worker를 실행하지 않았다. 스키마/migration 변경은 없다.

재시작 검증은 새 로그인 뒤 저장된 설정의 유지 여부를 확인한다. 재시작 전 세션 유지 검증을 뜻하지 않는다. 관리 HTTP 시험의 SAML 인증서는 합성 인증서이며 외부 IdP 로그인 증거가 아니다. OIDC/SAML 로그인·서명 검증은 로컬 IdP를 사용하는 PostgreSQL 시험 범위다.

## 실패 기록

- 최초 baseline의 권한 회수 시나리오는 마지막 owner 보호 규칙에 걸렸다. 보조 관리자 fixture를 추가하는 중 Prisma relation 입력 형식 오류도 확인했다. 두 초기 로그와 첫 수정 후 실패 로그를 보존했다: [최초](baseline.log), [fixture 수정 과정](baseline-valid-fixture.log), [첫 수정 후](provider-tests.log). 파일 이름과 무관하게 이 로그는 유효한 전체 baseline 통과 자료가 아니다.
- fixture를 실제 relation 계약에 맞춘 뒤 최종 27개가 통과했다.
- 첫 빌드는 로컬 메일을 production으로 실행하는 확인 플래그가 없어 중단됐다: [실패 빌드](build.log). 로컬 QA 전용 ALLOW_LOCAL_MAIL=1/ALLOW_LOCAL_KAKAO=1 설정으로 다시 빌드했다. 운영 공급자 연결의 증거로 집계하지 않는다.
- pg 라이브러리의 동시 query 호출 폐기 예정 경고가 남아 있다. 시험 실패는 없다.

## 남은 조건

- Ego 기존 작업 공간 45가 없어 현재 변경의 실제 브라우저 조작을 수행하지 못했다. 새 작업 공간 생성에 대한 사용자 응답을 기다린다. 다른 브라우저로 우회하지 않았다.
- 실제 SaaS IdP의 회사별 로그인·계정 연결·초대가입 UI, 회수/만료·실패 흐름과 공급자 결과를 검증해야 한다.
