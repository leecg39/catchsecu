# 정보주체 조회·동의 철회 검증

2026-10-03. 독립 로컬 구현의 DB·API·화면 검증이다. 전체 181경로 구현 완료를 의미하지 않는다.

## 구현 결과

- 폼 질문과 CSV 컬럼에 이름·이메일 역할을 직접 지정한다. 필수 단문 질문 두 개를 각각 한 번만 지정해야 게시할 수 있다. 제목으로 역할을 추정하거나 과거 게시본을 소급 연결하지 않는다.
- 회사·서비스별 DataSubject에 정규화 이름/이메일 HMAC과 암호화 연락처를 저장한다. 제출·CSV 반영·정정·파기에 연결했다. 마지막 응답 연결이 없어지면 연락처와 인증 범위도 삭제한다.
- 이름·이메일 조회는 존재 여부와 관계없이 같은 202 응답이다. 실제 일치 자료가 있으면 worker가 인증 메일을 전달한다. 요청 브라우저 쿠키, 10분 일회용 링크, 요청 제한을 검사한다. 링크 GET은 인증을 소비하지 않는다.
- 인증 후 30분 HttpOnly 세션을 사용하며 URL에는 비밀 없는 세션 ID만 남긴다. 각 API는 URL ID와 쿠키의 일치, 고정된 정보주체 범위, 현재 회사·서비스·응답 보유 상태를 검사한다.
- 동의 이력과 처리 이력에 동의·CSV 등록·철회를 표시한다. 응답 답변, 담당자 메모, 정정 원문은 반환하지 않는다.
- 철회 요청의 확인·취소·완료를 DB 상태로 처리한다. 확정 시 응답 상태, 불변 동의 이벤트, 서비스별 이메일 발송 차단을 함께 저장한다. 관리자 철회도 같은 차단을 적용한다.
- 서비스 범위를 가진 메일은 등록 시점과 worker 전달 직전에 차단을 검사한다. 이메일 인증 메일은 별도이며 만료된 정보주체 인증 메일은 전달하지 않는다. 만료 후 24시간이 지난 인증 요청·세션·연결된 임시 철회 요청을 정리하고 인증 메일 작업의 원문과 로컬 메일 파일도 삭제한다.
- migration 23~25를 개발·테스트 PostgreSQL에 적용했다. 파기 증명서에 정보주체 연결·연락처 삭제 건수를 포함한다.

## Ego 실제 화면 검증

동일 TaskSpace 30에서 합성 자료를 사용했다. 원본 운영 사이트의 데이터는 변경하지 않았다.

1. 폼 편집에서 이름·이메일 역할을 선택 → 생성·게시 → 공개 폼 제출. [접수 화면](01-submitted.png)
2. 이름·이메일·필수 동의 입력 → 공통 발송 안내 → 실제 worker의 로컬 메일 파일 확인. [발송 안내](02-mail-sent.png), [전달 확인](mail-verification.json)
3. 메일 링크에서 인증 버튼 → 동의 이력 1건. 관리자용 합성 답변은 API·화면에 없음. [응답 DTO](browser-consents.json)
4. 철회 취소 후 동의 유지 → 새 철회 요청 → 서버 재시작 → 완료 URL 직접 접근 시 미완료 안내. [미완료 결과](05-incomplete-result.png)
5. 철회 확정 → 완료 화면 → 동의/처리 이력 → 관리자 응답 상태와 DB 대조. [완료 화면](06-withdrawn.png), [동의 이력](07-consents-withdrawn.png), [처리 이력](08-events.png), [관리자 화면](10-admin-withdrawn.png), [관리자 API](browser-admin.json)
6. 다른 세션 ID 401, 사용한 링크 재인증 422, 정상 세션 200, 조회 종료 후 401. [접근 거부](browser-denials.json), [종료](browser-logout.json)
7. 390px에서 가로 넘침 없음. [모바일 화면](09-mobile-events.png), [측정](browser-mobile.json). 데스크톱 버튼 폭도 공통 스타일과의 우선순위를 수정해 재확인했다.

## 남은 범위

- 외부 SMTP 전달은 미검증이며 로컬 메일함 전달을 확인했다.
- 원본 agree/action-history와 formComplete/form-interrupt의 정상 인증 후 화면은 미확정이다. 위 화면과 상태 규칙은 독립 구현 계약이다.
- 현재 발송 차단은 서비스 이메일 공통 함수에 적용된다. 마케팅 동의·재동의·일괄 관리 화면, 문자 채널, 캠페인/외부 공급자 구현은 P07-T02·P08·P09에서 이어서 구현한다. 일반 수집 동의를 마케팅 수신 동의로 취급하지 않는다.
- Suppression HMAC의 운영 보존 정책, 외부 메일함·백업 삭제, 선행 Task의 전체 게이트는 남아 있다. 이번 결과는 P06-T05 등의 부분 검증 증거이며 정식 완료 집계는 2/72를 유지한다.
