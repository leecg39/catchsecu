# 이메일 내용·첨부 계약

2026-10-03. 원본 유료 작성기는 관찰 제한이 있어 독립 구현 계약을 사용한다.

- text/html과 필수 텍스트 대체 본문. 서버에서 sanitize-html 2.18.0을 사용하고 허용 요소·속성·HTTPS/mailto URL을 지정한다. CSS·이미지·스크립트·iframe·SVG·MathML·추적 리소스를 제거한다. 변수는 제목/텍스트 및 HTML 글자에만 허용하며 속성 안의 변수는 거부한다. [공식 문서](https://github.com/apostrophecms/apostrophe/tree/main/packages/sanitize-html).
- HTML 변수값을 이스케이프하고 렌더링 후 헤더·길이·미확정 변수를 검사한다. 미리보기 iframe은 sandbox·CSP·inert 본문을 적용한다. 실제 전송에는 저장된 정제 결과를 사용한다.
- MessageTemplate은 서비스·채널별 CRUD·보관/복원·검색·페이지와 불변 개정본을 가진다. 삭제는 과거 개정본의 이름·내용도 지운다. 적용된 캠페인은 별도 내용 사본과 원본 버전 식별자를 보관한다. 이후 템플릿 변경·삭제로 예약 내용을 바꾸지 않는다.
- 첨부는 FileObject의 campaign 소유권과 회사·서비스·업로더 범위를 사용한다. 최대5개·각10MB·합계20MB. ClamAV 검사·암호화 저장·부모 경로 다운로드를 적용한다. 요청 시 ID·SHA-256·크기·MIME 목록을 고정하고 예약/재요청/전달 직전에 실제 바이트를 확인한다.
- 공급자에는 검증한 Buffer·파일명·MIME만 전달하며 파일 경로·URL 접근을 차단한다. 로컬 메일함에는 base64 바이트와 해시를 기록해 실제 원문을 대조한다. [Nodemailer 첨부 문서](https://nodemailer.com/message/attachments).
- 공통 첨부 원본은 캠페인 소유이며 생성 후 최대30일 보관한다. 초안 삭제/첨부 제거 시 실제 파일도 지우고 실패는 deleting 상태로 재처리한다. 특정 응답/동의 원문 삭제 시 해당 수신자 메일 파일 전체(렌더링된 HTML·첨부 사본 포함)를 제거한다. 다른 수신자와 공유하는 공통 원본은 캠페인의 기한을 따른다. 외부 수신자 메일함의 사본은 삭제 증거 범위에 포함하지 않는다.
- v2 작업 유형과 캠페인 프로토콜 필드를 추가했다. 이전 worker가 HTML/첨부 처리를 생략해 전송하지 못하며 요청 이후 downgrade를 DB에서 거부한다. 기존 v1 텍스트 작업은 새 worker에서 처리할 수 있다. 모든 동일 프로젝트 worker를 중지하고 migration 후 같은 코드로 재시작한다.
