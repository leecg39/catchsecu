# 이메일 내용·템플릿·첨부 구현 계획

캠페인의 로컬 CRUD·발송 검증 이후 P09-T01의 남은 내용을 이어서 구현한다. 전체 72 Task와 선행 게이트는 유지한다. 원본 유료 편집기는 관찰되지 않았으므로 아래 계약은 독립 구현으로 기록한다.

## 작업 순서와 수용 조건

- [x] 1. 현재 Campaign.content, 파일 소유권/검사/파기, 발송 payload·응답 파기 연결을 파일 단위로 다시 읽고 변경 지점을 기록한다.
- [x] 2. 이메일의 text/html, 템플릿 변수, 첨부 제한 계약을 확정한다. 문자에는 이메일 전용 필드를 허용하지 않는다. 제목·본문의 미확정 변수와 렌더링 후 헤더 개행을 거부한다.
- [x] 3. MessageTemplate 모델·회사/서비스/채널 범위·version·불변 개정본·보관/복원·삭제 계약을 추가한다. 템플릿 적용 시 캠페인에 내용을 복사하고 이후 템플릿 변경이 예약 내용을 바꾸지 않게 한다.
- [x] 4. 생성·검색·목록·상세·수정·보관·복원 API와 화면을 연결한다. 현재 message.manage/read 및 서비스 grant를 다시 확인한다. 멱등 생성·버전 충돌·범위 위반을 시험한다.
- [x] 5. 검증된 HTML sanitizer를 공식 문서와 코드로 확인하고 허용 요소/속성/URL을 제한한다. 스크립트·이벤트·위험 URL·외부 추적 리소스·CSS 우회를 시험한다. 렌더링 변수값은 출력 문맥에 맞게 이스케이프한다.
- [x] 6. HTML 미리보기는 격리된 문서와 제한된 CSP로 표시한다. 텍스트 대체 본문을 제공하고 실제 보낼 정제 결과를 보여준다.
- [x] 7. 캠페인 첨부 소유권을 기존 FileObject에 연결한다. 최대 개수/총 바이트, 회사·서비스·업로더·캠페인 상태, ClamAV, 암호화 저장, 첨부 연결/교체/제거/다운로드를 구현한다.
- [x] 8. 요청 이후 첨부와 템플릿 내용을 고정한다. 예약/전송 직전 첨부 상태·해시·원문 기한을 재확인한다. 파일 경로나 임의 네트워크 주소를 메일 공급자에 전달하지 않는다.
- [x] 9. Nodemailer에 검증된 MIME/이름/바이트를 연결하고 로컬 테스트함에도 검증 가능한 첨부 메타데이터·원문을 저장한다. 재시도 시 중복 생성과 개인정보 파기 누락을 막는다.
- [x] 10. 초안 삭제·첨부 삭제 실패·30일 기한·응답 파기·동의 원문 삭제에 렌더링된 메일/첨부 사본을 포함한다. 공유 첨부와 수신자별 사본의 소유권 및 보관 기한 차이를 문서화한다.
- [x] 11. PostgreSQL 통합 시험: CRUD·격리·권한 회수·멱등/버전·불변 예약·XSS/URL/변수·검사 실패·용량/개수·실제 첨부 바이트·삭제/재시도·파기 증명서 연결.
- [x] 12. Ego에서 템플릿 생성→수정→초안 적용→HTML 미리보기→첨부 업로드→실제 로컬 메일 확인→첨부 제거→보관/복원·삭제를 실행하고 DB/파일과 대조한다. 390px와 앱/worker 재시작, 영향 회귀·타입·린트·빌드·OpenAPI를 확인한다.

## 완료 판단

각 단계의 구현과 증거가 모두 있어야 이 범위의 완료로 기록한다. 실제 외부 SMTP·반송/수신거부·문자/결제 공급자 검증은 해당 Task에 남긴다. 원본 미관찰 사항이나 외부 공급자 모의 응답을 실제 운영 증거로 집계하지 않는다.

## 실행 결과

위 12단계의 독립 로컬 구현과 검증을 마쳤다. [검증 보고서](README.md)에 328개 회귀·Ego·실제 메일/첨부/삭제·재시작 증거를 기록했다. 외부 SMTP 응답은 모의 계약 시험이며 외부 실전송·반송·수신거부 공급자 검증은 후속 Task다. 전체 Task 체크박스는 변경하지 않았다.
