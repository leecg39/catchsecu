# 외부 개인정보 공유 구현·검증 계획

대상: P06-T04 및 P06-T03의 `/file-view/.../shared`. 기존 72개 Task의 부분 구현으로 추적한다.

## 확인한 원본 근거

- `docs/research/public/_shared-privacy_{verify,email-verify,view}.json`: 세 경로 모두 인증 전 화면으로 돌아온다. 확인된 항목은 캐치폼 코드, 열람자 인증코드, 이메일, 필수 동의, 이메일 인증 버튼이다.
- 인증 후 목록·관리 화면은 원본 확인이 끝나지 않았다. 다음 구조는 독립 서비스의 계약이며 원본 내부 API를 추정한 결과가 아니다.

## 데이터와 API

1. ShareGrant: 회사·서비스·폼·게시 버전, 암호화 이메일/HMAC, 초대코드 HMAC, 만료·회수일, 낙관적 버전, 생성 구성원. 이메일 원문·코드는 감사 로그에 남기지 않는다.
2. ShareField: grant와 같은 게시 버전의 질문 FK. 최소 1개, 최대 100개. 다른 폼·버전·회사 질문 혼합은 API와 DB에서 차단한다.
3. ViewerChallenge: 브라우저 연결 HMAC, 6자리 코드 HMAC, grant 버전, 10분 만료, 최대 5회 시도, 일회용 소비. 인증 실패 횟수는 트랜잭션을 완료한 뒤 오류를 반환해 보존한다.
4. ViewerSession: challenge와 grant FK, opaque token HMAC, grant 버전, 30분 만료(공유 기한 이내), 회수일. HttpOnly·SameSite=Strict 쿠키, HTTPS에서 Secure.
5. `share.manage`는 소유자·관리자·개인정보 담당자 역할과 서비스별 권한으로 제한한다. 모든 변경과 열람에서 현재 회사·구성원·서비스 권한을 재검사한다.
6. 관리자 API: 옵션/목록/상세/생성/범위·이메일·기한 수정/초대 재발송/회수/열람 로그. 생성은 멱등키, 변경은 버전 필수. 수정·재발송은 코드 교체와 모든 기존 challenge/session 무효화.
7. 외부 API: challenge 발급·검증, session 조회·로그아웃, 허용 응답 목록·상세, 허용 파일 목록·메타·다운로드. 잘못된 초대 조합도 동일한 challenge 발급 응답을 받으며 인증코드·토큰을 JSON으로 보내지 않는다.
8. 외부 열람은 지정 게시 버전의 submitted/corrected 응답만 허용한다. 철회·파기 요청·파기·기한 종료 응답은 제외한다. legal hold라도 외부 열람 기한을 연장하지 않는다. 메모·정정 전 값·영수증은 공유하지 않는다.
9. 파일은 허용 질문의 현재 Answer에 연결된 clean/attached 파일만 허용한다. 응답·질문·파일 조합, 공유 회수·만료를 매번 확인한다. 파일 바이트를 읽는 동안 공유/응답/파일 잠금을 유지한다.

## 화면

- 응답 관리에 외부 열람자 관리 패널: 버전·질문·이메일·만료 선택, 목록 상태, 수정·재발송·회수, 열람 로그.
- 기존 인증 전 구성 유지. 이메일 코드 입력, 기한·오류·재인증 안내, 서버 세션으로 허용 필드/파일만 표시.
- 기존 `/file-view/:submissionId/shared`와 단일 파일 경로 연결. 일반 관리자 세션과 외부 세션을 구별한다.

## 검증 게이트

- 실제 PostgreSQL/API: 생성·재시도·충돌, 다른 회사/서비스/버전 및 역할 거부, 잘못된 코드 5회·브라우저 바인딩·만료·일회용·동시 검증, 범위 수정/회수/재발송 즉시 차단, 현재 권한 변경 차단, 공유 필드 외 PII 부재, 정정 이전 파일·다른 질문 우회 차단, 철회/보유 기한 차단, 감사 로그·암호화·DB FK.
- Ego: 합성 폼·응답·파일 준비 → 공유 생성 → 로컬 메일 worker 전달 → 이메일 인증 → 지정 항목·파일 다운로드 → 수정/재인증/회수 → 차단 → 좁은 화면 점검.
- 테스트·타입검사·lint·프로덕션 빌드 통과, DB 및 파일 바이트 별도 대조. 외부 SMTP는 자격증명 없는 상태이므로 검증 완료로 표시하지 않는다.
