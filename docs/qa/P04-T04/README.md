## 구현

- 목록/상세는 transaction에서 현재 회사·계정·세션·이메일 인증·구성원·전문가 배정·서비스 권한을 확인한다. 목록은 공유 토큰을 제외하고 상세는 현재 게시 권한이 있을 때만 반환한다. 전문가의 보관 서비스 상세·목록·즐겨찾기는 거부한다.
- 제목/생성자·상태·한국 날짜 기간·본인 즐겨찾기·제목/생성일 정렬을 서버에서 처리한다. 범위 밖 페이지는 마지막 페이지, 빈 결과는 첫 페이지로 보정하고 화면에 서버 페이지를 표시한다.
- 목록에 최신 내용 미리보기, formId 편집, 복사, 일시 중지/재개, 보관을 연결했다. 미리보기에는 질문·선택지·조건·행렬 행·선택 수·동의서·보유 기간을 표시한다.
- `GET /forms/{id}/deletion`은 현재 version과 삭제 가능 여부/참조 사유를 반환한다. 화면은 게시/승인/응답/공유/업로드/파일 참조 사유와 응답/파기 관리 링크를 안내한다.
- `DELETE /forms/{id}`는 공개를 종료하고 보관한다. `/purge`는 현재 작성 권한·활성 서비스·If-Match·전체 이력을 잠금 아래 다시 검사해 미게시·미참조 초안만 영구 삭제한다. 질문·선택지·문서 연결·즐겨찾기를 같은 transaction에서 제거하고 감사·게시 문서·독립 복사본을 유지한다.
- 생성/복사/템플릿 사용·초안 저장 캐시를 폼 자원에 연결했다. 완전 삭제 시 이전 형식의 캐시도 회사 구성원 범위에서 찾아 암호화 내용·요청 해시를 제거한다. 삭제된 폼의 생성 키 재전송은 410이며 같은 version의 저장/삭제 경합은 한 번만 성공한다.
- 새 모델/migration은 없다. 기존 56개 migration의 외래키·불변 게시/승인/문서 제약을 유지한다.

## 검증

처음 12개 중 실제 제품 실패 10개를 재현한 후 12개가 통과했다. 추가한 입력·회사/권한·보관 초안·템플릿 캐시·동의서 보존·전문가 범위를 포함해 최종 신규 PostgreSQL 18개가 통과했다. 외국 회사 policy 누락·존재하지 않는 템플릿 scope·전문가 viewer 제약의 fixture 오류는 제품 결함과 구분해 수정했다.

전문가 보관 서비스 회귀를 실제 실패로 재현해 상세·목록·즐겨찾기를 보완했다. 보강 전 583개·54 API 결과는 별도 당시 기록으로 유지한다. 최종 전체 회귀 42개 파일·583개가 통과했고 실패/대기는 0이다. 하나의 시험 DB에서 파일을 순서대로 실행했다. 타입·변경 파일 린트 오류 0·Node.js 24.19.0 production 빌드·계약/계획 검사를 통과했다. 계약은 252경로·366작업·31정책, 구현 314/계획 52이며 권한/입력/매핑 누락 0이다.

Production API 54개(준비 42개·재시작 후 12개)를 실제 서버와 PostgreSQL에서 확인했다. 합성 소유자의 별도 시험 회사에서 두 페이지 검색·정렬·페이지 보정·즐겨찾기, 생성/저장 재전송·독립 복사, stale/missing version 차단·초안 삭제·캐시 410, 게시/응답/보관·참조 삭제 차단, 회사 범위 404·익명 401을 검사했다.

최종 PID 56764→57673 재시작 전후 폼 2개(게시 후 보관 v3·독립 복사 초안 v1)·버전/질문 각 2개·게시본 1개·응답 1개·업무 감사 9개를 DB와 대조했다. 게시 직후 버전 해시와 응답 암호화 해시를 보관 전 저장해 재시작 후 보존을 확인했다. 삭제한 초안의 생성/저장 캐시 내용과 요청 해시가 비어 있고 독립 복사본의 캐시는 유지된다. 같은 키/참조 차단의 추가 쓰기는 없다. 합성 세션을 종료했고 사용자 관리자 계정은 변경하지 않았다.
