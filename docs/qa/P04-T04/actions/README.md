# P04-T04 서비스별 작업 권한 후속 검증

2026-10-03. P04-T04는 진행 중이며 공식 완료는 15/72다. 이 폴더는 당시 폼 목록·상세·삭제와 작업 권한 검증이다. 후속 전체 회귀·템플릿/전체 흐름은 [P04-T05](../../P04-T05/README.md)에 기록한다. 상위 폴더의 583개·54 API 기록은 검증 당시 증거로 유지한다.

## 변경

- 목록·상세 GET은 현재 역할·서비스 grant·서비스/폼 상태·공개 링크 만료로 미리보기·응답·편집·복사·템플릿 등록·공유·중단/재개·보관·삭제 조건 확인을 계산한다. 생성·저장·복사·템플릿 사용의 멱등 응답에는 작업 권한을 캐시하지 않는다.
- 목록의 생성·업로드·업로드 작업 목록은 선택 서비스의 현재 권한을 따른다. 서비스 미선택 시 현재 조회할 수 있는 서비스에서 계산한다. 응답 권한이 없는 제목은 미리보기를 연다.
- 보관된 폼은 독립 복사와 삭제 조건 확인을 허용한다. 보관 서비스와 가져오기 양식의 변경 작업은 표시하지 않는다. 만료된 공개 링크의 공유·재개를 표시하지 않는다.
- 삭제 조건 조회는 읽기 권한으로 삭제 불가 사유를 확인할 수 있다. 실제 완전 삭제는 별도 작성 권한과 version을 요구한다. `checkDeletion`은 조건 확인 버튼의 권한이며 `canPurge`와 다르다. 응답 링크는 현재 `submission.read` 권한을 따른다.
- 권한·버전·삭제 상태 오류 후 목록을 다시 조회한다. 복사 결과가 유실되면 다른 폼 작업을 거쳐도 원래 폼의 멱등 키를 유지한다.

## 검증

새 권한 테스트 6개에서 작업 DTO/목록 메타데이터 부재를 실제 실패로 재현했다. 가져오기 양식의 원본 종류는 DB에서 변경할 수 없어 실제 생성 방식으로 fixture를 바로잡았다. 기존 18개를 포함해 24개가 통과했다.

전체 회귀는 실제 PostgreSQL에서 파일을 순서대로 실행해 **42파일·589개 통과, 실패/대기 0**이다. 타입·변경 파일 린트·Node.js 24.19.0 production 빌드·계약/계획·diff 검사를 통과했다. 계약은 252경로·366작업·31정책, 구현 314/계획 52이며 권한/입력/매핑 누락은 0이다.

별도 합성 시험 회사의 실제 production API **52개(역할 검증 36개·재시작 후 16개)**가 통과했다. 동일 세션에서 편집자→조회자→개인정보 담당자→다른 서비스만 편집자→양쪽 서비스 편집자→조회자로 바꾸고 DTO와 실제 저장·복사·재개·응답 조회의 허용/거부를 비교했다. 사용자 관리자 계정은 변경하지 않았고 합성 세션을 종료했다.

PID **94799→2211** 재시작 전후 폼/버전 각 3개·게시본 2개·응답 1개·구성원 역할/grant·쓰기 감사 24개가 동일했다. 추가 역할 변경 전후에도 폼·게시 버전·암호화 응답 해시가 같았다. `submission.list_viewed` 열람 감사는 쓰기 감사와 구분한다.

준비 실행은 질문 종류명·fixture 관계 필드·현재 회사 선택 순서·삭제 조건 GET 기대값 오류로 중단됐으며 성공으로 집계하지 않았다. 회사 생성 429와 로그인 429도 기록했다. 요청 제한을 수정하지 않고 최초 생성한 빈 합성 회사·서비스를 선택해 재사용했다. 준비 실행은 폼·게시·응답·복사·실제 만료·역할 변경을 DB에 저장했지만 성공 보고가 없어 52개에 포함하지 않는다. 최종 역할 검증은 그 checkpoint를 읽고 실제 API로 역할 전이를 다시 실행한 뒤 재시작과 비교했다. 초대는 `local` 전송 설정의 해당 합성 회사 큐 한 건만 복호화해 수락했다. 외부 전송이나 전체 worker 실행의 증거로 사용하지 않는다.
