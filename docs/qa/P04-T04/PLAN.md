# P04-T04 폼 목록·상세·보관·완전 삭제 계획

2026-10-03. 기존 폼 API·화면을 대조했다. 선행 P04-T03의 정상 원본·브라우저 게이트는 별도로 유지한다.

## 확인한 누락

- 폼 목록/상세는 이전 Context의 권한으로 조회하며, 목록은 범위 밖 page를 보정하지 않는다.
- 목록에는 정렬·미리보기·참조 중 삭제 사유가 없고 DELETE는 보관만 수행한다. 계약의 미참조 초안 완전 삭제가 구현되어 있지 않다.
- 폼 생성/복제/템플릿 사용과 초안 저장의 암호화 재전송 캐시는 폼 삭제와 연결되어 있지 않다.

## 구현·검증

1. 현재 계정/세션/이메일/구성원/전문가/서비스를 transaction 안에서 검사하고 목록/상세 DTO의 공유 토큰도 현재 게시 권한에 맞춘다. 목록의 제목/생성자·상태·즐겨찾기·한국 날짜·정렬·페이지 계약을 고정한다.
2. 목록에 정렬·미리보기·보관·완전 삭제 사유를 연결한다. 신규/편집 링크를 formId로 구분하고 서버의 보정된 페이지를 표시한다. 보관은 공개를 종료하며 기존 응답/승인 증거를 유지한다.
3. 삭제 가능 여부 API와 If-Match를 요구하는 완전 삭제 API를 추가한다. 게시/승인/응답/공유/가져오기/파일 참조가 있는 폼은 409로 차단한다. 미참조 초안만 질문/선택지/문서 연결/즐겨찾기와 함께 transaction에서 제거하고 감사는 남긴다.
4. 생성/복제/템플릿 사용의 캐시를 새 폼 자원에 연결한다. 이전 형식의 캐시도 삭제한 폼을 재전송하지 못하고, 완전 삭제 시 해당 초안 캐시의 암호화 내용까지 정리한다. 독립 복사본은 유지한다.
5. 실제 PostgreSQL에서 권한 회수·세션 종료·전문가/회사 범위·페이지/기간/정렬·참조 차단·삭제 경합·캐시 정리의 실패를 먼저 재현하고 수정한다.
6. Production API에서 두 페이지 목록, 검색/정렬/즐겨찾기, 게시/응답/보관 후 기록 보존, 미참조 초안 삭제·캐시 410과 재시작 후 독립 DB를 대조한다. 타입·린트·빌드·전체 회귀와 계약 표를 확인한다.

## 완료 게이트

기존 Ego 창 제어 재개 응답 후 목록·정렬·미리보기·보관/완전 삭제 안내·오류·페이지·390px를 실제로 조작하고 정상 원본과 대조한다. 선행 Task 게이트와 본 작업의 모든 수용 조건이 갖춰질 때만 완료로 집계한다.
