# 공개 문서의 게시 당시 관계·필터 검증

2026-10-10. `DocumentVersionRecipient`를 게시 트랜잭션에서 저장하고 공개 조회가 현재 초안 대신 게시 당시 정보를 사용하도록 보완했다.

- [최초 실패 4건](red.json): 목적을 통한 수탁자 누락, 초안 연결 삭제에 따른 공개 필터 변경, 새 관계와 불변성 제약의 부재를 재현했다.
- [1차 회귀 36건 통과](green.json): 관계 보존과 기존 문서·공개 서비스·PDF 검사를 함께 실행했다.
- [100건 제한 실패](limit-red.json): 필터와 맞지 않는 과거 링크 101건 뒤에 있는 문서가 누락됐다. 4건 통과·신규 1건 실패를 확인했다.
- [최종 관련 회귀 37건 통과](limit-green.json): 문서 유형·수탁자 유무·국가·필수 항목·고유식별정보·수탁자 ID 및 조합 조건을 PostgreSQL에서 필터링한 다음 100건 제한을 적용했다.
- 회사/서비스/게시 버전 복합 FK, 다른 회사의 수탁자 연결 거부, 게시 후 관계 추가·수정·삭제 거부를 실제 PostgreSQL로 검증했다.
- 과거 출처 없는 버전은 공개 스냅샷 기준 목록에 남는다. 특정 수탁자 ID는 추정하지 않아 해당 ID 필터에서는 제외된다.

개발 DB의 102→103 이관 전후 [7개 기존 테이블의 해시](../../R10-T01/public-recipient-snapshots/migration-after.json)는 모두 동일했다. 기존 게시본 29건·PDF 6건·동의 영수증 129건·동의 이벤트 134건을 보존했고 과거 출처 관계를 소급 생성하지 않았다. 개발/시험 DB 스키마 비교에서 예상 밖 차이는 0건이다.

전체 회귀는 별도 실행 중이다. 공개 목록은 조건에 맞는 앞 100건을 제공하는 기존 계약을 유지한다. 페이지 탐색 기능을 추가했다는 의미는 아니다.
