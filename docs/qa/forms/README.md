# 폼·응답 기능 검증 기록

상태: 구현 진행 중. 이 기록은 P04/P06 전체 완료 판정이 아니다.

## 확인한 범위

- PostgreSQL에 폼·질문·선택지·게시 버전·공개 토큰·응답·동의 영수증을 저장한다.
- 게시된 질문과 버전의 직접 수정을 DB 트리거로 막는다. 수정은 새 초안으로 보존한다.
- 목록 검색·상태·생성일·즐겨찾기·페이지 이동, 복사, 게시·일시중지·재개·보관을 API에 연결했다.
- 고정 URL 생성·조회·연결 변경·사용 종료, 재게시 후 새 버전 연결을 구현했다.
- 제출 시 필수값·선택지·질문 소속·동의·응답 한도를 검사한다. 같은 요청을 재전송해도 한 번 저장한다.
- 응답과 정정 전후 값, 변경 사유, 메모를 암호화한다. 동의와 정정 이벤트는 수정할 수 없다.
- 응답 조회·정정·철회, 메모 생성·수정·삭제, 보존 조치 및 파기 요청을 구현했다.
- 보존 조치 중 파기 요청과 기존 메모 변경을 차단한다.
- 2단계 인증을 활성화하거나 변경하면 다른 기기 세션을 폐기한다.

## 미완료 조건

회사 템플릿 CRUD, 분기·행렬 문항, 파일 업로드, 게시 승인, 문서 버전 연결, 실제 파기 작업·증명서, 외부 열람·정보주체 인증, 마케팅 수신동의, 내보내기와 전 경로 통합 검증은 아직 전체 게이트를 통과하지 않았다. 공개 파일 업로드와 본인인증이 필요한 게시 요청은 현재 명시적 오류로 차단한다. 외부 공급자 실제 발송·결제는 검증하지 않았다.

화면의 파기 요청 상태는 실제 파기 완료를 뜻하지 않는다. 단순 폼 보관도 응답을 지우지 않는다.

## 재현

Node 22.23.1, PostgreSQL 17.11, 개발 DB catchsecu_dev / 테스트 DB catchsecu_test.

```sh
npm run db:migrate
npm run db:generate
npm run db:seed
npm run dev
npm test
ALLOW_LOCAL_MAIL=1 npm run build
npm run lint
```

테스트는 정확히 로컬 catchsecu_test DB에서만 fixture를 초기화한다. 운영 계정·원본 사이트 데이터는 사용하지 않았다.
