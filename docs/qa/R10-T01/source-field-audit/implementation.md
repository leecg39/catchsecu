# 구조화 처리방침 보완 설계

상태: 아래 저장·DTO·게시·개별 화면을 구현하고 부분 수용을 검증했다. [실행 증거](../structured-policy/README.md), [필드 대응표](implementation-map.csv). 전체 R10/원본 동등성 완료가 아니며107개 작업 분모는 유지한다.

## 저장·호환성

- `DocumentPolicyDraft`를 문서당0..1개 관계로 추가했다. `tenantId/serviceId/documentId` 복합 FK, 문서별 unique, `schemaVersion`과 검증된 JSON 자료를 저장한다. 기존 Document/DocumentVersion/PDF/영수증 행을 소급 변경하지 않는다.
- 회사·서비스·문서의 기존 쓰기 잠금과 `Document.version`을 함께 사용한다. 별도 충돌 버전을 만들어 한 요청에서 서로 어긋나지 않게 한다. 문서 초안+구조화 자료+감사 기록은 한 트랜잭션이다.
- 기존 `/documents` 생성·상세·수정·미리보기·게시 API에 선택적 `policyDetails`를 통합한다. 과거 클라이언트가 필드를 생략하면 현재 값을 보존한다. 명시적 `null`은 초안의 구조화 자료를 제거한다. 처리방침 이외 유형에는 입력을 거부한다.
- 게시 스냅샷은 기존 schemaVersion1에 선택적 policyDetails(schemaVersion1)를 추가했다. 기존 자료가 없는 버전에는 키 자체를 추가하지 않아 해시·공개 응답을 유지한다. 선택되지 않아 화면에 숨은 하위 초안은 게시 JSON에서 제거한다. 폼 영수증의 처리방침 본문도 기존 고정 렌더링을 사용한다.
- `policyDetails`는 알 수 없는 키·형식·과도한 배열/문자열/총크기를 거부하는 DTO로 검증한다. 원본에서 관찰한 제한과 독립 구현의 자원 제한은 구별해서 문서화한다. 임의 JSON 저장이나 JavaScript 실행은 지원하지 않는다.

## 입력·표시

- 처리방침 편집기에 아동/법정대리인, 위탁/재위탁, 미사용·탈퇴, CCTV, 자동화 결정, 권리담당자/대리인/DPO, 민감정보/국외이전, 기기내부/광고/보존항목 구역을 연결한다.
- 구역별 선택 여부와 반복 항목의 추가·삭제, 필수/선택 항목을 보존한다. 배열 입력은 개별 폼 또는 한 줄 한 항목으로 제공한다. 화면 라벨은 한국어이며 원본 변수명이나 JSON을 표시하지 않는다.
- 존재하지 않음/미작성/직접입력을 구분한다. 원본에서 N으로 전환할 때 하위 입력을 초기화하는 동작은 사용자에게 현재 초안 변경으로 보이게 적용하고 게시본에는 영향을 주지 않는다.
- 초안에는 작성 중 상태를 저장할 수 있게 하고, 선택한 구역의 게시 필수 항목은 미리보기에 구체적인 오류를 표시한다. 원본 근거가 없는 법률/보유기간/계약 규칙을 생성하지 않는다.
- 구조화 내용이 미리보기·버전 비교·공개 본문·PDF에서 같은 순서와 제목으로 렌더링되는지 확인한다. 현재 자유 본문과 함께 사용할 수 있도록 한다.
- 기존 입력 보호·409 보존/재조회·보관 시 읽기 전용·서비스 범위·반응형 동작을 그대로 적용한다.

## 실행·검증 순서

1. `control-contexts.json`을 확장해 아직 모르는 enum/배열원소/전송변환을 확정하고 필드별 지원 표를 갱신한다.
2. DTO와 전체 필드의 유효/거부 fixture를 작성한다. 조건부 필수·범위·특수문자·중복·길이 경계를 검증한다.
3. 신규 migration과 원자적 저장/조회/삭제를 구현한다. 기존 자료 해시를 보존하는 이관 및 rollback 실패 원자성을 검증한다.
4. 게시/공개/PDF/폼 연결에 스냅샷을 통합한다. 구버전 해시·PDF·영수증을 기존 fixture와 대조한다.
5. 개별 입력 UI를 연결하고 각 구역을 실제 브라우저에서 저장/수정/해제한다. 게시 불가→보완→게시, 낡은 버전409, 권한 거부, 새로고침/재시작을 확인한다.
6. 새 필드마다 입력값→DB→게시본→PDF 수용표를 기록한다. 구현하지 않았거나 외부 관찰이 부족한 필드는 부분/미확정으로 남긴다.
