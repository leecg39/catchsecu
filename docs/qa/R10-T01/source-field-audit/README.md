# 처리방침의 구조화된 원본 필드 대조

2026-10-10. 저장된 역공학 산출물 `static/data-models.json`의 `infoManagement`(AST-S015)를 현재 `Document`/`ProcessingPurpose`/`Recipient`와 DTO·화면에 대조했다. 원본 서버 DB 스키마로 해석하지 않는다.

[전체 필드 표](field-map.csv)와 [출처 지문·필드 경로](field-map.json)에 102개 말단 경로를 기록했다. 로딩 플래그3개와 중복된 `infoManagementModel` 전송용 표현은 분모에서 제외했다. 빈 배열의 원소 타입 및 `null` 초기값의 실제 타입은 초기값만으로 확정하지 않았다.

- 정확히 대응1개: 시행일→`Document.effectiveDate`.
- 일부 대응21개: IT/개발 수탁자, 필수/선택 항목, 국외이전 거부 안내. 현재 이름·국가·항목·연락처 등의 저장은 가능하지만 원본 구분과 재위탁 관계 전체를 보존하지 않는다.
- 전용 구조 누락80개: 아동/법정대리인, 미사용/탈퇴 처리, CCTV 설치/보관/담당자, 자동화 결정/특별정보/문의처, 책임자·부서·국내대리인·DPO, 민감정보 공개, 기기 내부 처리, 행태 광고 및 별도 보존 항목 등. 자유 본문에 쓸 수 있다는 이유로 구조화 지원으로 집계하지 않았다.

## 구현 세부 작업

R10-T01~T04의 기존 범위에서 다음 순서로 보완한다. 새 기능 완료로 표시하지 않는다.

1. 원본 번들의 실제 컨트롤과 전송 변환에서 Y/N·boolean·보유기간 단위·재위탁 원소 구조를 확인한다. 확인한 필드와 독립 구현의 제한값을 분리 기록한다. 초기 `null`에서 타입·법적 보유기간을 추정하지 않는다.
2. 문서 초안에 버전이 있는 구조화 처리방침 내용을 저장할 모델/DTO를 정의한다. 서비스·회사 범위, 문서 유형, 과거 클라이언트의 필드 생략, 명시적 삭제를 구분한다. 기존 문서/PDF/영수증에는 변경을 소급하지 않는다.
3. 게시 트랜잭션에 구조화 자료의 스냅샷과 렌더링을 포함한다. 초안 수정·항목 삭제·재게시 후에도 구버전의 공개 본문/PDF/동의 영수증은 고정한다. 미작성 필수 항목은 초안 저장과 게시 가능 여부를 구분한다.
4. 사용자에게 보이는 제목과 개별 입력/반복 항목 추가·삭제로 편집한다. JSON 원문 편집기로 대체하지 않는다. 기존 저장·미저장 입력 보호·409 복구·보관/복원 흐름에 통합한다.
5. 각 필드 입력→저장→재조회→게시 본문→PDF를 대조한다. 배열 중복·입력 경계·과거 필드 생략·회사/역할/서비스 경계·불완전 게시·동시 수정·재시작을 실제 DB/API/브라우저로 검증한다.

현재 조사에서 확인한 예: 원본 자동화 결정 사용 여부는 `Y` 비교, CCTV 위탁 여부는 boolean으로 변환되며 선택 해제 시 수탁자 입력을 초기화한다. 원본 값이 서로 다르므로 모든 플래그를 동일 타입으로 추정해 복사하지 않는다. 정확한 번들 위치와 추가 enum은 후속 대조에 기록한다.

## 컨트롤에서 추가로 확인한 자료형

[번들 위치와 주변 코드](control-contexts.json)에 다음 근거를 보존했다. 위치는 저장한 번들의 문자 오프셋이다.

| 원본 항목 | 확인한 동작 | 위치 예시 |
|---|---|---|
| IT 인프라 | `C`/`I` 선택, 위탁 직접입력/링크는 `DIRECT`/`LINK` | 11682682 |
| 재위탁 | 직접입력은 회사명·국가·연락처·업무, 링크형은 표시문구·URL·국가 검사 | 11705047,11707216 |
| CCTV 위탁 | Y/N 선택을 boolean으로 변환; 해제 시 위탁자 입력 제거 | 11648299 |
| CCTV 수량·촬영시간·보관기간 | 각각 문자열 입력, 원본 입력 길이70. `null` 초기값을 정수로 단정할 수 없음 | 11646598,11647009,11647374 |
| 미사용자 보존 단위 | `DAY`/`MONTH`/`YEAR`, `S` 보존형과 `C` 직접입력 분기 | 11692716 |
| 탈퇴자 보존 | `D` 선택 시 보존 상세 초기화, `S` 선택 시 기간·단위·항목 요구 | 11632392,11709079 |

이는 관찰한 화면·전송 동작이다. 법적 의무나 허용 보유기간을 판정하는 규칙으로 확장하지 않는다.

## 구현 후 대조

초기 결손 기록은 그대로 보존했다. 이후 구현은 [정규화 대응표](implementation-map.csv)와 [실행 증거](../structured-policy/README.md)를 따른다. 원본102필드 중98개 대응·수탁유형2개 부모 구역 구분·초기화 배열2개 추가 검토다. 미사용자 W는 회원탈퇴 처리이고 CCTV managerInfo는 성함·직위라는 원본 번역을 확인해 수정했다.

## 서비스 항목 초기화와 재수탁자 추가 대조

후속 조사에서는 [서비스 항목 조회 출처](service-item-source.json)에서 `Eft`가 서비스 ID로 `/company-operated-service/output/services/{id}/items`를 호출하고 mandatoryItems/optionalItems를 초기화 배열에 대입함을 확인했다. 이 호출에는 선택한 목적 ID가 없다. 원본 서버의 집계·중복 제거 방식까지 확인한 것은 아니다.

[재수탁자 컨트롤](initialization-controls.json)의 `zmt`는 재수탁자 직접 입력에도 mandatoryEntrustItems/optionalEntrustItems/piReasonType를 보존한다. 초기 상태에서 reconsignment가 빈 배열이었으므로 위102개 말단 경로가 이 내부 필드를 포함한 전체 필드 수는 아니다.

이 두 초기화 배열을 `DocumentOptions.policyItems`와 신규 수탁자·재수탁자 입력에 연결했다. 활성 목적만 집계하고 필수·선택별로 중복을 제거하며, 100개 초과는 임의 절삭 없이 사용자가 선택한다. 항목 직접 입력과 100개/200자 제한, 처리 근거의 자유 텍스트는 독립 구현의 계약이며 원본 다중 선택기·piReasonType enum과 완전히 같다고 집계하지 않는다. 기존 입력은 목록 재조회나 목적 선택 변경으로 덮어쓰지 않는다.

재수탁자 추가 필드는 선택 속성으로 저장해 과거 자료의 JSON 모양과 게시 해시를 유지한다. 새로 작성한 직접 입력 행은 게시 시 위탁 항목을 요구한다. 링크형으로 전환하면 숨겨진 항목·근거를 공개 JSON/본문에서 제거한다. [관련 DB 시험](../../R10-T02/trustee-items/tests-final.json)과 [실제 화면·저장 자료](../../R10-T04/trustee-items/)에서 추가 검증한다. 원본 전체 동등성 수용은 여전히 미완료다.
