# 서비스 없음·접근 요청·관리자 검토 실제 화면

2026-10-10. Ego Lite 공간3에서 로컬 전용 회사 `5e834085-5627-4f30-ad6c-f1fbd58392a5`와 새 합성 소유자/조회자를 사용했다. 계정 인증과 조회자 멤버십만 시험 준비로 직접 생성했고 실제 접근 요청 4건은 화면에서 생성했다.

| 흐름 | 실제 관측 | 증거 |
|---|---|---|
| 서비스 없음 | 조회자 로그인→/service/none, 요청 가능한 자기 회사 서비스만 표시 | requester-responsive.json, requester-390.png |
| 미저장 입력 | 이전 구현은 로그아웃 링크에서 사유가 사라짐. 수정 후 확인창 취소는 서비스 선택과 사유 유지 | guard-before.json, guard-after.json |
| 요청 취소 | 첫 요청 생성→확인창→본인 취소, 다시 요청 가능한 선택지 복원 | created-cancel.json, cancelled.json |
| 관리자 거절 | 두 번째 요청 생성→검토 답변 입력→닫기 취소로 답변 보존→거절. 요청자 재로그인에서 관리자 답변 표시 | review-guard.json, rejected.json, requester-rejected.json |
| 충돌 복구 | 세 번째 요청의 승인 창을 열어 둔 동안 별도 요청자 HTTP 세션에서 취소→승인409·답변 보존·재제출 금지→최신 목록 복귀 취소/확정 | rival-cancel.json, conflict.json, conflict-recovered.json |
| 최종 승인 | 네 번째 요청 승인→상태 필터와 성공 안내 유지·구성원 표의 서비스 권한 즉시 갱신 | final.json, approval-notice-after.json |
| 실제 접근 | 요청자 새 로그인 후 대시보드 진입·승인 내역/답변과 서비스 확인 | requester-approved.json |
| 실패 재시도 | 해당 탭의 접근요청 GET만 네트워크 차단→오류/재시도 버튼→차단 해제·재시도→4건 복원 | retry-error.json, retry-recovered.json |
| 검토 권한 거부 | 조회자의 /set/member에 권한 오류·승인/거절/초대 컨트롤 없음 | viewer-denied.json |
| 재시작 | 새 서버 프로세스에서 화면 새 조회·승인과 이력4건 유지 | after-restart.json |

관리자 검토 성공 후 상위 컨텍스트 전체를 재조회하면 검토 컴포넌트가 재생성돼 성공 안내/필터가 사라졌다(`notice-before.json`). 구성원 표만 갱신하도록 수정해 최종 승인에서 확인했다. 거절은 수정 전에도 DB에 저장됐으며 실패한 브라우저 대기 때문에 중복 제출하지 않았다.

요청자와 검토 화면390/768/1440폭에서 문서 가로 넘침0을 확인했다. 요청자390폭과 검토 화면390폭 스크린샷을 직접 보았다. 넓은 관리 표는 내부 가로 스크롤을 사용한다. 첫/마지막 페이지 버튼 상태는 실제 UI에서 확인했고 여러 페이지 이동은 아직 별도 수용하지 않았다.

브라우저 전환 중 한 번 로그인 이메일이 앞선 계정으로 표시되어 인증 실패했다. 화면 확인 후 이메일을 다시 채워 로그인했다. 자동완성/초기 렌더 시점 중 어느 원인인지 확정하지 않았으며 R02 후속 조사로 남긴다.
