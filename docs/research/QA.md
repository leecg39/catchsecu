# 최종 검증 기록

2026-10-02. 로컬 데모를 Ego Lite에서 검사했다.

## 정적·서버 검사

- `npm run build`: 최종 변경 후 성공.
- TypeScript: 통과.
- ESLint: 오류 0개. 원본 이미지 `<img>` 사용에 대한 최적화 권고 및 추출 스크립트 경고가 남는다.
- CSV 181개 라우트: 181개 HTTP 200. 동적 파라미터는 `demo`로 대체했다. 정상 데이터·권한의 시각 검증을 뜻하지 않는다.
- 목록에 없는 `/unknown-qa-route`: HTTP 404.
- PDF 35개: 파일 존재 및 `%PDF-` 헤더 확인.

## 실제 브라우저에서 확인한 흐름

- 폼 생성: 제목·본문·질문 작성 → 임시저장 → 편집 URL 변경 → 새로고침 후 복원.
- 폼 설정: 동의 목적과 최대 응답 수 저장 → 공유 화면.
- 공유 주소: `/projects/{id}/form` 경로로 수정. 초기 누락으로 발견된 404를 해결.
- 응답: 이름 입력·동의 → 제출 완료 → 관리 화면에서 같은 응답 조회. 선택형 질문 옵션 저장·복원, 라디오 응답 제출도 확인. 최대 응답 2건 이후 마감 안내 표시 확인.
- 회사 정보: 담당자명 변경 → 저장 → 새로고침 후 유지.
- 모바일 메뉴: 열기 → 하위 메뉴 → 캐치폼 템플릿 이동.
- 로그인: 데모 이메일·비밀번호 입력, 비밀번호 표시 전환, 대시보드 이동.
- 결제: 연 구독 선택 → 해당 상품의 데모 결제 모달 표시. 실제 결제하지 않음.
- 공지: 실제 공지 ID로 상세 본문 표시.

## 반응형 화면

대시보드, 템플릿, 폼 편집기, 회사 정보, 상품 안내, 로그인 6개를 각각 1440·768·390px에서 캡처했다. 깨진 이미지가 없음을 확인했다.

초기 대시보드 768px와 상품 안내 1440px에서 가로 넘침을 발견해 flex/grid 최소 폭을 수정했다. 두 화면을 다시 열어 문서 가로 넘침이 없음을 확인했다. 캡처는 `docs/design-references/qa/`, 측정값은 `responsive-qa.json`에 있다.

## 코드 리뷰 반영

- 생성 버튼의 신규 폼 모드 통일과 저장 URL 정규화.
- 동일 경로의 쿼리 변화에 맞춰 편집기 재초기화. 실제 편집 중 신규 생성으로 전환해 빈 제목으로 초기화되는 것까지 확인.
- 동의서 두 탭의 입력값 분리·저장·복원.
- 로그와 폼 목록의 날짜·상태 필터 적용 및 초기화.
- 검색 후 표의 페이지 번호가 행 범위를 벗어나지 않도록 보정.
- 파일 유형과 선택형 질문의 입력·저장 처리.
