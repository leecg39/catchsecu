## 범위와 판단 기준

- 전체 메뉴: 대시보드, 개인정보 수집/관리, 동의서&처리방침, SMS, 이메일, 알림, 관리, 모니터링, 라이선스, 외부 공유. MY·공지·도움말·보안·숨은 알림톡·인증·공개 문서·결과 경로도 포함한다.
- 일반 리소스는 실제 C/R/U/D를 구현한다. 게시 문서·동의 증거는 버전과 정정 이력을 유지한다. 발송·결제는 예약/취소/환불 상태 전이를, 로그·원장은 시스템 생성과 조회/출력을 제공한다. 대시보드 수치를 임의 편집하는 CRUD는 만들지 않는다.
- 원본에서 제한 안내만 확인한 기능도 독립 구현에서는 허용된 계정으로 정상 기능이 작동해야 한다. 원본 정상 UX를 보지 못한 부분은 독립 설계로 표시한다.
- 폼 질문유형·문서 항목·모달 이벤트 등 모든 상세 필드는 최신 번들/화면과 DTO/컴포넌트 대조표로 확정한다. 이름만 보고 기능을 추측하여 완료하지 않는다.
- 현재 로컬 역할은 owner/admin/editor/viewer/privacy/sender/billing/security/auditor이며, 원본 ROOT/USER 등의 문자열과 동일한 권한이라고 간주하지 않는다. 별도 매핑과 테스트로 확정한다.
- 기존 사용자 수정 중인 `TASKS.md`, 진행판, 결제 코드와 계약은 보존했다. 본 계획을 활성 기준선으로 통합하는 일은 **R00-T03**이다. 이번 작업은 구현 문서 통합이나 코드 변경을 실행하지 않았다.
