# 전 페이지 풀스택 전환 계획

상태: 2026-10-02 계획 기준선. 이후 구현이 진행 중이다. 현재 사실과 완료 판정은 [구현 현황](../IMPLEMENTATION-STATUS.md)과 [작업별 증거](../../TASKS.md)를 따른다.

## 목표와 완료의 의미

CSV의 기존 181개 경로와 전체 메뉴를 유지하면서, 각 페이지의 데이터가 인증·권한 검사를 거친 서버 API와 영속 DB를 사용하도록 전환한다. 화면에서 생성한 데이터가 새로고침·서버 재시작·다른 브라우저 로그인 후에도 남고, 수정·삭제 또는 적절한 상태 전이가 실제로 반영되어야 한다.

- 입력은 `src/data/route-manifest.json` 181개이며, 원본 CSV와 경로 집합을 대조한다.
- 메뉴 파일에 없는 생성 모달·헤더·MY·공지·공유 열람·외부 폼도 포함한다.
- `TASKS.md`가 작업 상태의 기준이다. 181행 페이지 매핑은 `03-route-matrix.csv`에 있다.
- 화면 조사 때의 HTTP 200, 기존 프런트엔드 빌드 성공은 이번 백엔드 구현의 완료 근거가 아니다.
- 최종 완료는 모든 해당 Task, DB 통합 테스트, 권한 테스트, 실제 브라우저 흐름, 외부 서비스 시험 결과가 충족된 때에만 표시한다.

## 제안 아키텍처

기존 Next.js/React/TypeScript를 유지한다. 새 기능은 한 저장소의 모듈별 서버로 구현한다.

```text
브라우저 페이지 → /api/v1 Route Handlers → 서버 세션/정책 → 도메인 서비스 → PostgreSQL
                                                        ├→ 파일 저장소
                                                        └→ Outbox → 별도 Worker → 외부 서비스
외부 callback/webhook → 서명/중복 검증 → 상태 전이·원장 → 화면 재조회
```

- DB: PostgreSQL. ORM은 Prisma를 우선 후보로 두고 P00 호환성 시험에서 설치 버전·Next.js 런타임·마이그레이션을 확인해 고정한다. 검증 전 버전을 가정하지 않는다.
- 검증: 요청 스키마 및 DTO를 공유하되 DB 레코드 전체를 클라이언트에 전달하지 않는다. 검증 라이브러리는 P00에서 고정한다.
- 인증: 유지보수되는 인증 라이브러리를 P00에서 선정하고 DB 세션을 사용한다. 직접 OAuth/SAML/암호 알고리즘을 구현하지 않는다.
- 파일: 로컬 개발용 비공개 디렉터리 어댑터와 운영 S3 호환 저장소 어댑터. 사용자 원본 파일은 `public/`에 두지 않는다.
- 비동기 작업: PostgreSQL Outbox/Job 기반의 별도 Node Worker. HTTP 응답 뒤의 메모리 타이머에 발송·파기를 맡기지 않는다.
- 테스트: 단위/통합 테스트와 브라우저 E2E를 분리한다. DB 통합 테스트는 PostgreSQL을 사용한다. 도구 후보는 Vitest·Playwright이며 설치 호환성은 P00에서 검증한다. 수동 확인은 Ego를 우선 사용한다.
- 개발 인프라: Docker Compose PostgreSQL + 테스트 메일함 + 선택 파일저장소. Docker 사용 가능 여부와 기존 포트는 읽기 점검 후 확정한다.
- 운영: 배포 대상 미정. 우선 로컬 및 staging에서 재현 가능한 실행·마이그레이션·백업 절차를 만든다.

### 예정 파일 경계

- `src/app/api/v1/**/route.ts`: 요청/응답·인증·검증 경계
- `src/server/{auth,tenancy,policies,db,files,jobs,audit}/`: 공통 서버 기능
- `src/server/modules/{companies,services,members,forms,submissions,documents,messaging,integrations,billing,analytics,content}/`: 업무 규칙
- `src/contracts/`: DTO, 오류 코드, 검증 스키마
- `src/features/`: 도메인별 API hook·화면; 기존 `src/components/`에서 점진적으로 분리
- `prisma/schema.prisma`, `prisma/migrations/`, `prisma/seed.ts`: DB 설계·이력·가상 데이터
- `src/worker/`: 예약·재시도·수명관리·정산 작업
- `tests/{unit,integration,e2e,fixtures}/`: 계약·트랜잭션·화면 증거
- `docs/api/openapi.yaml`, `docs/qa/`: 구현 후 계약·검증 자료

설치된 Next.js 문서의 Route Handlers, Data Security, Authentication을 읽었다. API는 페이지와 충돌하지 않는 `/api/v1`에 두고, 권한 확인은 서버 DAL/서비스에서 수행한다. 구현 시 `AGENTS.md` 지시에 따라 변경 기능에 해당하는 설치 버전 문서를 다시 확인한다.

## 전체 CRUD의 적용 규칙

| 데이터 성격 | 허용 동작 | 삭제·변경 의미 |
|---|---|---|
| 회사/서비스/구성원/폼 초안/발신자/알림/템플릿 | C/R/U/D | 참조 상태 확인 후 보관 또는 삭제, 복구 정책 명시 |
| 게시된 폼·동의서·처리방침 | 초안 CRUD + 게시·개정·중단 | 응답이 참조한 버전은 불변; 수정은 새 버전 |
| 제출 응답·동의 이력 | 생성·열람·정정·철회·파기 요청 | 관리자 조작으로 과거 동의 증거를 덮어쓰지 않음 |
| 발송·결제 | 초안 CRUD + 예약/발송/취소/환불 | 보낸 메시지·성공 결제는 상태 전이와 보정 이력 |
| 감사 로그·결제 원장 | 시스템 생성·조회·내보내기 | 일반 U/D API 없음; 보존 정책과 승인된 파기만 허용 |
| 대시보드·통계 | 조회·기간/서비스 필터·출력 | 원천 데이터 변화로 값 갱신; 수치 편집 버튼 없음 |
| 로그인 callback·완료·오류·로딩 페이지 | 서버 상태 조회·명시적 action | 페이지별 가짜 CRUD 테이블을 만들지 않음 |

유료 기능은 개발용 모든 권한 seed와 제한 계정 seed를 둘 다 제공한다. 기능을 제한 안내로만 남겨두고 완료 처리하지 않는다. 권한 있는 계정에서는 실제 CRUD/업무 흐름이 동작해야 한다.

## 기존 데이터와 원본 구분

원본 서비스의 운영 데이터를 임의로 수정·발송·결제하지 않는다. 구현 대상은 독립 백엔드다. 기존 로컬 샘플은 명시적인 내보내기/가져오기 도구를 통해 현재 회사에 귀속시키고, 중복·타입 검증과 dry-run 후 이관한다. 출처 불명 토큰·비밀번호는 이관하지 않는다.

## 아직 확정되지 않은 사항

- 유료·동적 경로의 정상 UX: 보유한 캡처/명세부터 대조하고, 접근 가능한 샘플로 재관찰한다. 관찰할 수 없으면 동작 명세에 “독립 구현 제안”으로 표시한다.
- 문자·카카오·PG·본인인증·전자서명·GPKI·새올 서비스사, 테스트 자격증명, 허용 callback 도메인: 외부 연동 완료의 의존조건이다.
- 이메일 발신 도메인과 DNS 인증, 운영 저장소·KMS·호스팅: staging 통합 검증 전에 결정한다.
- 보존/파기/환불/요금 정책: 수치·기간을 원본과 같다고 추론하지 않는다. 회사별 구성값과 버전으로 두고 담당자가 확인할 항목을 기록한다.

이 의존성은 계획 수립이나 독립 DB·CRUD 구현을 막지 않는다. 서비스사 시험이 안 된 기능은 “외부 검증 대기”로 남기며 전체 완료율에서 제외하지 않는다.

## 의존성 보완

인증·초대·복구에 필요한 플랫폼 메일은 P02에서 개발 테스트메일함/트랜잭션 메일 어댑터를 먼저 제공한다. P09의 사용자 마케팅메일은 동의·수신거부·캠페인에 의존하는 별도 상위 기능이다. 공통 전송 어댑터를 재사용해 인증과 마케팅의 순환 의존을 만들지 않는다. 전체 실행 순서는 `.Codex/goals/timeline.md`의 의존성 검증 결과를 따른다.

AccessRequest·폼승인·파기보류 등 기존 메뉴의 추가 action은 해당 페이지 모달/상세에 포함한다. 발신자 인증을 단순 버튼 클릭으로 승인하거나, pay success URL 방문을 실제 결제 승인으로 처리하지 않는다.
